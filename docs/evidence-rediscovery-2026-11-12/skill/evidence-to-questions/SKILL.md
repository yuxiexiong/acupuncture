# Evidence to Questions

从当前项目已有材料出发，先还原发生过什么，再判断证据支持什么，最后在用户要求时提炼值得研究的问题。保留每次实验原来的科学目的与证据身份；不能为新故事改写历史，也不能把完成许多实验等同于形成完整贡献。

## 确定范围与交付

读取当前项目规则、研究主线、已有索引及最新用户纠正；复用现有目录和记录。明确时间起止、来源版本、研究线、用户要求的细节和交付位置。来源可为仓库、实验笔记、数据、日志或对话，不假定某种学科或固定目录。

- **仅历史梳理：** 按时间解释目的、设计、实际执行与结果，做到用户指定粒度；不擅自生成问题、做文献检索或提出下一实验。
- **证据重审并提炼问题：** 完成来源与证据检查后，比较科研价值、竞争解释、近邻工作和可行性，给出少量有依据的推荐；允许没有足够好的候选。

先利用可访问材料补背景，不让用户重复提供已有信息。若关键来源不可访问，说明具体影响，继续不依赖它的部分；不虚构时间、目的、结果或缺失日志。用户要求细节完整时可分批，保留连续编号、已覆盖范围和剩余项，不用链接或摘要代替所要求的逐实验叙述。

## 1. 来源与时间线

先列范围内来源及去向，标记版本、来源位置和核验深度。实际开始/结束时间优先取日志或回执，不以目录名或文件修改时间冒充运行时间；无时间证据时标未知或仅给已知先后关系。

按真实比较和可辨识子运行组织实验，不假定一个目录就是一个实验。区分扫描、提出假设后的检验、开发选择、独立材料确认、事后分析、工程验收、失败、用户停止和未运行计划。计划与实际分开写；预检、重试、更正和预算变更保留原顺序。旧报告与新纠正并列标明身份，不覆盖原始记录。

逐实验解释：当时为什么做、操纵什么、对照是什么、怎样测量、实际怎样执行、得到什么、原结论是什么、现在能支持和不能支持什么。字段见 [references/records.md](references/records.md)；它是记录提示，不是要求每个任务建立一套新文件。

范围较大时先全量索引，再重点核查影响结论的材料，并明确未核部分。索引覆盖不等于逐样本重验；多批输出不遗漏阴性、反例、停止和缺失记录。仅历史梳理到此按用户要求交付，不强制进入后续研究选择。

## 2. 证据地图与依赖

每条关键判断对应具体来源、实际数字、分母、比较条件与限制。区分观察、作者报告、解释、条件推导及未检验假设。记录实际阅读层级：只定位、读报告、对照协议/回执、核对机器结果、重算原始数据；未执行就不写已验证。

连接跨实验结果前核对研究对象、干预/暴露、对照、背景、时间、终点、评分版本及材料选择历史。区分样本、配对、重复测量、运行和独立实验单位；不把多条轨迹或同批数据的重分析当独立复制。标出复用、重放、开发选择、确认和修订关系。

内部或代理指标改善不能自动升级为最终目标改善；替换/修复可能重新带入信息，不能由恢复推出原内容完整保留或唯一原因。阴性仅约束相应操作，不能据此宣布所有替代解释成立。单次失败、工程无效和科学阴性分开处理。

只做当前任务授权的确定性核对；新评分、分组搜索或统计分析不混入资料整理。需要分析时先明确输入、变换、终点、分母、缺失和已见数据历史，遵守当前项目设计要求；未经请求不悄悄改指标、筛样本或重评分。

## 3. 从结构性观察到科研问题

寻找重复但有边界的关系、条件反转、同类干预不同作用、预期失败、指标与真实目标分离，以及解释间的冲突。同时考虑负结果和早期材料，避免只围绕最新阳性或旧论文框架选题。

先登记初始候选及其来源，承认已见结果造成的锚定。保持四层分开：科研问题、候选答案、所缺证据、具体实验。问题要说明答案会改变什么重要理解、预测或实践判断；“还不知道”“下一步能测”“有一个反常点”本身不足以立题。

每个候选写明最强支持、最不利证据、合理竞争解释与不可判部分。不要机械凑假设数量或强求互斥；不要仅扩大标题就声称跳出旧框架。已有材料可以提出新假设，不会因此变成新假设的独立确认。保留实验原本已取得的科学价值。

## 4. 近邻核查：青蒿素原则

针对影响取舍的具体主张查最接近、最可能削弱创新性的工作。用当前领域的一手论文、官方代码或原始资料，分别核实文献身份和它实际支持的主张；公开查询只使用通用概念与公开信息，不发送未授权私有材料。

明确前人已经回答什么、可以直接借什么、我们的结果是否只是重述、剩余认识为何有用。允许承接成熟方法、重要复现或可靠边界，不要求所有环节首次；也不把新模型、新参数组合或没有搜到同题当贡献。记录检索日期、查询、来源、阅读深度和检索如何改变排序，不声称穷尽查重。

用户禁止联网或工具不可用时，标明文献缺口，仍可完成证据整理和暂定问题，不给确定新颖性结论。查重应允许修改或淘汰候选，不能只为既定主题找支持。

## 5. 推荐与 Advisor

比较问题的重要性、已有支持、技术可实施性、解释可识别性和潜在贡献；不以数据量、已有投入或点子听起来宏大决定排序。正面说明推荐什么及其最危险的未知，不只批评旧方向；无依据不编成功概率、录用率或工期。

形成具体草案后，在可用时调用 `$advisor` 审查方向建议与关键取舍，按其独立咨询流程提供当前项目、证据和草案；项目明确要求咨询时必须遵守。作者先做自查，再逐项处理辅导师纠正。若当前 agent 本身是辅导师，不递归启动审查链。Advisor缺失或工具不可用时如实标注作者自查，不伪称独立意见，也不擅自安装依赖。纯历史整理不为凑流程额外咨询。

问题卡应包含一句问题、科学价值、支持与反证、竞争解释、已有工作和剩余增量、可行性关键依赖、哪些观察会改变判断、缩小或停止条件。只需描述证据需求，不擅自写操作、样本量、预算或运行队列；用户另要求设计时，转入当前项目的设计审查流程。

## 6. 交付与维护

按用户请求交付时间线、证据地图/索引、问题卡和推荐/暂缓理由；只有历史需求时不交问题卡。每条关键判断可追溯，明确覆盖范围、未核材料、冲突与不确定性。最终在聊天中解释主要内容，不只贴文件链接；用户要求仅聊天时不新建文档。

有新证据时更新“原判断→新证据→修正判断→取消或保留事项”，保留旧判断的历史身份。局部问题不断被回答，不等于整体解释收敛；有合理下一问不等于值得继续。允许停止分支；成果足够时转向整合，不无限增加细节。

本 skill 不携带旧项目的结果、停止状态、路径、检查编号或授权。不会自动启动模型、训练、GPU、候选搜索或其他新实验；执行权限以当前请求和项目规则为准。只按项目要求提交推送，不把通用技能变成新审批或后台服务。

方法来源及与其他技能的分工见 [references/methods.md](references/methods.md)；核心流程已自包含，不要求先装完整技能套件。
