### 数量为什么不能直接相加

正剂量交付复用了十针实验的 +1 与原版；正负剂量交付又复用了正剂量结果。并排 HTML 还会在多个通道旁重复显示同一份原版，这些展示格不等于新增实验。

去掉重复来源，Qwen 三模型共有 **13,400** 份唯一回答，Llama 有 **4,872** 份，共 **18,272** 份。模型内分别为 2B 3,656、4B 4,872、9B 4,872、Llama 4,872。这个分母只适用于上述独立单针调查，不包含历史双针、迁移能力面板或已停止的 Llama 合并运行。

数量依据：各批 `delivery-r01/export_receipt.json`，以及[统一结果库的范围说明](../experiments/neuron-explorer-multimodel-v2-2026-10-26/all-experiments-r01/README.zh-CN.md)。本索引核对了五份 JSONL 的实际行数。

## 2. 如何定位某一条回答

单针调查 JSONL 中最常用的字段如下；历史能力／迁移实验可能使用不同结构，应以该批记录为准。

| 字段 | 用途 |
| --- | --- |
| `model_id` | 模型：`2b`、`4b`、`9b`、`llama31-8b-instruct` |
| `layer`、`channel` | 注入层号与该层内通道号；不同模型同编号不表示同功能 |
| `dose` | 剂量；较早的 Qwen 十针记录在 `intervention.dose` 中保存 |
| `question_id`、`prompt` | 题号及实际输入 |
| `output.answer_text` | 回答正文；导师 HTML 的剂量案例展示此字段 |
| `output.raw_text` | 保留特殊标记的原始输出 |
| `output.token_ids`、`generated_token_count`、`end_reason` | 输出 token、长度及停止原因；后两项也位于 `output` 内 |
| `source`／`source_record` | 原始运行文件与来源身份；不同批次字段略有差异 |

例如，在 Qwen 正负剂量完整原文中筛选 `model_id=4b`、`layer=6`、`channel=7840`、`question_id=Q04`，就能找到导师 HTML 的“整理书桌”十档剂量案例；对应原版按同模型、同题号查找 `layer=null` 的记录。原版是共享参照，不是每个通道重新生成一份。

## 6. 核对来源时看什么

`delivery-r01/` 是便于阅读和分析的导出；`survey-r01/` 或 `runs/` 保存逐次运行输出；`receipt.json`、`export_receipt.json`、`verification.json` 保存范围、身份和哈希核验。它们经常指向同一份来源，不应按目录份数累加。

本索引只改变查找方式，保留旧目录及文件名，以免破坏冻结合同、代码中的路径和历史收据。导师总结及图表入口见[实验总结 MD](Acupuncture_实验总结_导师版_2026-10-28.md)和[导师展示 HTML](Acupuncture_实验结果_导师展示_2026-10-28.html)。
