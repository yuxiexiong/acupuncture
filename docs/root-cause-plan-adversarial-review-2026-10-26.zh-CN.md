# 根因方案的对抗性检查与下一阶段修复计划

日期：2026-10-26。对象：[根因方案 v1](root-cause-localization-plan-v1.zh-CN.md)。状态：设计审查与修复提案；没有运行模型，没有替换 v1 或改变迁移队列。根因实验继续暂停。

本轮采用两路独立审查，分别检查因果可识别性与测量定义，再结合 [HanLab 原论文核查](literature/hanlab-mechanism-primary-audit-2026-10-26.zh-CN.md)进行综合。以下反例均为逻辑测试，不是新的实验发现。

**裁决：需要修改。保留“分解两针、定位、局部修复与重现、自然功能、范围及迁移”的主线；修复成功判据和关键鉴别实验。** 当前方案较容易找到有效干预点，但一些成功结果仍无法判定原始故障发生在哪里。已有风险声明不能代替能区分解释的操作。

## 1 对抗检查发现了什么

| 漏洞及 v1 位置 | 不同机制产生相同结果的反例 | 必须修复的地方 |
|---|---|---|
| 修复与重现不足以定位故障，§4 四种对照 | 真正修好受损计算；或上游仍坏，只把正确答案信息送入下游。两者都可通过 clean 修复、AB 重现、正常消融和随机替换对照 | 对最终解释检查输入贡献如何改变未被直接替换的接收计算；补答案内容与报告码的反事实，限制结论为实际检验的关系 |
| 计算与输出竞争尚无相反预测，§4 最小鉴别 | 给出答案会增强正确答案证据，两种机制都可能因此表现改善 | 任务内容和输出符号独立改变；给每个具体解释写出不同预测。无法区别的解释合并或收窄，不靠命名拆开 |
| 共同路径可能只是通用修补点，§3 随机源、§4 联合验证 | A、B破坏不同计算，却都能靠同一答案读取组件救回 | 同一个候选分别修复 AB 和已有随机源损伤；保持同类题与操作定义，检验候选对损伤来源是否有差异 |
| 两剂量均饱和，§3 低剂量、§8 A主导 | A、B各自足以导致近乎全错，因而A、B、AB看起来相同；不等于B无用或共同回路 | 分别估计B相对原版、AB相对A；事前限定低剂量补充，加入读数可辨性条件，不从地板区作作用分解 |
| 指标定义冲突，§3 能力开发集与能力读数 | 选项后半段似然恢复、答案标签偏置恢复、独立判断恢复，被混称能力恢复 | 冻结每类任务的评分文本、归一化、连续优势与终点；固定前缀读数和自主解题分开 |
| 代理漏检，§4 的8个排序加2个随机候选 | 关键组件梯度小或必须联合修复；榜单外两个随机样本都没有抽中 | 将随机抽查称为有限漏检探查；固定候选集合及选择规则，阴性不推出不存在机制；不自动扩大搜索 |
| “范围”混入操作大小，§5 集合曲线 | 一个整层、多个位置的替换优于八个单位置注意力头，仅因替换预算更大 | 固定操作粒度及位置范围；无法统一时只比较具体操作包，不声称脑区更小 |

已核实的评分定义：现有 [MMLU items](../experiments/capability-screen-v3-2026-10-26/items/mmlu.jsonl) 的评分续写为 A—D 标签；[ARC-C items](../experiments/capability-screen-v3-2026-10-26/items/arc_challenge.jsonl) 为完整选项。现有[协议](../experiments/capability-screen-v3-2026-10-26/PROTOCOL.zh-CN.md)使用 MMLU acc、ARC-C 字符数归一化 acc_norm。因此 v1“完整选项评分”必须消歧，**并非已发现历史评分出错**。

## 2 优先修复的三个鉴别实验

### 修复是否恢复了计算

仅对最终1—2个解释，明确候选要传递的任务变量、发送端贡献、接收计算及位置。保持两针开启，改变有限的发送贡献，检查未被直接替换的接收计算是否按预测改变，再检查真实答案。整层重置、直接抵消针或直接送入最终答案，仍只作技术诊断。

配一个内容反事实：使用任务结构相同、关键事实改变的供体，同时独立交换答案报告码。预先写出：若候选传递某项任务信息，其变化应跟随哪项事实；若只是推动固定输出符号，则在报告规则互换后仍偏向同一输出 token。接收端需按受体题目的报告规则产生答案。只随供体答案改变，并不能单独证明修复了推理；它也可能是在传送答案，必须结合未被直接替换的计算及关键连接证据解释。

接收端按受体报告码转换供体答案，只证明答案信息传递与重新编码。若没有事前定义、区别于最终答案的任务变量及后续计算证据，不称为原任务计算恢复；“接收端没有直接被替换”本身也不能排除答案注入。

这把目标从“能不能救分”收窄到“哪项有限信息经过哪个计算影响结果”。即便成立，也只支持这条局部关系，不保证唯一根因。

### 计算受损还是某种输出偏置

沿用计算／已给答案的任务对，但不以这一个差异直接分类。增加两套反平衡的报告码，在答案语义不变时交换最终符号；同时保留改变关键事实但保持报告码的配对题。各形式先在原版核对可解性，在 AB 下确认仍覆盖待解释现象。

优先裁决两个窄解释，例如“固定输出符号偏置”与“某个任务变量的传递异常”。前者预测互换报告规则后，偏置仍指向同一输出 token，而该 token 的正确／错误身份随映射改变；任务变量的传递则应使对应语义按新规则转换为另一个输出 token。观察到后者可削弱固定符号解释，但仍不自动证明全部计算能力保留或损坏。对于“语义层面的答案选择错误”等同样能解释结果的替代说法，继续保留，不强行二分。

### 特殊传播路径还是通用修补点

沿用 v1 计划中的20组随机源，不新增全模型搜索；这些根因对照尚未运行。获准执行后，在开发题上仅按修复前的损伤程度和预定距离规则选1—2组接近 AB 的条件；不能根据谁最难修复来选择。冻结后，在独立题上对 AB 与这些随机源施加同一候选修复，并保留无修复及匹配无关修复。

报告各损伤来源的原始损伤、修复增量及相互差异。独立题上的损伤仍满足预定可比性要求时，候选对 AB 更有效首先支持“修复效果依赖损伤来源”；结合关键连接证据，才进一步讨论传播特异性。对二者都有效，说明它可能是共有瓶颈或补偿点，不能证明源头相同。平均损伤相近不能自动排除受损题组成、难度与恢复空间的差异；这些可比性检查须提前定义。确认集上失去可比性时记为不足，不重新挑选随机源。全部随机源记录保留，所选子集不能用于估计随机损伤的总体发生率。

## 3 下一阶段怎样修方案

| 顺序 | 具体修改与交付 | 为什么必须这样做 |
|---|---|---|
| 1 先修测量定义 | 一张评分合同：每项任务的输入、评分续写、长度处理、主要终点、连续优势公式、前缀来源、聚合方式 | 防止实际上换了终点；MMLU与ARC-C的连续分数不未经定义直接平均，数学／代码需要自身终点确认 |
| 2 写可判别的解释 | 每个拟保留解释写成“具体计算—竞争解释—差异预测—必要干预—允许结论”五栏；确认阶段最多1—2个 | 若两个解释对所有拟做操作都给同一预测，就在运行前删掉或改造该项鉴别，不等跑完再争论措辞 |
| 3 限定分解与搜索 | 明确B单独效应与B在A开启时增量；冻结低剂量补充和可辨性条件；保留最多10个候选预算与有限随机审计 | 避免地板区误判、代理排名成为机制结论、阴性触发无限搜索 |
| 4 强化最后验证 | 对筛出的1—2个解释加入上述内容／报告码反事实、关键连接检查及跨损伤源修复；替代辨别力低的重复验证 | 将额外成本集中于能改变因果判断的条件，不对全部候选展开完整矩阵 |
| 5 再讨论大小和迁移 | 统一操作粒度后测范围；解释冻结后才用9B、2B检验计算关系；最终解释再跑正式面板 | 不把层数、头数、状态位置混成体积，也不以再次掉分替代机制预测 |

第1—3步的文档、评分字段核对、判词检查均可在不运行模型时完成。数值可辨性与代理有效性只能在获准后的有限测量中验证，不能纸上宣布通过。64题是开发预算，不能据此保证等价判断的精度；效应阈值、等价范围与确认样本量须在确认结果打开前具体冻结。

三个鉴别分别采用必要的最小条件，默认不把内容、报告码、任务形式、损伤来源与修复操作交叉成笛卡尔积；共用基线，执行前冻结合计题目—条件数及完整生成预算。

选择题快测可以定位其自身的损伤路径，但无权排除数学、代码中的其他机制。若最后声称解释四项能力损伤，每项都需要相应实际终点的确认；不因统一叙事而把四类失败合成一个原因。

## 4 在运行前用反例检查判定规则

以下是纸面反例验收，没有产生模型结果。

| 假想输入给裁决流程的情形 | 修订后的流程必须输出 |
|---|---|
| 修复、重现、自然消融均有效，但仍兼容把答案直接送入下游 | 有效因果干预点；原始故障位置及完整路径未确定 |
| A、B、AB均接近地板，两个剂量读数相似 | 当前剂量与读数不能分解；不能输出B无效或同一路径 |
| 正确率不变，完整选项后半段概率改善 | 该续写读数改善；不能输出独立解题恢复 |
| 一种任务提高、另一种同量降低，平均为零 | 分任务效应不同；不能输出能力基本不变 |
| 十个候选无效，但梯度筛选未验证对非线性或联合效应的覆盖 | 已测候选未获支持，搜索覆盖有限；不能输出不存在局部机制 |
| 一个全层多位置操作胜过多个单头单位置操作 | 具体操作包效果不同；不能输出更小功能区 |

这一步能够发现设计造成的错误升级。它不能保证真实数据一定能区分所有机制。确认结果分开记为：支持具体解释、与该解释的预注册预测相冲突、精度不足、测量或干预未通过验收、搜索范围不足。最后三类不能合并成“机制失败”，也不能包装成成功。

## 5 保留与暂缓

保留 A/B/AB、同前缀重算状态、有限贡献替换、无关对照、开发与确认分开、全部失败记录。根因主线仍是解释两针怎样引起严重损伤，以及对应计算在哪、正常做什么、作用范围多大。

本轮将“前额叶大小”的统一解释、大规模内容与能力分离实验、多模型机制验证，以及最终大 Benchmark 放在局部解释之后；内容与结束的辅助记录保留。这些后续目标依赖前面可判别的局部解释。当前交付是修复计划，原 v1 留作版本记录；未生成已冻结执行协议，未启动模型。
