# 第一张设计卡草稿：形成窗口对齐下的恢复与选择（WIN-01）

2026-11-04。**设计稿，未冻结、未实现、未运行，无 GPU 授权。** 对应 [Proposal v3](mechanism-second-half-v1-2026-11-03/PROPOSAL.zh-CN.md) §6"第一步：先核对可比性，再决定首个关系检验入口"。依据：[R1 对齐报告（含更正）](../experiments/cache-mechanism-alignment-r1-v1-2026-11-04/REPORT.zh-CN.md) 与 [协议差异清单](../experiments/cache-mechanism-alignment-r1-v1-2026-11-04/PROTOCOL_DIFFS.zh-CN.md)。档位：**推导**＝有论证链；**类比**＝相邻证据；**推测**＝待验证。

## 1. 要回答的问题

项目级问题（11-04 讨论）：

> **为什么"开头/交付层面的恢复"和"正确答案的恢复"会分开？这种分开随干扰位置、任务和缓存背景怎样变化？**

已有的分开实例：
- **L0 事实**：恢复递推后停止消失（24→0），答案 8/24、2/24；
- **L0 编号**：恢复 V 后停止消失，答案 16/48；
- **L0 编号**：恢复深层 S，答案 48/48；
- **L1 事实**：只恢复 KV 就修好（24/24、21/24），而 L0 只恢复 KV 是 0/24。

问题在于这些实例的干扰形成方式不同（差异清单第 1 项），现在不能互相比较。本卡分两块：

- **W 块（关系 A，对齐窗口）**：两个任务、两个深度上用相同的形成窗口，再看恢复的作用。先回答"分开"的差异有多少来自窗口，再谈任务和深度。
- **B 块（关系 B，非编号任务）**：事实任务上跨输入移植状态，能否像编号任务的 CSx 那样把答案带成供体的答案。

两块都以自然完整回答为终点。D（写入/读取）不在本卡，等 W、B 的结果指明值得解释的差异后再加。

## 2. 为什么先对齐窗口（推导与推测分开）

- **推导**：NCC 系列先对 0..b 做一次无针前向，所以记录句及之前位置的 KV 在每一层都与干净运行逐位相同。阶段二在 0..n−2 全部加针，记录句位置的 KV 也受了干预。
- **推测**：事实任务恢复递推后仍答错，是因为记录句本身的历史受了干预，单靠递推恢复不了。R1 §3 的文本现象与此相容（失败回答说题面"仅包含重复的……"），但不是证据。
- **类比**：QC-01、QCD-01 在编号任务上已经表明，窗口覆盖什么比总剂量更重要。

## 3. W 块：窗口 × 任务 × 深度下的恢复

**输入与任务**
- 事实：阶段二开发 24 条＋历史 24 条（都已接触过）。
- 编号：LVK 新面板 48 条（已见）。
- 两任务都是"记录句＋问题＋指令"。b 统一定义为记录句最后一个 token：编号沿用 `c1p_core` 的 `boundary_text`；事实取第一行（"\n问题："之前）。事实的 b 需要在冻结前用真实分词器逐条导出。

**针**（都来自阶段二的固定 32 点面板，不是按损伤大小挑的）
- L0/N4146/−1：主针，是 R1 的分歧所在。
- L1/N2765/−1：跨深度对象，阶段二上只恢复 KV 就修好。
- 两针剂量都沿用各自家族的校准：事实用本题 f0 版提示，编号用 NQ-01。这样能保住逐位桥接。两边每位置强度相差不到 10%，每条记录都写入实际范数。

**形成窗口**（主操作，形成时只改窗口，其余全同）

| 窗口 | 加针位置 | 用途 |
|---|---|---|
| W_all | 0..n−2 | 阶段二方式 |
| W_post | b+1..n−2 | NCC 方式；记录句历史保持干净 |
| W_rec | 0..b（模板＋记录句） | 只干预记录句历史；直接检验 §2 的推测（建议保留，可删） |

**臂**（以 T 为背景，在切点 τ 一次性替换，卷积保持 T）

| 臂 | 替换 | 对照来源 |
|---|---|---|
| T | 无 | 原生 |
| R_all | 全部线性层递推 | 阶段二 TCT |
| S_deep | G 层递推 S | NCC TS |
| KV_all | 全部 KV 层 | 阶段二 CTT |
| R+KV_all | 递推＋KV（卷积仍为 T） | 阶段二 CCT |
| C | 干净运行（每输入一条） | — |

R_all 和 S_deep 并排放，在同一窗口下顺带检验差异清单第 3 项（范围）。

**桥接**（工程闸门，任一失败即停）
- 事实 W_all 下的 T、R_all、KV_all、R+KV_all，t1 logits 与生成 token 应逐位等于阶段二已有记录。
- 编号 W_post 下的 T 与 S_deep，应逐位等于 NCC 的 T 与 TS。
- 结构断言：W_post 下 0..b 位置的 KV 在所有层等于 C；所有窗口下，第 0..L 层（针所在层及更浅）的缓存等于 C。

**读数**
- 首步：是否停止，首 token 分类。
- 自然完整回答：
  - 统一生成 128 个 token；
  - 编号用 `y_full`，同时报前 32 个 token 处的判读，以桥接 NCC；
  - 事实沿用阶段二的预写规则判读（流程见 §7 待确认 1），另报两选一候选分数作辅助。
- 逐格报告：救回数、改坏数（相对 T）、停止数、异常类型。不合并成单一比例。
- 汇总：逐输入配对；场景分层 bootstrap（2000 次，种子 20261103）只给描述性区间。零点用 C 和同格 T 标定，不用"大于 0"作判据。

## 4. B 块：事实任务上的跨输入移植

- 事实每个情景有两版（f0/f1），记录里的事实互换，正确项也互换，正好互为供体。24 对里 22 对两版的提示 token 数相同，可以按位置移植全部缓存；另 2 对只移植与长度无关的递推状态。
- 接收者为 f0 的干净运行 C，在 τ 换入 f1 的干净状态：
  - **Bx_R**：全部递推；
  - **Bx_S**：深层 S，对应编号的 CSx；
  - **Bx_KV**：全部 KV，只用于 22 对；
  - **Bx_all**：全部缓存，只用于 22 对，作参照。
  
  反方向（f1 接收、f0 供体）同样做一遍。
- 读数：回答是否变成供体事实（两选一里的另一项），是否仍是接收者事实，或其他。
- 对照：编号任务的 CSx（38/48 改坏，32 条变成供体答案）是已有参照，不重跑。
- 限制：两版只差事实词，接近"最小对"；但记录句以外的差异和拼接失配仍不能排除。

## 5. 开跑前写死：每种结果导向哪里

| W 块主要观察 | 读法 | 下一步 |
|---|---|---|
| 事实 W_post 下 R_all（或 S_deep）的答案恢复明显高于 W_all，接近编号；编号 W_all 下 S_deep 明显变差 | R1 分歧 1 主要来自记录句历史是否受干预，不是任务 | 问题转为"哪些位置的历史必须干净，答案才回来"：按位置和层分开，接 QC-01；任务比较在 W_post 下继续 |
| W_rec 也让 R_all 恢复不了答案，W_post 能恢复 | 与 §2 推测相容（仍是混合缓存干预，不说唯一路径） | 同上，并在 W_rec 下检验 KV 恢复是否必需 |
| 两个窗口下事实都恢复不了，编号都能恢复 | 窗口解释不了，差异保留在任务结构上 | 用 B 块与任务结构比较继续，不归因于单一缓存 |
| 结果随窗口和任务混合变化 | 窗口与任务交互 | 只按格报告，先讨论再设计，不自动加格 |
| L1 在两个窗口、两个任务上都是"只恢复 KV 就够" | 跨深度的稳定分叉：L0 靠递推去停止，L1 靠 KV | 选 L1 做代表，深入 KV 在 L1 的作用 |
| L1 在编号上不成立 | L1 的 KV 关系依赖任务 | 记为条件分支 |

| B 块观察 | 读法 |
|---|---|
| Bx_S 或 Bx_R 让多数回答变成供体事实 | 关系 B 在非编号任务上成立：状态带着答案选择信息 |
| 只有 Bx_KV 或 Bx_all 能带走答案 | 事实任务的答案选择信息主要在位置历史里，与编号不同（分叉） |
| 都带不走 | 关系 B 不迁移到事实任务 |

无损伤、不适用、没拿到结果、合同执行失败分开记录。结果弱或不可判时，不加针、不改剂量、不换题。

## 6. 规模与成本（粗估，以预检实测为准）

- W 块：每输入 2 针 × 3 窗口 × 5 臂，再加 C，共 31 条轨迹。两任务共 96 输入，约 2,976 条，生成上限 128。事实 W_all 里约 384 条应与阶段二已有记录逐位相同，可以复用，但仍要重跑桥接。
- B 块：48 输入 × 最多 4 格，约 190 条。
- 参照 NCC 实测（32 token 下每条轨迹约 2 设备秒），128 token 且多数提前结束时，估计 2–5 GPUh。双卡并行，预检后给出上限。
- 事实新记录的判读量约 1,100 条（见 §7 待确认 1）。
