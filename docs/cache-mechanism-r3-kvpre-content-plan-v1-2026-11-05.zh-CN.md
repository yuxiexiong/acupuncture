# R3 第一步设计稿 v2：在固定恢复背景中，改变补入前段 KV 的供体事实，能否定向改变答案（KVC-01）

2026-11-05。**设计稿 v2**（v1 见提交 `f43cd22`，按 11-05 评审修订；用户已授权按 v2 执行到实验结束）。

**v2 相对 v1 的改动**
1. 问题不再写成"恢复作答条件，还是提供答案内容"：两种作用可以同时存在。两个 M 臂都恢复了递推、都补入了干净的模板部分 KV，两臂之间只差记录句里事实词及其后位置的 KV。
2. 结果标签改为描述性名称；不写"内容来自别处""路径不同""失配/不兼容"等机制结论。
3. B_pre 不转移只读作"前段单独替换不足、全部 KV 替换有效"，不自动追加后段实验。
4. 针之间、受针背景与干净背景之间的差异，用同一批接收者的配对差直接判定，不凭"一组过阈值、另一组没过"宣布分叉。
5. 写明本卡是连接"状态恢复"与"答案选择"的一步桥接，不检验原有 v/k—写入—递推—读取链是否在新条件下复现。

## 1. 要回答什么

WIN-02 的关系 M：全前缀受针以后，先从同一输入的 C 恢复全部递推，再补入模板＋记录句位置（0..b）的干净 KV，完整回答进一步恢复：

| 条件 | 只恢复递推 | 再补前段 KV |
|---|---:|---:|
| 事实 L3/C7666 | 35/48 | 48/48 |
| 事实 L0/N4146 | 10/48 | 47/48 |
| 事实 R0（L0 随机） | 20/48 | 46/48 |

本卡问：**在固定的接收背景中，改变补入前段 KV 的供体事实身份，能否定向改变完整答案？这种响应在三根针及干净背景之间是否不同？**

它检验的是"这项恢复操作是否具有答案方向上的选择性"，是连接状态恢复与答案选择的一步桥接。它不直接检验原有的 v/k—写入—递推—读取链；要把这里的作用接到具体的写入、状态处理或读取计算上，是后续步骤。

WIN-01 B 块显示：在**干净接收背景**里，换入另一事实版本的**全部位置** KV，回答 44/44 跟随供体事实。但 B 块的背景和替换范围都与 M 不同，两个阳性结果不能直接拼成一条机制。本卡把两者对齐到同一背景、同一位置范围，判断它们是否依赖同一读取。

本卡不定位层或注意力读取。那是下一步，按本卡结果另立设计。

## 2. 操作

**任务与输入**：只用事实任务（编号任务没有可按位置对齐的事实版本对）。阶段二两面板中位置对齐的 22 对（44 个接收者），对齐由 [WIN-01 prep](../experiments/window-recovery-win01-v1-2026-11-04/prep/PREP.zh-CN.md) 确定：两版只在事实词处有 1–2 个 token 不同，n、b 相同。

**针**（全部全前缀 W_all，剂量与校准同 WIN-01/02）：
- L3/C7666/−1：代表条件（原生针；M 正向 13/13、无改坏；严重损伤不依赖首步停止）；
- L0/N4146/−1：L0 型原生针，全前缀下首步停止；
- R0_L00/−1：与 N4146 共享恢复关系、但错误形态不同的随机方向。

**格**（v 为接收版本，o 为另一版本）：

| 格 | 背景 | 递推来源 | 位置 0..b 的 KV 来源 | 其余 KV、卷积 | 作用 |
|---|---|---|---|---|---|
| M_same | T(v)（W_all） | C(v) | C(v) | T(v) | 即 WIN-01/02 的 R_all＋KV_pre；**阳性对照**，逐位桥接旧记录 |
| **M_other** | T(v)（W_all） | C(v) | **C(o)** | T(v) | **主格**：只把前段 KV 换成另一版本的干净 KV |
| **B_pre** | C(v)（干净） | C(v) | **C(o)** | C(v) | 干净背景下只换前段 KV（对应 WIN-01 B 块，但位置限定为 0..b） |

- 只恢复递推（R_all）的格已有记录（WIN-01/02），作基线引用，不重跑。
- **推导**：两版模板部分 token 相同，C 无针，所以位置 0..b 中模板部分的 KV 在两版间逐位相同。M_other、B_pre 实际只换了记录句里从事实词开始到 b 的位置的 KV。这一点作为工程闸门逐位核实。

**规模**：3 针 × 44 × 2 格（M_same、M_other）＋ 44（B_pre），共 308 条生成（≤ 128 token）＋候选打分。按 WIN-01/02 实测约 0.3–0.5 GPUh。

## 3. 读数与判据（冻结前写死，经 6.2 合成演示）

**读数**：每个接收者的回答盲读后归入三类：
- **接收者事实**（R）：v 的事实；
- **供体事实**（D）：o 的事实；
- **其他**：答错、未交付、无法判断。

判读规则与截断规则同 WIN-02。

**零点**：D0 ＝ M_same 中回答为 o 事实的比例。M_same 的 KV 来自本版，理论上应接近 0。

**判定**（场景分层 bootstrap 2000 次，种子 20261103，单位为接收者，22 个情景等权）：

| 标签（描述性） | 条件 | 只能说 |
|---|---|---|
| **定向转移** | M_other 的 D 比例区间下界 ≥ D0 ＋ 0.20 | 在该背景中，补入前段 KV 的供体事实身份定向影响完整答案 |
| **恢复保留但未跟随** | M_other 的 D 比例上界 ≤ D0 ＋ 0.10，且 R 比例相对 M_same 的配对差区间下界 ≥ −0.10 | 在当前背景下没有观察到回答跟随供体事实，接收者事实仍能恢复；恢复与供体事实跟随可以分离 |
| **恢复减弱且未跟随** | M_other 的 D 比例上界 ≤ D0 ＋ 0.10，且 R 比例配对差区间上界 ≤ −0.20 | 跨版本替换后恢复减弱，且未发生定向转移（"不兼容""支持信号被破坏""其他历史占优"等只是候选解释） |
| **不可判** | 其余 | — |

B_pre 用转移判据（转移 / 未转移 / 不可判），零点是 C(v) 本身的 D 比例。

**条件之间的差异**（直接比较，不比阈值）：三根针用的是同一批 44 个接收者。对每一对条件（L3 对 N4146、L3 对 R0、N4146 对 R0，以及每根针的 M_other 对 B_pre），逐个接收者计算"是否跟随供体事实"的配对差：
- 区间不含 0 且 |差| ≥ 0.20：记"响应不同"；
- 区间在 ±0.10 内：记"未检出差异"；
- 其余：记"不可判"。

## 4. 预测（数据前登记，**推测**）

- M_other 在三针上都判"定向转移"。依据：WIN-01 B 块全部位置 KV 44/44 转移；两版在 0..b 内只在记录句的事实词及其后位置不同。
- B_pre 判"转移"。依据同上，但 WIN-01 B 块换的是全部位置，只换前段能否转移没有测过。
- 预测失败照实记为科学失败。

## 5. 结果导向（数据前写死）

| 观察 | 能说 | 不能说 | 下一步 |
|---|---|---|---|
| M_other 定向转移 | 前段 KV 在该背景中具有与事实相关的答案影响 | 答案只由这部分 KV 携带；补回的 KV 只提供内容、不恢复作答条件 | 研究这部分 KV 怎样被读取：层组与读取侧，另立设计，与原有写入—读取链比较 |
| M_other 恢复保留但未跟随 | 恢复与供体事实跟随可以分离 | 内容来自别处；M 与 B 块不是同一路径 | 先讨论，不自动追加实验 |
| M_other 恢复减弱且未跟随 | 跨版本替换后恢复减弱，且未发生定向转移 | 失配、不兼容（只是候选解释） | 先讨论 |
| 条件间配对差判"响应不同" | 这些条件对同一操作的响应不同 | 机制分叉（还需要计算层面的证据） | 围绕这个差异另立设计 |
| B_pre 未转移 | 前段单独替换不足以在干净背景改变答案，而全部 KV 替换有效（WIN-01） | 答案载体在后段 KV | 不自动追加后段替换；先讨论 |
| B_pre 转移 | 在干净背景里，前段 KV 的供体事实身份也能定向改变答案 | M 与 B 块依赖同一读取（只是相容） | 与第一行一起进入读取研究 |

**措辞限制**：
- 每针 44 个接收者、22 个情景，结论只限这三根针和这批题。
- 不说明自然受针运行中信息怎样丢失。

## 6. 工程闸门（任一失败即停）

1. **桥接**：三针的 M_same 生成 token、t1 logits sha、候选对数似然，逐位等于 WIN-01（N4146）/ WIN-02（L3、R0）的 R_all＋KV_pre 记录；C(v) 等于阶段二。
2. **结构**：
   - 两版 C 在位置 0..b 的模板部分 KV 逐位相同（§2 的推导）；
   - M_other 与 M_same 只在记录句从事实词起到 b 的 KV 上不同；
   - 其余张量逐位等于背景。
3. **对齐**：只用 prep 判为位置对齐的 22 对，接收者与供体的 n、b 相同。
4. 供体、接收者在替换前后不变；自换不变（预检）。

## 7. 判读量与执行

- **盲读**：新读约 3 × 44（M_other）＋ 44（B_pre）≈ 176 条（M_same 逐位桥接，沿用旧标签）。流程同 WIN-02：一读、15% 二读、规则裁决。
- **执行**：代码改造 WIN-02 运行器（只需 W_all、两种 KV 来源、干净背景一格）→ CPU 测试与 6.2 演示 → 冒烟 → 冻结 → 预检 → 正式 → 盲读 → 冻结分析 → 报告。

## 8. 不在本卡做的

- 不扩大针表，不补编号任务的阳性格，不展开编号 L3/L5 的非加和；这些都保留在横向路线上。
- 不做层或注意力定位（第二步，按本卡结果另立设计）。
- 不改递推来源。
