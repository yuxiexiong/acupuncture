## 1. 本轮为什么直接推进核心问题

核心问题保持为：**稀疏激活干预怎样改变模型的写入、旧状态处理和后续读取，并造成显著回答变化？**

已有恢复实验表明，历史状态替换能改变完整回答；仅恢复 V 与恢复整块卷积历史的效果不同。但它还不能告诉我们：q/k 历史带来的是一般恢复，还是与“正在问哪个目标”有关的定向作用。

本轮固定接收者状态与 V，换入同一记录、另一个查询形成的 q/k 历史，检验两个关系：

1. 同一个接收者分别得到查询 b、c 的历史时，完整输出是否相应跟随 b、c，而非固定输出某个编号？
2. 在同一受针接收背景中，把干净供体改成受针供体，以上身份跟随是否减弱、保留或反向？

新增认识是**这部分历史状态的查询身份对完整答案具有何种条件性因果作用，以及针是否改变该作用**。它从“某块缓存换了会恢复”前进一步，不能自动闭合原生形成—读取机制。若只有一般恢复而无定向作用，结束这个候选；不能靠改布局、拆层或加头把结果救成阳性。

## 3. 被替换的物理对象及其含义

依据[已安装源码摘录](../experiments/cache-conv-factor-design-audit-v1-2026-11-01/installed-conv-source.txt)及[源码审计](../experiments/cache-conv-factor-design-audit-v1-2026-11-01/REPORT.zh-CN.md)，每个指定线性层的卷积缓冲形状为 `[1,8192,4]`。8192 通道由 q=2048、k=2048、v=4096 组成，存的是卷积前投影，不是全注意力 KV，也不是递推矩阵 S。源码摘录对应安装文件 SHA-256 为 `b4b17fe08d8d54da34a0fce78639666279ae7fd0a9e4ec06fce6602774707ca3`。

核长为 4。读入末提示 token 前，缓冲保存位置 `n−5…n−2` 的四项；单步卷积拼入当前位置 `n−1` 后，实际使用旧缓冲最后三项和当前投影，最老的一项不直接进入这次输出。该更新逻辑也可在[官方固定版本源码](https://raw.githubusercontent.com/huggingface/transformers/v5.20.2/src/transformers/models/qwen3_5/modeling_qwen3_5.py)核对；公开标签与安装文件的哈希身份仍须分别核验。换四槽保持完整缓存接口，不另立三槽扫描。旧槽在后续三次更新后移出，不代表其造成的递推和下游效应消失。

NA 的这些位置处在对话模板尾部。问题不同而这些 token 字面相同时，其投影差异只能来自上下文计算；**不是直接搬了问题文本所在位置**。旧档案有尾部文本和 token 哈希，本次尚未在目标运行环境重新解出每个尾部 token；§8 要求在模型加载前列出每条输入最后五位的真实 id、解码和绝对位置，并验证同组一致。

准确承诺：检验“读出前末端 q/k 投影历史的查询相关差异，能否在固定接收背景中定向改变完整答案”。k 同时参与当前状态更新，q 参与读取；后续各层也响应。**本轮测替换的总效果，不把它称为只改变从固定 S 读出哪条记录。** 混合 q/k 与接收者 V 不保证原生联合关系，阳性属于指定背景下作用，阴性不证明查询信息不存在。

## 5. 完整运行矩阵

记 `C(a)` 为查询 a 的宽切分干净状态，`T(a,d)` 为同题方向 d 的 B1 受针状态。这里括号内 a/b 是查询身份，避免与旧 QCD 字段 `C_b`（宽切分）混淆。`C(a)` 对应旧记录中 a 的 `hashes.C_b`。

所有替换发生在输入 `n−1` 前。每条臂从不可变接收者深复制；修改源张量视为工程失败。G 以外缓存、递推 S、全注意力 KV、位置、mask 和末提示 token 全取接收者；只有表中 G 卷积块更换。

| 臂 | 接收者背景 | G卷积 V | G卷积 q/k | 自然轨迹 |
|---|---|---|---|---:|
| U(a,b) | C(a) | C(a) | C(b) | 132，跨方向只做一次 |
| H_C(d,a,b) | T(a,d) | C(a) | C(b) | 4×132=528 |
| H_T(d,a,b) | T(a,d) | C(a) | T(b,d) | 4×132=528 |
| T_nat(d,a) | T(a,d) | 不改 | 不改 | 4×48=192 |
| **正式总计** | | | | **1,380** |

U(a,a) 就是干净自然参照；H_C(d,a,a) 等于旧 T_F；H_T(d,a,a) 等于旧 T_V。因此不再额外重复48次干净生成。正式包含756条新外来供体轨迹与624条既有自然/自供体参照重放。新增 U 的外来84条加已有自身48条，完整实现了截图要求的132条干净接收者对照。

U 是**干净背景的方向性参照**，不能把“必须转移成功”设为工程闸门。U 阴性、H_C 阳性仍可能表明作用依赖受针背景。真正工程阳性对照是 U(a,a) 与不做替换的 C(a) 完全一致，及既有自供体恢复重放。

只在分叉起点固定上述状态；随后 hidden、当前 q/k/v、门、S更新、全注意力、下游层和生成历史自然响应。原始输入始终问 a；输出 b 是对原题答错但发生供体目标转移，不能记成原题正确。

## 6. 读数与预先冻结的主判据

### 6.1 完整交付、分类和连续量

沿用[既有分类器](../experiments/cache-first-token-continuation-v1-2026-11-02/fc_core.py)解析可见完整回答，分别对记录中的每个候选编号求旧 `Y_delivery`；允许编号前有正常解释，不能只保留直接编号开头或单编号成功格。

本轮主终点新增明确终止约束：`Y_full(j)=Y_delivery(j) AND termination==stop AND NOT think_unclosed`。一个回答只能交付一个候选编号；多编号、复述整条三项记录、未闭合思考区、预算截断不得计为完整交付。保留旧 Y_delivery、Y_strict、原文、全部 token 和终止原因，并公开新旧终点差异；不追改 QC/QCD 历史结果。这是格式化编号任务的操作性判定，不自动证明附带文字的语义正确。重复同一编号仍按旧规则算单一目标，另报 target_repeated；分类器存在边界时列出原文和确定性解析结果，人工解释不能改变主读数。

全体轨迹报告接收者目标交付、供体目标交付、首列目标交付、其他/多编号/无编号/截断以及正确→错误、错误→正确转移。多编号不得先删掉再分析“选对率”。首列恰为原题目标的条件另外标注。

辅助量：首步共同字母相对停止与其他 token 的分差；从相同读出后缓存分叉强制共同字母的一步诊断中，保存三候选 logits 及全部 logits 哈希。自然臂绝不强制或屏蔽。共同字母是自然首 token 时，这个诊断与自然第二步同构，不作为独立证据；编号前文字也不等于不回答。

### 6.2 双外来供体主比较

对主集合每个接收者 a，两个外来供体按 id 固定为 b、c。给定同一臂类型 X（U、某方向H_C或H_T），令 `y_j(b)=Y_full(j | donor=b)`，类似定义 `y_j(c)`。

`J_a = [y_b(b) − y_b(c) + y_c(c) − y_c(b)] / 2`

`W_a = 1[donor=b 时完整交付 b，且 donor=c 时完整交付 c]`

另记反向一致 `W_reverse=1[分别交付c、b]`。J 范围 [−1,1]。无论供体都答同一个编号时 J=0；只一个供体能交付时可得 J=0.5，但 W=0，不能单靠这种情况宣称双向跟随。连续辅助量 `L_a=[(z_b−z_c)|b − (z_b−z_c)|c]/2` 使用同前缀诊断；只改变分数不满足主行为承诺。

按四基础场景分别计算 J、W 均值，再场景等权汇总（每场景主集9条、非首列子集3条）。**“达到本轮稳定定向标准”同时要求：**

- 全36条：至少3/4场景 J均值>0，四场景等权 J均值≥1/3，W均值≥1/3。
- 两个外来供体均非首列的12条：同样三个条件。故不能依靠“供体恰为第一条”通过。

阈值是预先冻结的最小一致性和效应量标准，不是 p 值、零分布或泛化保证。全部原始数值照报；低于阈值写“未达到”，不写零作用。反向模式把 J 取负、W换成W_reverse，使用同一标准。不得事后挑方向、场景或答对格；四方向分别完整结论，不把三方向多数作为新跨方向机制门槛。

### 6.3 受针供体是否削弱作用

同一 d、同一 a、同一 b/c 下比较 H_C 与 H_T：`ΔJ=J(H_C)−J(H_T)`、`ΔW=W(H_C)−W(H_T)`。称“供体受针后定向作用减弱”需：

1. H_C 达到§6.2正向标准；H_T未达到反向标准（反向另报）。
2. 全36条中至少3/4场景 ΔJ均值>0，场景等权ΔJ≥1/3、ΔW≥1/3。
3. 非首列12条中，ΔJ与ΔW的等权均值均>0。

这是相同接收背景下更换供体形成条件的操作效应，可与H_T仍部分正向并存。两者均正向但差异未达阈值，只能说未检出预定程度的削弱，不能声称等效。反向、混合或不适用如实列出。U 仅辅助判定背景依赖；本轮没有U背景下T供体的完整因子设计，不推断不存在的交互项。

12个单外来供体接收者及28个双方非首列有向配对，分别报告自身→外来后的原题/供体/首列/多编号变化；它们不进入主判据，也不能挽救主判据失败。不要求 T_nat 全错才分析转移，因为本轮问身份定向作用；同时报告原题保持与改坏，避免把损伤减轻称作选择机制。

**固定预检：** 五输入 `NA-NQ01-ABC-A/B/C` 和 `NA-NQ02-ABC-B/C`，覆盖三供体组、两供体组、两种长度、全部四方向和全部臂。不得根据是否转移换预检题、改阈值或调剂量。按组保留不可变C/T，先完成同路径参照校验，再生成外来供体轨迹。

- 形成C/T时核对base_b、C_b、四T_b的哈希与QCD G逐位相同；既有校准及实际注入量与旧来源一致。只读审计不能改变前向路径。

## 9. 完整预算与执行顺序

状态不能假设旧缓存文件仍在内存中。正式每条文本重新预填一次，形成C一次和四个T各一次，共48预填、240形成；按同场景/顺序的供体组流式复用，不能按接收者或方向重复形成未记账的C。每组所有查询置于同一worker，最多两个worker；加载与等候占用均计设备时，不能拿双卡墙钟代替设备小时。

预检基本矩阵为13配对×9加5×4=137轨迹；另5条未替换C及8条重建重放，共150。正式为132×9+48×4=1,380。每个“形成”是一份完整C/T状态，逐token形成前向另外计数。

按QCD G/S收据的运行量粗估，本轮通常约0.5–1.5设备GPU小时；这不是实测、保证或统计区间，转移后答案变长也可能提高耗时。硬上限为每次预检0.25设备小时、正式2.5设备小时、全任务3设备小时，三者同时约束；预检重试也消耗总额。数据产物总上限12GiB（全部尝试），不包含已存在模型权重，不新下载模型。上限到即停止，保留partial，不删对照、不改长度来赶预算。截图的“约1430”是粗估；本次去掉重复的干净自身参照后得精确1380，未删科学条件。

执行顺序：CPU身份/分词/清单验收 → 已获另行模型运行授权后固定实现与启动收据 → 一次固定预检（仅工程失败可修复重试一次）→ 正式按组形成、先校验参照再跑外来臂 → 完整性和来源验收 → 按冻结规则分析 → 原始证据与报告归档。不额外增加“只看结果是否值得继续”的试跑。
