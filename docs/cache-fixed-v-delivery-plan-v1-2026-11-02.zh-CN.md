# FX-01：固定45头卷积V的完整回答恢复验证 v1

2026-11-02；状态：设计及同一助手自查通过，非独立评审；未实现、未运行，无新增GPU授权。与SP-01独立立项、授权及记账。建议A先行、B随后；B不依赖A阳性，也不自动扩到SP面板。

## 1. 设计卡与依据
主线：稀疏干预如何通过历史状态和读取改变回答。本轮问：已经冻结的45头V历史规则，能否在原生T背景下恢复完整编号交付？增量是将停止侧材料规则连接到行为，避免再次只解释停止logit。
已读FC-01报告、合同与正式verification（5a1c166）：T_F 48/48严格交付，T_nat 0/48。已读C2合同及随机名单结构；C2的N混合背景、停止侧结果不等于本轮原生背景完整交付，因此不能直接拼成既定机制。
复用P01–06双事实旧面板、FC四方向与全部身份；这是已见面板上的新操作结果，不是独立泛化验证。最不利依据：此前固定名单答案侧并未接通；恢复供体可带入任务信息；全卷积有效不保证V子集有效。正反结果都能检验既定规则，不再寻找新名单。
估计对象：一次恢复指定旧卷积槽位后所有下游自然响应产生的完整交付效果。不是最初形成来源、唯一存储位置、必要性或自然中介比例。

## 3. 判据、预测与退出
主端点Y_delivery，Y_strict及答案首token名次/竞争差辅助。每情景双事实：C正确、T_nat未交付、待测恢复臂正确，才记“完整救回”；至少5/6情景达到支持一方向，整体至少3/4方向。必须全分母报告基线不足、自然未损伤、恢复恶化；不挑受损输入。FC原生/F/C应逐token复现；若身份相同而不复现是工程失败，停止而非科学阴性。
P_V：T_V整体达标，弱依据是此前V恢复停止侧有效，非保证答案。P_FIX：T_FIXV整体达标，是允许失败的规则迁移预测，没有把它预设正确。报告T_FIXV−T_U逐情景配对Y_delivery/Y_strict及胜/平/负；“对这一U有优势”要求方向内至少2/6情景FIX双事实成功而U不满足、且没有反向情景；跨方向仍报k/4，不做总体随机特异性推断。该差距门槛是预先约定的实际差距，不能称显著性。
FIX成功且U成功：多个集合可恢复，无FIX特异性证据。FIX成功而REST失败：仅当前背景下FIX恢复较有效，不称必要。FIX和REST都成功：允许双方分别足以恢复。FIX失败但V成功：停止侧名单没有接通完整交付，结束固定名单分支，不重筛。V失败但F成功：V单独不足，不能直接命名Q/K是唯一机制，也不自动开Q/K实验。所有新子集失败保留阴性。是否转到SP或形成机制，需结合实际结果另立问题；本合同不预付下一轮运行。

## 4. 完整预算与交付
正式12输入每输入1C+4T供体：60形成、300轨迹、最多9600评分/解码前向、6校准。预检P01双事实：10形成、50轨迹、1600前向、1校准。记录器关闭独立重建C/T4146：2形成、2自然轨迹、64前向。总计72形成、352轨迹、11264前向、7校准。旧C/T/F重放已计在臂内，不另加重复预算；额外形成token前向/prefill按冻结输入长度列清。
建议独立上限1 GPU设备小时、2 CPU核小时、8 GiB产物；先预检实测，不照搬FC耗时。若预检不能支持剩余预算则停止，不删臂。目录拟experiments/cache-fixed-v-delivery-v1-2026-11-02/；原始生成、逐臂来源表、名单哈希、重放校验、实测成本、失败及报告必须提交。
实现前先用CPU检查槽位/名单/哈希/计数；全F/C/T原始首步logits及完整token轨迹与FC相同；源缓存不被轨迹修改。T_V/FIX/REST/U仅更改指定V字节范围，其他分类来源哈希相同；对空集、并集和C到C替换做CPU/已有张量检查，不添加科学臂凑完整性。
