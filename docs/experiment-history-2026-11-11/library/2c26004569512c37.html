前六层统一窗口与 4B 全层轨迹追加合同

日期：2026-10-28，北京时间。实验：layer-trace-extension-v1-2026-10-28。本合同追加到 原内部采集之后；执行以本批冻结清单、测试和运行收据为准。

1. 已授权范围与顺序

用户要求：三模型统一看前六层，补 2B、4B 的 L4、L5；再补 4B 所有其余层。合同和测试通过后直接挂到现有队列后顺序执行，已经采集的内部记录不重跑。

原队列 early-layer-mechanism-v1-2026-10-28/execution-r01 保持原样，包含 2,152 个唯一来源。追加只使用旧全层十点及正负剂量调查中已存在的通道、剂量、八题和原始回答，不扩展科学条件。

阶段 模型与追加注入层 新增来源记录 新增生成流
six-layer 4B L4–L5，然后 2B L4–L5 304 + 304 = 608 1,216
4b-full 4B L6–L31 3,952 7,904
合计 30 个模型—层组合 4,560 9,120

每个模型—层仍为十个旧通道各 +1 × 八题，加其中一个旧通道的四档低正剂量及五档负剂量 × 八题，共 19 个通道—剂量条件、152 份回答。不是给十个通道各补十档剂量。

完成后的唯一覆盖为：2B L0–L5，920 条；4B L0–L31，4,872 条；9B L0–L5，920 条；合计 6,712 条。原先每模型八份独立原版回答共 24 条全部复用，不再生成。三个模型前六层可以先比较；4B 全层阶段随后独立完成。

2. 来源与避免重复

三份源 JSONL、SHA-256、模型 revision、参数和维度见 contract.json，沿用原项目证据。按 (model_id, layer, channel, dose, question_id) 唯一身份去重；相同身份的 token 或校准冲突必须失败。

新增 4,560 个身份必须与原队列全部 2,152 个计划身份互斥；两个追加阶段也必须互斥。源记录、原始回答、校准、偏移、历史 shard、原始 record/receipt/metadata 哈希全部保留。执行 shard 与历史 shard 分开：在每个阶段和模型内对条件排序后交替分两卡，同一条件的八题放在一起。

原来的基线可作为校准和来源引用放入清单，但不得进入新增生成计划或新增结果分母。失败不自动跳过、重试或伪装为完成。已有输出目录不得覆盖；已有记录及当前队列的冻结文件不修改。

3. 同一测量方法

直接复用冻结的原 trace_engine.py，不修改生成或观察算法。每条记录使用原 prompt、校准、同一通道/剂量及原始 BF16 偏移；BF16/eager、greedy、batch=1、thinking 关闭、原 EOS、最多 128 新 token 均不变。输出必须与旧来源逐 token 一致，不续写或为语义结果重试。

注入点仍为 gated MLP 的 down_proj 前坐标，覆盖原 prompt 与实际生成位置。每个实际分支配一个独立 cache 的同前缀无针参照，记录强制 token 选择之前的 logits；无针参照不是原版自由回答。

观察覆盖各模型全部层的 attention/GatedDeltaNet 输出、MLP 输出和层末残差；保存原方法的逐位置范数、差分、相对变化、余弦、逐步 EOS 竞争、候选词并集交叉评分和前缀身份。不保存全部高维向量，不增加 patch、反向替换、随机方向、训练或静态权重编辑。

4. 验收与继承预检

本次改变来源选择和调度，采集引擎及其依赖保持原冻结版本。CPU 测试必须验证新增数目、两阶段顺序、与原队列无交集、基线仅引用、原范围完整、来源冲突拒绝、冻结身份、前驱/GPU占用门禁和失败阻断，且零失败、零错误、零跳过。

原队列已经完成的三模型六 worker、42 个观察案例/114 条生成流 GPU 预检可继承，但必须验证完成收据、退出码、预检接受凭证及对应冻结哈希。既有预检和基线回答不重复生成；不能仅凭口头“通过”开始追加。

每次模型加载仍做模型资产、运行环境和目标权重核对，并用原八题 prompt 做清洁校准前向，与旧校准逐项一致；此处没有生成新的基线回答。每条新增记录继续执行原有严格验收：旧 token、prompt/校准、偏移身份、全层三组件和应有位置覆盖、有限数值/明确未定义值、原 prompt 上注入点之前组件不变、hook 撤除。每个 worker 结束必须核验目标权重未改和全部输出哈希。

任一验收失败即停止本追加批次，保留失败和部分输出。不得放宽阈值、改回答或自动扩大预算。继承预检不等于可以跳过新增记录自身检查。

5. 队列与完成标准

后台追加队列先等待原 2,152 条任务成功完成、其进程退出，并确认 GPU 0/1 无其他计算进程；然后运行 six-layer，该阶段全部成功后运行 4b-full。每次仅一个模型、两张 GPU、每卡一个 worker。只清理自身启动的子进程，不停止前驱或其他任务。

合同、来源和代码另行冻结；授权绑定来源预算、前驱身份、测试收据和输出目录。无需用户再次确认启动。最终新增阶段须有 4,560 个完整唯一身份，与旧采集合计 6,712 条；每份图上记录能够返回原始文本与轨迹证据。排队、各阶段模型加载、生成/参照、核验和保存耗时分别记录；CPU测试通过、排队、运行中和完成分别报告。

6. 解释边界

L0–L5 是统一的观察窗口，不预设自然功能边界，也不把 L5 视作经过验证的分界。2B 共24层，4B/9B各32层，保留绝对层号和相对深度；同层号、同通道号或三维邻近不等于同源功能区。

4B全层追加用于比较不同深度的传播和输出变化。相似轨迹、差分峰值、停止倾向和词汇变化仍是机制线索，不能单独证明因果根因、人脑式功能分区或道德/安全神经元。无相似规律和反例同样保留。
