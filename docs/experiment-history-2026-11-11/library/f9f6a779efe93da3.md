# CFM-LOCAL-READOUT v1 决策日志

每条：偏离了什么、为什么、影响哪些结论。

- **D1 模板前向（冻结前）**：方案只计“前缀形成”和“单步评分”。重建评分缓存需要一个结构正确的 cache 对象，combo 用新形成的 C 前缀作模板，本轮禁止形成。改为每 worker 一次 1-token（位置0）前向取对象，随后所有内容张量被归档覆盖并逐字段核对 bridge manifest；正确性由 Y_T / T_native logits 逐位重放检验。单列计数（预检1、正式2），不计入评分与形成。影响：无科学读数依赖它；若重放失败即说明此路不通，按合同停止。
- **D2 补丁精度（冻结前）**：方案 §6 写“FP32 减法”，§10.4 要求减后加回逐位恢复。FP32 下 (c−d)+d 不保证逐位等于 c；改为 FP64 减法/加回后一次转回 BF16（BF16 值在 FP64 中精确）。已写入方案 r3 §10.4。删除对象不变；删除量误差仍按实际返回值计。
- **D3 随机方向归一化精度（冻结前）**：标准正态仍按方案在 CPU FP32 生成；逐头归一化放在 FP64，使匹配后的逐头范数与 I 相等到 1e−12（FP32 归一化有 ~1e−7 误差，会让“范数一致”闸门无法逐位成立）。方向本身不变。
- **D4 记录器关闭的 N 参考（冻结前）**：方案 §9.2 列为“N记录器关闭参考”。冻结代码 `form_ab.score` 要求模型无任何钩子，而 N 必须装入口钩子；改为只装入口钩子、直接前向并比较 logits 哈希。检验目的（记录器不改变输出）不变。
- **D5 D 复算容差（冻结前）**：读数里的 D 以冻结 `bridge.score` 的值为准；`lr_core.cell_readout` 的 FP64 复算与之差 ≤1e−5 作为一致性检查，不另取值。
- **D6 我在讨论中的口误（冻结前登记）**：对话中曾称 VAR03-f0“原生不停止”、VRL04-f0“原生停止”，与归档相反（VAR03-f0 原生 D=+0.0625，VRL04-f0 为 −0.8125）。方案原文正确，预检选择不受影响。
- **D7 冻结前已见的局部描述**：CPU 预演（`readiness/cpu-real-data-r01.json`）给出 M 背景 cos(I, A_S+A_F) 在 −0.47 至 −0.56。它来自归档、不含任何新评分，合同中登记为已知描述，不作判据，也不据此改动判据。
