# FC-01（首步选择、条件续答与卷积恢复的有限行为验证）合同 r01

日期：2026-11-02。设计：[计划 v1](https://github.com/yuxiexiong/acupuncture/blob/7d6bdf84ab74062ac9ab55bc8201b5a6586b92c8/docs/cache-first-token-continuation-plan-v1-2026-11-02.zh-CN.md)（评审撰写，6486eff），本合同只把计划冻结为可执行规则，不改科学判据。基准：NR-01（c19cb45）、CT-01（c11487f）。授权：用户 2026-11-02「同意，直接写计划合同代码，测试后上卡跑」。已见面板；续写输出未见。

## 1. 操作

沿用 NR-01 的模型、revision、BF16、内核、token、晚段窗口、L0 剂量 −1、四方向、12 条输入、worker/GPU 分配、进程内校准。每输入形成 C；每方向形成 T。从评分前缓存的独立克隆出发，先处理末 prompt token 得到第一步 logits，再按臂选择第一个输出：

| 臂 | 起点缓存 | 第一个输出 | 之后 |
|---|---|---|---|
| C_nat | C | argmax | 自然贪心 |
| C_noEOS1 | C | 屏蔽停止集合后 argmax | 自然贪心 |
| T_nat | T | argmax | 自然贪心 |
| T_noEOS1 | T | 屏蔽停止集合后 argmax | 自然贪心 |
| T_q0 | T | 强制 q0（C_nat 的实际首 token） | 自然贪心 |
| T_F | T 但深层 G 层卷积缓冲恢复为 C（NR-01 的 010 组装） | argmax | 自然贪心，缓存正常更新 |

最多 32 个新 token（含强制 token 与停止 token）；停止集合 {248044, 248046}，模型配置的 eos（248044）已包含在内；argmax 平局取最小下标；无采样、温度、重复惩罚或自动模板；生成期不注入针、不挂任何 hook；`<think>` 不当作停止。真实选出的 token 喂入下一步。预检另做 C_q0（等价核对）以及首输入的 C/T4146 重建续写。

## 2. 预算

| 阶段 | 形成 | 轨迹 | 解码前向上限 | 校准 |
|---|---:|---:|---:|---:|
| 预检（P01-f0/f1，1 worker；含 C_q0 ×2、重建续写 ×2） | 12 | 40 | 1280 | 1 |
| 正式（12 输入，2 worker） | 60 | 216 | 6912 | 6 |
| 合计 | 72 | 256 | 8192 | 7 |

GPU ≤1 小时（预检实测后若预计超限则停止汇报，不缩短 32 或减少输入）；产物 ≤8 GiB。预检工程失败可记账后重试一次；正式不重试。

## 3. 工程闸门（任一不过即停止）

校准、GPU 分配等于 B3；L0 写入 ≤1%；第一步原始 logits：C_nat = NR C_native，T 三臂 = NR T_native，T_F = NR R010（逐位）；T_nat/T_noEOS1/T_q0 第一步 logits 与更新后缓存哈希相同；q0 = C_nat 首 token = NR a_token、非停止、是目标编号的前缀；C_noEOS1 与 C_nat 逐 token 且终态缓存哈希相同；预检 C_q0 同上；屏蔽/强制只在第一步，强制的 q0 实际喂入下一步；T_F 组装：浅层、S、KV 来自 T，深层卷积来自 C（哈希）；供体不变；生成前无 hook；预检重建缓存哈希一致、续写逐 token 相同。

## 4. 读数与判读（`fc_core`，照计划 §5–6）

可见文本 = 去掉停止 token 文本、去掉所有 `<think>…</think>`（未闭合则其后全部去掉）。编号 = `(?<![A-Za-z0-9])[A-Z][0-9]+(?![A-Za-z0-9])`。Y_delivery：可见文本含目标编号且无其他不同编号（主读数）；Y_strict：可见文本去首尾空白后恰为目标编号。互斥主分类：多编号 > 正确 / 干扰编号 / 其他编号 > 停止且无编号 / 预算内无编号。正交标签：think 出现/未闭合、编号数、首个编号及是否正确、目标重复、可见文本是否含完整问题原文及次数、停止步、token 数。

- **P_F**（推测档）：每情景两事实都满足“C_nat 正确且 T_F 正确”（Y_delivery）才支持；方向内 ≥5/6 情景支持；预期 ≥3/4 方向。若 C_nat 两事实都正确的情景不足 5 个，记基线不足。另报 T_nat → T_F 的转移（错→对、都对、对→错、都错）。
- T_noEOS1、T_q0 不预设优劣，按计划 §6 结果表解读；q0 提示审计（计划 §4）逐输入报告。
- 措辞：T_q0 答对只说明“给定正确前缀后能生成正确后缀”，不推出记忆完整；失败不推出内容删除；首 token 排名只作解释变量。
