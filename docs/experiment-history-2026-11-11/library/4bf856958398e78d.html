QC-01（目标指定 × 问题布局 × 注入覆盖）结果报告

日期：2026-11-02。合同 r01；决策 D1–D7；计划 v1（8f9324e，评审撰写）。代码 8a63880，freeze-r01 2cd5ce17…27aa。五个新条件此前无模型输出；NB 复用 NQ-01（6 个场景各一条逐位重放通过）。同一助手实现、运行与撰写。

1. 结论（不利与限制先说）

  1. 覆盖与注入总量混淆，本轮不能区分。 问题在窗口内的条件（NA、LA）窗口 26–27 token，缩窄后（NA-tail、LA-tail）20 token；每 token 名义写入范数相同（约 2.63），宽窗口的注入总量约多 30%。所以下面的“覆盖效应”是“覆盖范围 + 总剂量”一起变化的总效应，不能写成“问题 token 被写坏”。
  2. LB（标签式、问题在前）不可判：干净运行只有 48/54，NQ01、NQ03 两个场景低于 8/9（6 个失败格都是干净模型把三个编号全列出来）。LB 的结果只作描述，不进入比较结论。
  3. 缩窄本身也减轻了损伤：tail 条件下未恢复的 T_nat 有 0–18/54 自然答对（NB 为 0–1/54）；LA-tail 的 R0 因 T_nat 37/54 答对，按规则判为“效应未迁移/不可判”。按计划，这部分只算减轻损伤，不算 V 修复更强。
  4. 预注册的 P_cov 成立（两种指定方式都支持）：同文本、只缩窄注入窗口，T_V“跟随查询”从 1/4 方向（NA、LA 都只有 C1343）升到 4/4（NA-tail）和 3/4 + 1 不可判（LA-tail）。
  5. SP 上的“首列”失败在按名查询下复现了：NA（按名、问题在记录后、问题在窗口内）的 N4146 方向，T_V 在目标不在首位的 36 格里 36/36 输出首列编号、0 输出目标；同文本缩窄后变成 36/36 目标。LA 在 N4146、N1210、R0 也是首列占多数（31/30/29 of 36）。
  6. 在可判条件中，两种指定方式呈现相似的宽窄窗口趋势（LB 不可判，四模板比较缺一角，不能说指定方式总体不重要）：宽覆盖下 NA 与 LA 都失败（NA 在 N1210、R0 略好）；缩窄后两者都恢复。布局（问题在前 vs 在后，且都不注入）在 NB 与 NA-tail 之间对 T_V 几乎没有差别（R0 上 NA-tail 更好）。
  7. 合起来（类比档，跨条件解释）：SP 与 NQ 相反的恢复结果，主要对应“问题所在区域是否被注入”（连同剂量），而不是目标指定方式。T_F（完整卷积恢复）在全部可判条件中都是 52–54/54（LB R0 43/54 不可判），没有失败。
  8. 工程全部通过：NB 重放 6 条 × 13 轨迹与 NQ-01 逐位相同；所有窗口按 token 审计；C/T 共用窗口前缓存；通道块来源逐位核对。同文本宽/窄覆盖的 C 自然输出 54/54 相同，首步 logits 哈希 0/54 相同。零 GPU 审计（§7）：差异在 BF16 精度级别（共同首 token 分数最大差 0.25、首步分差最大差 0.375、诊断三候选最大差 0.375 logit，中位 0–0.125），来源是窗口边界移动后，哪些 token 走整段预填、哪些逐 token 形成的计算切分不同；C 的首步分差最小 10.6 logit，任何 C 判读不受影响。恢复用的 C 供体也随之有同级差异。（更正：初稿写“证实各自形成 C 的必要”，不成立——这只说明切分改变 BF16 数值，两种选择没有哪个更正确。）

5. 解读与出口

  • 计划 §7 的出口“同文本覆盖差异稳定”成立：下一步候选是另立合同区分覆盖与剂量（例如在缩窄窗口内把每 token 剂量提高到与宽窗口总量相同，或在宽窗口里降低每 token 剂量），本轮不暗加。
  • 不能说：问题 token 被写坏；指定方式无关（LB 不可判，NA/LA 在 N1210、R0 有差别）；V 是选择的承载者。可以说：在这个面板上，只恢复 V 能否恢复正确选择，强烈依赖问题区域是否在注入窗口内（含剂量变化）；SP 与 NQ 的相反结果主要对应这一点。
