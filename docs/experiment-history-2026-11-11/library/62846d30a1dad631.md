# NQ-01：按条目名查询时，恢复后的回答跟随目标还是记录位置

日期：2026-11-02；版本 v2；状态：未运行的设计。本文与[自查记录](https://github.com/yuxiexiong/acupuncture/blob/7d6bdf84ab74062ac9ab55bc8201b5a6586b92c8/docs/cache-name-query-order-self-check-v2-2026-11-02.zh-CN.md)共同交付。只授权本次文档编写和 Git 交付；未授权模型预检、校准或 GPU 运行。实现合同须引用本版，不以截图里的命令作为运行授权。

本版取代 v1 作为后续实现依据；v1保留作历史记录。修订：查询移到记录之前，固定注入后缀；每场景共享一次校准；Q仅描述；正式一次运行全矩阵，适用性按冻结规则自动判读。没有新增执行授权。

## 1. 设计卡与证据边界

**主线**：解释稀疏激活干预如何改变写入、历史状态处理及后续读取，最终改变回答。**本轮问题**：在记录内容与条目—编号绑定不变时，独立改变记录排列和查询条目，原生干预及卷积恢复后的回答，是否随被询问条目改变，还是随记录位置或固定条目／编号改变？这把现有“开始回答但选错目标”推进为可配对检验的行为关系；不把停止修复或层定位当总目标。

依据为下列已完成资产；不是新的独立复现：

- [SVQ-01 合同](https://github.com/yuxiexiong/acupuncture/blob/7d6bdf84ab74062ac9ab55bc8201b5a6586b92c8/experiments/cache-sp-v-qk-delivery-v1-2026-11-02/CONTRACT.zh-CN.md)及[报告](https://github.com/yuxiexiong/acupuncture/blob/7d6bdf84ab74062ac9ab55bc8201b5a6586b92c8/experiments/cache-sp-v-qk-delivery-v1-2026-11-02/REPORT.zh-CN.md)，结果 ae03863，事后诊断附录 a7d8566：只恢复 V 通常能开始输出编号，却不能可靠选中目标；完整 q/k/v 卷积恢复较好，C1343 是 V 单独恢复较好的例外。不能据此称 q/k 为选择器或 V 为内容存储。
- 同报告事后分析：在共同首 token 后，T_nat 的目标分数高于另一个非首位干扰项为 29/32；仍被首列编号压过。这是已见数据的线索，无随机零分布，不能推出目标信息完整保存。
- [SP 输入](https://github.com/yuxiexiong/acupuncture/blob/7d6bdf84ab74062ac9ab55bc8201b5a6586b92c8/experiments/cache-shared-prefix-continuation-v1-2026-11-02/data/inputs-r01.json)用记录内“目标条目”标签指定答案，问题本身不变；旧数据不能在记录完全不变时改问另一个目标。
- [FXS 报告](https://github.com/yuxiexiong/acupuncture/blob/7d6bdf84ab74062ac9ab55bc8201b5a6586b92c8/experiments/cache-fx-fixed-score-followup-v1-2026-11-02/REPORT.zh-CN.md)的分数非加和不排除行为跨阈值；固定45头支线不重开。

**新增量**：区分“位置第一”与“特定条目／编号偏好”，并检验输出与条件分数是否随问题所指目标改变。固定条目—编号绑定时，条目偏好与编号偏好仍不可分；本轮不承诺区分它们。不能从行为规律推断内部注意力路由、记忆删除或唯一承载者。

**估计对象**：同一场景内，顺序、查询与恢复条件共同定义的完整运行之间的配对行为差异；恢复操作是混合状态上的条件性总效果。不同问题各自形成缓存，不是固定历史状态下只改一个查询向量。

**范围**：沿用6个 SP 场景的词汇和 f0 编号绑定，建立54个新提示组合；属于已见任务家族上的新组合验证，不是新任务、独立外部验证或跨架构证据。四干预方向沿用 N4146、N1210、R0、C1343，不筛掉例外。

## 2. 新面板：6场景 × 3记录顺序 × 3查询目标

每场景三个条目记为 A/B/C，固定如下。只用旧 f0 绑定，不再叠加 f1；新问题由名称明确指定目标，记录内不放目标标签。

| 场景 | 记录前缀 | A | B | C |
|---|---|---|---|---|
| NQ01 | 仓储台账 | 铁锚 U17 | 竹篮 U43 | 陶罐 U86 |
| NQ02 | 巡检名册 | 松针 V28 | 石桥 V54 | 芦苇 V91 |
| NQ03 | 图纸目录 | 齿轮 W35 | 弹簧 W62 | 轴承 W19 |
| NQ04 | 标本登记 | 蝶翼 X46 | 贝壳 X73 | 羽毛 X28 |
| NQ05 | 航线编排 | 北港 Y57 | 南屿 Y14 | 东滩 Y82 |
| NQ06 | 乐谱清单 | 短笛 Z63 | 竖琴 Z39 | 铜锣 Z15 |

固定模板（换行实际渲染）：

```text
{被询问条目}的编号是什么？
{记录前缀}：{条目1}编号为{编号1}，{条目2}编号为{编号2}，{条目3}编号为{编号3}。
请根据上面的记录，简短回答，只需给出编号。
```

聊天模板和系统消息沿用SVQ-01。将问题和全部记录放在边界b及之前；只有固定尾部指令与模板尾部进入 b+1..n−2。实现必须保存完整渲染字节、token ID、逐token区段标签与边界，并验证54条的注入窗口token序列完全相同、查询名称不跨入窗口。最后提示token仍单独评分。不能只凭文本相同推断token相同；边界跨token、窗口不一致则工程停止，修改后重新冻结，不静默移动窗口。

这避免直接在查询名称token上注入，但不保证查询相关状态未受后续干预影响，也不使不同问题共享同一缓存。问题提前改变了任务格式，必须重验C基线。

顺序仅 ABC、BCA、CAB；每个顺序分别问 A、B、C。每个条目恰好各处首、中、末一次。固定顺序改问目标时，记录字节完全相同；固定查询换顺序时，名称与编号绑定完全相同。54条全部提前生成、核对和哈希冻结，不按模型答案换例子。

真实分词器必须核对：同场景三个编号共同首 token 相同，第二 token 已能区分三个编号；不凭字符推定。若不成立，停止当前版本，报告分词不适用，不看生成后另挑编码。旧名字／编号的固定偏好与位置可分，名字偏好与编号偏好不可分。循环排列也没有穷尽全部相邻关系，结论限于这些排列。

## 3. 操作与实验臂

模型、revision、tokenizer、BF16、内核、L0 干预方向文件及剂量约定，严格继承 SVQ-01 的冻结配置和资产清单。形成窗口 b+1 至 n−2，最后一个提示 token 是评分入口；生成期不注入。每场景在固定 ABC/问A 提示上按既有流程校准一次，共6次；同场景9条提示、四方向均按既有方向规则复用该场景校准尺度，不按查询、顺序或损伤另调。保存尺度、实际注入值及逐token扰动范数。同提示各恢复臂共用同一份T供体。共享尺度消除逐提示校准差异，但不消除不同查询的形成响应差异，故不称为固定缓存上的纯查询因果效应。

源码核对：SP runner的 `run_item` 用 `PK.label_tokens` 得到b，再以 `range(b+1,n-1)` 形成，并先无hook预填至b。新模板不能直接沿用旧字符串边界假设；须明确按新模板标注并验收。截图对SP02实际token的报告作为评审依据，本次没有运行模型或真实分词器核验新模板。

| 臂 | 深层短卷积 q/k | 深层短卷积 V | 浅层、递推 S、全注意力 KV |
|---|---|---|---|
| C | C | C | C |
| T_nat | T | T | T |
| T_V | T | C | T |

每输入 C 共享，四方向各有 T_nat/T_V/T_F，共13条轨迹。供体来自**同一完整提示**的 C 或对应方向 T；不跨顺序或查询移植。深层 G 层为13、14、16、17、18、20、21、22、24、25、26、28、29、30；q/k 是短卷积缓冲通道0–4095，V是4096–8191，恢复全部值头。不是替换全注意力 KV。

恢复只发生在最后提示 token 评分前一次，随后所有下游计算与缓存随真实生成正常更新。C供体可重新引入任务信息，恢复阳性不证明T原有信息完整。没有T_QK新臂：本轮要拆位置与查询的混淆，不重复上一轮的V/qk四格。

自然生成：贪心 argmax，最多32个新 token，停止集合沿用 {248044,248046}；不屏蔽停止、不强制任何答案。每轨迹另建诊断分叉：首步评分后克隆更新后的缓存，喂共同首 token，只做一次前向并保存全词表分数。自然首步停止也保留诊断；诊断输出不计自然交付。

## 4. 先验适用性检查与执行顺序

采用一次运行全矩阵：工程预检通过且取得运行授权后，54输入的C及四方向T_nat/T_V/T_F全部运行，共702条自然轨迹；不由人工看C/T结果决定是否补跑恢复臂。

分析脚本按以下冻结规则自动判读：

- C场景合格：9格至少8格完整正确；面板合格：至少5/6场景合格。
- 损伤迁移按方向判断：某场景9格至少6格T_nat未完整正确且这些格C正确；至少4/6场景满足，才称该方向损伤迁移。
- C面板不合格，恢复机制主判为“新面板基线不足／不可判”；某方向未迁移，该方向标“效应未迁移／不可判”。仍完整公布所有臂与全部格，不删除、不换例、不缩分母。不能把不适用算作机制阴性。
- 适用方向在全部54格上应用§5规则，不只挑损伤格。方向结果保留支持、未支持、不可判三种状态；跨方向支持须达到固定3/4，未达到时区分实测失败与适用性不足。

这是科学适用性检查，不是软件闸门或统计显著性检验。CPU规则先以合成例覆盖通过、失败和不可判；冻结后不得人工裁决放行。一次运行避免第二阶段供体重建差异；预检及正式仍分别记录来源与重放验收。
## 5. 终点、配对对照与预注册预测

主终点为自然完整交付 Y_delivery，严格输出 Y_strict 同报，复用既有解析规则并冻结版本。额外记录输出对应的条目身份、列表位置、目标身份；列举多个编号与没有完整编号均单列，不把“文本含目标”算交付。

每方向／场景9格分别分类（所有未交付格留在分母）：

1. 跟随查询：至少8/9格完整正确交付目标。
2. 跟随首位：至少8/9格唯一交付首列编号。
3. 跟随固定身份：至少8/9格唯一交付同一条目／编号，查询与位置改变也不变。
4. 其余报告混合、其他位置倾向及未交付分布，不强行归类。

每场景另列目标不在首位的6格；在首位的3格不能区分查询与首位规则。中位／末位同样输出位置频数，只作描述。方向支持要求至少5/6场景满足相应分类；跨方向至少3/4支持，任一不可判如实保留，不能缩分母重算支持率。

**推测档预测 P_pos**：T_V 在至少3/4方向跟随首位。依据是旧SP非首位目标上的失败；C1343例外及按名查询的新难度是明确反例风险。

**推测档预测 P_target**：T_F 在至少3/4方向跟随查询。依据是SP完整卷积恢复3/4方向达标；新面板不保证迁移。T_F是参照，不是T_V不可超过的上限。

预测失败不修改名单、判据或场景。另列每方向逐格 T_F/T_V 的仅前者正确、仅后者正确、都正确、都错误，区分恢复差距与共同难例。行为“恢复”须同时列C正确且T_nat失败的配对改善数；单看TV正确率不等于因果恢复率。

**次级连续诊断**：共同前缀后记录三编号第二token原始logit、目标减最大干扰的M、首位减另外两项的分差；自然首步另记录共同首token相对停止集合最大值及全词表其他最大值的分差。共享前缀诊断只测提示条件下的选择倾向，不代表自然回答。

固定场景、顺序和恢复臂，对两个查询i/j定义：

`Q_ij = ((z_i-z_j)[问i] - (z_i-z_j)[问j]) / 2`。

每顺序3对、每场景9个Q。它对词表整体平移不敏感，是改问目标后相对偏好变化的描述量，不是信息存量或固定状态下的读取效应。

**Q不设支持门槛、不赋方向支持标签、不进入预测或放行判据。** 并列报告C、T_nat、T_V、T_F的逐格值、场景分布及相对C的变化；C只是阳性参照，不是查询无关零分布。0.5 logit或量化界不能代替科学零分布。BF16转FP64不恢复原精度，可按半ULP给四项误差和除2的数值敏感性界，仅说明量化影响，不解释为统计置信区间。

自然输出与Q描述可以不同；Q为正或较小都不能证明信息完整或删除。本轮有用增量由正交面板上的自然行为跟随提供，不靠Q阈值成立。
