实验设计自查规范

版本：v1；日期：2026-10-31。来源：用户对本项目连续实验设计的纠正及本日明确要求。

适用：Acupuncture 两条研究线的所有后续新实验和实质修改，包括实验计划、补充实验、探索性分析与运行合同。缓存机制案例用于说明，不把其他课题强制改成缓存研究。

交付规则：设计者先检查、修正、复查，再把通过设计审查的版本交给用户。不得把已知的逻辑硬伤留给用户发现。 本规范是研究质量要求，不是额外的用户审批流程；已有授权继续有效。设计通过不等于实现通过、实验已运行、假设成立或 GPU 获得授权。

1. 判断标准

缓存线总问题：针插入以后，模型内部如何反应；怎样改变写入、旧状态处理和后续读取，最终造成显著的回答变化？ 撤针、首步停止、事实敏感度及某一层组是条件或窗口，不替代总目标。

每轮应直接推进其中一个可解释的环节，允许形成有边界的机制片段、因果定位、负面证据或可失败的计算预测。不能要求每轮闭合全部机制，也不能靠把目标改为“只要有输出变化”通过审查。

区分三类问题：

  • 硬伤：即使预期结果全部出现，仍无法支持本轮承诺；操作与名称不符；指标偷换；隐含必要前提不成立；无法区分却声称能够区分。必须修正，不能用免责声明抵消。
  • 可接受边界：适用范围有限；尚未找到唯一原因；有明确含义的混合反事实；暂未连接完整机制。说明为什么边界内的认识仍有价值，不自动否决。
  • 工程待验收：实现、重放、数值容差或实际耗时尚未验证。可通过逻辑设计审查，但不能标为可直接运行；工程失败停止执行，不冒充科学阴性。

不以实验数量、矩阵大小、GPU 用量、审查轮数或文档篇幅证明质量。

2. 设计卡：审查前必须填完

  1. 主线和本轮问题：各一句；说明连接关系。
  2. 新增认识：与已有理论、related work、已有数据相比具体新增什么。
  3. 依据与反例：固定来源、运行/计划身份、已有最不利证据；未知和缺失量明列。
  4. 操作：模型/版本、针/剂量、供体与接收者、层、位置、时段、hook 边界、替换内容、固定项和继续响应项。
  5. 估计对象：比较哪两种运行的哪个终点；是局部量、操作总效果、条件性依赖还是路径归因。
  6. 判读：正向、反向、部分、无效、异号和不可判分别改变什么认识；哪些结论不允许。
  7. 范围与成本：复用什么、真正缺什么；独立样本、探索/确认身份；重建、重放和验收均计入预算。
  8. 退出：什么结果结束本轮、撤回解释或暂停分支；不得自动扩层、加剂量、换题救假设。

3. 必过的十四项

每项填写“通过／不通过／不适用＋理由”，并指向设计中的具体段落或证据。不得只打勾。

ID 自查问题 通过要求
C01 主线 有没有从原问题偷偷换成撤针、局部敏感度、停嘴、事实丢失或热点？ 局部任务怎样推进原主线说得清；总体问题保持不变。
C02 增量 结果出来具体比现在多知道什么？ 至少一条实质认识；不是重复公式、验证模块存在或仅报告输出变了。
C03 资产 源码、理论、文献、已跑数据实际用了哪些？ 给出处和适用边界；使用已有成熟解释，不为新颖性另造框架。
C04 假设 有什么支持，又有什么反例？ 同时面对最不利结果；不从“可以发生”跳到“实际发生”。
C05 操作 真正改变的是哪个对象和时刻？ 当前输入、过去状态、当前更新及未来缓存分开；供体、位置、层、剂量清楚。
C06 路径 哪些固定，哪些正常响应，哪些被阻断？ 没有手动修改不等于保持不变；直接操作与所有下游后果分开。
C07 耦合 是否割裂共享变量或引入补偿？ k/β 等共享用途明确；反事实含义明确，不声称自动回到原生轨迹。
C08 归因 结果能支持所用的因果词吗？ 能影响、恢复、条件必要/充分、形成来源、承载位置、原生路径不混用；跨阶段拼链需条件对齐。
C09 区分 候选真有不同预测，且这些预测真由假设推出吗？ 不强制互斥；可共同成立、部分支持或不可判；剩余项不能靠排除法命名。
C10 指标 终点有没有被代理指标替换？ 状态距离、局部读取、D、EOS、完整交付、正确率、事实敏感度分别定义；主要读数能回答本轮承诺。
C11 失败 科学阴性和实现失败能分开吗？ 允许有效阴性；不把没恢复写成架构矛盾；阈值有明确用途，不伪装统计显著性。
C12 成本 是否必须新增运行？ 先用旧数据/理论/CPU；新增每格有用途；不为完整感同步跑所有模块。
C13 可信度 身份、数据划分、校验和报告是否可靠？ 冻结、原始结果、失败、单位与缺失明列；看过结果的面板不能继续称完全未见；实现验收另列。
C14 累积 什么结果会改变下一步判断？ 本轮能留下稳定结论；正反结果不都自动导向更大实验；不要求提前设计下一包。

4. 必查的历史错误

以下是本对话曾出现的错误或过强推断，作为检查对象；不是已经证实的模型机制。

ID 错误 防止重复的方法
E01 把撤针持续性当总目标；反复缩小问题；用户要求修方法却换问题 对照 C01，明确保留的问题与修改的操作。
E02 实验后才补架构常识；默认 L12 是天然特殊点 先核源码与选点历史；不把层号和两个锚点推广为通用规律。
E03 少坐标等于小扰动；后来又因扰动大就排除放大 分开校准尺度、逐 token 实际扰动、传播差异和行为幅度；绝对范数跨层比较不定位原因。
E04 把代数分账或固定驱动恒等式当机制发现 已知公式只是工具；新增认识必须是实际作用的大小、方向、条件或因果约束。
E05 将写入/处理共享变量独立拼换；用 value 补偿保持 βv 不变 明确操作是否改变原模型允许的联合关系；不宣称排除了失配。
E06 只换 value 与衰减门就代表全部写入与旧状态处理 检查 k/β、查询和后续响应；有限变量不代表整个机制类别。
E07 四格/八格、恢复和反向移植都有效，就证明原生路径 双向作用仍是特定反事实证据；不自动排除补偿、冗余和背景依赖。
E08 “只留 G”供体/固定值含糊；把结果直接命名直接/间接作用 写明每格所有组来源、G 的固定值、参照、允许的下游反应及估计对象。
E09 状态交互与行为交互都大，就认定前者导致后者 构造它们来自不同分量或读出非线性的反例；两项同时变化不等于已连接。
E10 分数恢复＝实际停止恢复；不停止＝正常交付 D、首步 EOS、后续停止和完整任务表现分开报告。
E11 事实敏感度＝信息存量；对比向量转向＝语义完整保存/删除 数值区分与语义/行为结论分开，不能由投影直接推出信息有无。
E12 配对相减自动消除一般损伤；反射方向可充当零分布 检查乘性压缩、地板效应、非线性和对照自身损伤；结构化反向不等于随机零对照。
E13 恢复供体重新带入事实，却称原记忆恢复 明确供体身份和信息来源；“没回完全干净”也须按真实供体理解。
E14 必要、充分、最初形成和末端承载混用 分别写与每个词对应的操作条件；恢复强度不是自然机制份额。
E15 S2 某层过程与 S3 全层 V 阳性直接拼成完整链 对齐旧历史、时段、变量前/后卷积位置、层范围、读取背景和终点。
E16 阴性不符预期就认定实现有误；所有剩余解释都算支持 工程校验独立于科学结果；保留异号、无效和不可判。
E17 减去残差原始加法项等于撤销干预；换写入变量等于只删过去记忆 区分当步分支响应与跨位置状态；减法不撤回已经形成的下游后果。
E18 A/B 不起作用，剩下的就是浅层放大 操作不一定穷尽路径；方向改变不等于增益放大；不预设三分唯一。
E19 L12 完全抵消/全缓存替换重放成功算机制发现 结构必然性作为工程校验；有限精度也不能用口头“精确”跳过。
E20 不同维度的解释被包装成互斥候选 位置集中和方向集中等可以同时成立；预测必须按真实假设限定。
E21 旧查重报告永久有效；多拆几格就是原创 针对实际主张核对直接近邻；区分方法已有、具体结果新增与领域首次。
E22 六情景两事实当十二独立样本；同源分析当独立确认；已见面板仍叫留出 明确分析单位、观察历史、开发用途；探索结果不冒充外部确认。
E23 把自查称独立审查；计划、完成、验收、复现混同 准确记录身份和状态；同一助手的反方检查不算独立复现。
E24 每轮要求完整机制，贬低有价值的局部定位 只要求本轮承诺与证据匹配，明确其如何累积认识。
E25 每个疑点都加对照，导致矩阵和 GPU 预算失控 先修定义、删无效模块或收紧结论；结论收紧后仍须有实质增量。
E26 研究形成过程，但最终输出还混入了被操作部位的直接读取效应 检查形成期操作与评分期背景是否对齐；若未隔离，承认测的是总效果，不命名为形成中介。

5. 自查与反方检查流程

  1. 填设计卡与 C01–C14，不通过项先修，不交给用户替设计者排错。
  2. 与最近一版及对方设计比较：哪些问题/操作保留、哪些改动、改动解决哪个错误；不靠换题过关。
  3. 同一助手站在反方检查：预期结果全出现能否仍有合理替代原因？完全相反时是否真正撤回？哪些问题使认识无效，哪些仅限定范围？修复是否更贵、更偏题？
  4. 逐条记录反例如何处理。改变操作、估计对象、终点或结论后重过相关项及 C01/C02/C08/C14；不得因上一版曾通过而沿用结论。
  5. 标明判定：设计通过／设计未通过，继续内部修订／当前无法设计出有增量的有效比较。后两类不得作为可执行方案交付；确实缺信息时说明具体阻塞，不伪造通过，也不无限循环凑方案。
  6. 设计通过后，另列代码/数值/来源验收与运行授权状态。用户只收到通过版本和关键限制，不收到每一轮失败草稿；内部审查历史可保存以便追溯。

反方不得仅靠“可能补偿”“可能分布外”否定所有干预。必须指出它怎样破坏当前承诺；无法排除的一般风险如实限定即可。无需为每轮组建独立团队，也不得将角色模拟说成独立审查。

7. 证据与维护

  • 项目主线、研究状态：最新用户纠正优先于历史快照。
  • S1 原始轨迹设计与计算对象：结合固定版本模型源码核对计算路径；历史任务表述不替代用户最新主线。
  • S3 固定结果：使用报告实际支持的条件性作用及边界，不将旧计划当完成证据。
  • E2 固定结果：只完成 E2，不冒充 E1 已完成。

只有新证据或用户明确修订才调整规则。不得为让某个实验通过，临时放宽其核心识别标准。检查表不是零错误保证；发现新错必须主动更正并记录，不要求用户承担发现责任。
