FC-01（首步选择、条件续答与卷积恢复的有限行为验证）结果报告

日期：2026-11-02。合同 r01；决策 D1–D5；计划 v1（评审撰写）。代码 9baa563，freeze-r01 c1bc9dfb…df47。已见面板，续写输出此前未见。同一助手实现、运行与撰写。

1. 结论（含限制）

  1. 干净基线可用：C_nat 与 C_noEOS1 都是 12/12 正确交付，且都严格只给出编号（Y_strict 12/12）；C_noEOS1 与 C_nat 逐 token 相同。
  2. 原生干预下完全不交付：T_nat 在 48/48 个单元未交付编号（N4146、N1210、C1343 首 token 即停止；R0 多数先输出问题行开头“请根据上面的记录，简短回答”的片段，然后停止）。
  3. 只给一次“不停止”的机会，大多仍不交付：T_noEOS1 的 Y_delivery 为 N4146 0/12、R0 0/12、C1343 2/12、N1210 6/12（Y_strict 全部为 0）。主要形态有两种：(a) 输出问题行的开头片段（“请根据上面的记录，……”）后停止（N4146 10、R0 12、C1343 6）；(b) 输出一个空的 <think>\n\n</think>，然后开始逐条罗列记录（“根据您提供的档案记录，关键信息如下：- 松塔编号：A17 - 目标条目：……”），在 32 token 预算内被截断（N1210 12、C1343 6、N4146 2）。按冻结规则，(b) 中只来得及出现第一个条目编号的单元被判为“干扰编号”（N1210 3 例），这来自罗列被截断，不是模型选错了答案。
  4. 给定正确的首字母后，几乎全部接出正确编号：T_q0 在 47/48 个单元正确交付且严格只给编号；唯一例外是 N4146 的 P02-f1（目标 D14，输出 “D1” 后停止）。f0 与 f1 的目标编号只是数字顺序不同（如 B26 与 B62），T_q0 在两者上都接出了对应记录的正确数字。限制（计划 §4 的 q0 审计）：12 个输入中，q0 都只覆盖编号的首字母，而且没有任何干扰编号与 q0 同首字母，所以强制 q0 实际上排除了记录里的其他编号。T_q0 正确只说明“给定这个前缀后，干预状态下仍能生成正确后缀”，不证明原来的记忆完整，模型也可能是在给定首字母后从提示里复制。
  5. 只恢复深层卷积，就完全恢复交付：T_F 在 48/48 个单元正确交付且严格只给编号。预注册的 P_F 4/4 方向成立（每方向 6/6 情景；基线 6/6）。转移：T_nat → T_F 为“错→对” 48/48。

4. 按计划 §6 的结果表解读

  • “q0 答对、noEOS1 大多未答对”：正确前缀条件化比给一次任意继续机会有效得多。不能说“信息完整保存”或“唯一瓶颈已定位”。
  • “F 答对”：状态恢复（只恢复深层卷积）在这组输入上足以恢复完整的编号交付，不只是恢复首 token；CT 中 F 让 q0 回到第一（48/48）与这里的完整交付（48/48）一致。不能说 F 唯一保存答案，也不能说它是自然路径。
  • 由 T_noEOS1 可见：原生干预下，一旦首步不能停止，模型常常转向问题行开头或罗列记录，而不是直接给出编号。这说明干预改变的不只是“停不停”，还有“从哪里开始说”。但在给定正确首字母的条件下，干预状态仍能产生正确的后两位。

5. 对课题的含义与出口

  • 回到核心问题：在这组编号检索输入上，稀疏干预造成的回答改变，主要表现为回答起点被改变：答案首字母失去优势，首步落到停止、问题行开头或 <think>。只要给定正确的起点，干预状态仍能接出正确内容（47/48）；只要恢复深层卷积历史，回答就完整恢复（48/48）。
  • 这和前几轮的状态分析衔接：深层卷积既是 CT 中让 q0 回到第一的那一类，也是这里让完整回答恢复的那一类。但 NR-01 显示它单独只占竞争差变化的 33–48%，所以“回答恢复”所需要的并不是撤销全部分数变化，而是让答案首字母重新领先。
  • 按计划，不自动启动新实验。若继续，可以问：深层卷积的哪一部分（例如固定 45 头的 V 通道）足以恢复答案首字母并带出完整回答，以及在不提供首字母的提示下，罗列记录时模型最终会不会给出目标编号（需要更长的预算）。两者都需要另立合同。
