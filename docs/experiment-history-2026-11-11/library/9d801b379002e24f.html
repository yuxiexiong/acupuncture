WIN-01 冻结前零 GPU 准备

2026-11-04。对应 WIN-01 设计稿 v2 §8。只用 CPU 分词器和已有记录，没有加载模型、没有用 GPU。服务器上的临时文件放在 /tmp/acu_win01/，没有写入仓库目录。

先说不利的部分

事实自动判读没过事先写死的门槛，按约定不用。 门槛写在 judge.py 文件头，写定时还没看到任何判读结果。

指标（阶段二全部 26,928 条已标注记录） 结果 门槛 结论

盲读为 follows_fact 或 other_fact 的 23,977 条上的一致率 0.885 ≥ 0.95 不通过

  • 合成自测通过，其中故意设计成会判错的例子确实被判错，所以"能判对"和"能判出错"都演示到了。
  • 最大的一类不一致：盲读判答对、自动判成 other_fact，共 2,601 条。原因是模型先给出正确结论，又复述了题面里另一件物品的位置，例如"钥匙放在红抽屉……而'票据放在蓝抽屉'……"。"取最后出现的关键词"这条规则因此判错。
  • 要修好，就得把关键词和所属对象绑定，相当于另建一个打分器。在同一批标签上边调边测，是拿答案调规则，不做。

2. f0/f1 逐位比对

  • 24 对里 22 对 token 数相同；这 22 对逐位比较，不同的位置全部落在事实段内，每对 1–2 个 token（例如"红/蓝""17/18""在三楼/在二楼"），两版的 b 相同。
  • 2 对长度差 1（RL02、CAR02），只做与长度无关的递推移植。
  • 所以 B 块位置相关的移植（KV、全部缓存）用这 22 对。限制：位置对齐只说明两版只差事实词，不排除事实词的差异在后续位置引起的状态差异，后者正是移植要测的东西。
