NVB-01 偏离与修复记录

D1（2026-11-03，预检 r01 合同执行失败 → 修复重试 r02）

  • 现象：runs/preflight-r01 在第一个输入、第一个方向（N4146）的随机臂 j=0 处断言失败：random direction differs between b = 0 and b = 1 的前身 rho differs between b = 0 and b = 1。此前该方向的全部闸门已在真实数据上通过（对角四格对 LVK 的 t1/C t2/M/自然 token 逐位一致、对角完整缓存对参考实现逐位一致、四组“只有 S 不同”桥接、FP64 恒等式、随机格对 B00b 的“只有 S 不同”桥接）。约 28 设备秒；无记录、无判读证据。分类：合同执行失败（信息量为零，不作任何负面证据）。
  • 根因（我写坏的闸门）：合同 §3 写“b=0/1 共用同一 ρ_j”，同时又要求 ρ_j 的幅度等于该头 ‖v1−v0‖。b=1 时第 13 层 k 编辑改变该层 t1 输出，更深 G 层的输入、v0、v1 随之不同，‖v1−v0‖ 必然不同，二者不能同时成立。闸门描述了想要的东西，而不是测量能支持的东西。
  • 修复：b=0/1 共用同一单位随机方向（种子只依赖输入、方向、j、层），幅度跟随各自前向的 ‖v1−v0‖——与主格中 v1 本身随 b 变化的方式一致。闸门改为核对单位方向哈希（dir_sha）；范数闸门不变。CPU 测试补“不同 v0/v1、同方向、各自幅度”一例。
  • 影响：判读口径、阈值、K、格子、输入都不变；DR_j 的配对含义从“同一 ρ”改为“同一随机方向”。第 13 层两者完全相同；更深层幅度随前向变化，与 a=1 的 v1 一致。合同正文未改（冻结），以本条为准。
  • 重试：按合同 §5 使用唯一一次有记录的修复重试：新 CPU 收据 r02、冻结 r02、授权 preflight-r02、输出 runs/preflight-r02。r01 目录原样保留。
