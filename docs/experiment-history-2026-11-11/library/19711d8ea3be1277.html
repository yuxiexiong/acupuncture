Gemma 3 4B：C 任务 50 轮方法复用

日期：2026-11-05。用户明确要求“把 gemma3-4b 下载到服务器，然后排队上卡实验。和 qwen vl 一样，50轮”。本目录承接已确认的 Qwen 两模型复用，保留逐轮正确率折线图与 CSV 的交付要求。

固定合同与真正的改动

模型为 google/gemma-3-4b-it，官方 revision 093f9f388b31de276ce2de164bdc2081324b9767。官方元数据见 upstream-4B.json。服务器现有 HF 账号已获访问权限，经本机官方 HTTPS 核验为 200；凭据只在内存中用于官方域名，不保存、不发送给镜像。权重通过官方签名 CDN 地址下载；地址以 0600 权限置于 Git 外，逐文件校验官方 LFS SHA256 / Git blob SHA1。

保持不变：C 的 64 个独立源组、2560 条开发请求、原图/题目/答案/顺序、评分、选择与保护、绝对编辑预算、gpt-6-astra / max 独立空上下文研究员、持久 CPU 沙箱和 SSH broker、BF16、SDPA、batch64、greedy、最多128生成 tokens。临时4,000,000、最终1,000,000个改动标量；每个新非零补丁完成全 D 评估计一轮，失败改善也计轮，诊断/部分评估/相同权重不计。50轮自动冻结；不加轮救结果。

继承每模型384,000样本/前向、1,622,016,000 target-token reservation、36,000 CPU Python秒、2,000研究员工具对话轮/50,000,000研究员tokens，无硬会话 wall cutoff。完整W0基线2560请求计入搜索账本；50候选完整评估至少128,000请求，诊断也计账。工程验收132生成样本+2诊断前向单列；下载约8.60GB权重与处理器文件、CPU预检和实际卡时另记，未测得的耗时不作承诺。

模型必要适配如下，均不改研究策略：

  1. 加载类使用 Gemma3ForConditionalGeneration，保留官方原始 safetensors 字节和 checkpoint 参数名。旧 language_model.model.*、vision_tower.*、multi_modal_projector.* 通过可审计别名对应新版 Transformers 的模块名；LM head 与词嵌入共享存储按真实配置验证。没有搬运 Qwen 的层号或补丁。
  2. 输入采用 Gemma 原生模板及896×896处理器，单图256视觉tokens、关闭额外pan-and-scan；保留原图像素来源。模板已含BOS，故处理器不再添加第二个BOS；保留原生token_type_ids对图像注意力的定义。不能把 Qwen 图像网格或模板强行套在 Gemma 上。两家族视觉预处理和分词不同，不声称逐token或纯架构受控比较。
  3. 独立新W0完整基线，旧4B Qwen预测不放进Gemma证据包，样本及图片不变。工程代码的视觉参数探针改为Gemma命名；三标量测试仅检验存取/回滚，不参与选点搜索。
  4. 独立运行目录与现有GPU文件锁共用。先等模型下载校验；再等无计算进程、显存低于128MiB、利用率0的空卡，取得锁后再次检查。已运行任务不被中断。服务器执行GPU模型，研究员继续采用本地现有ChatGPT CLI和SSH控制器。

验收与结果

先运行继承的离线合成测试；再用真实处理器及meta架构做零GPU预检：官方参数名映射、真实tie关系、原生模板入口与适配输入完全一致（含图/无图）、continuation不改前缀token。meta实例不是已加载权重，不能冒充真实模型验收。

领取空卡后，完成真实模型验收：严格checkpoint加载信息、全部运行时参数形状/共享映射、固定batch64重复、输入等价、三个固定参数标量修改/异常回滚/重新加载、诊断测量与直接logits一致。真实验收通过才测全W0和进入50轮。失败保留原件，报告工程错误，不静默降低batch、变更解码、重放不确定调用或把失败记作科学阴性。

结果目录：/workspace/acupuncture/external/wsp-vlm-c-gemma3-4b-v1-2026-11-05/4B/search/reports/。

  • result.json：原始基线、最后候选、按冻结规则选中的候选、冻结后的最终百分比。
  • trajectory.json / trajectory.csv：0轮基线及每个已完成轮次的全部请求正确率、C联合修补指标、候选身份和接受/拒绝理由。
  • progress.png / progress.svg：两种指标分面；每轮真实候选曲线与按原规则保留的模型曲线分别显示，不只画上升包络。未完成轮次不填造数据。

每完成一轮自动更新，停止时再更新。报告只读已有评分，不新增目标模型调用。C联合指标仍是选优依据，全部单题正确率可能非单调。原始回答、失败、候选、费用/调用计数和研究员transcript保留。

设计卡与自查

规范：docs/experiment-design-self-check.zh-CN.md v1。设计者本人自查，不是独立评审。

主线：用稀疏静态权重修补改善C图文冲突表现。本轮问题：相同WSP合同在另一家族Gemma3-4B是否能获得满足原保护条件的开发集改善？新增认识是方法适用范围从Qwen家族向Gemma的延伸或失败边界，不是模型排名或纯参数量因果效应。

依据：已运行Qwen C提供动机，当前代码、评分和数据为直接资产；Gemma效果尚未知。操作对象是本模型W0与每个候选静态补丁，在相同本模型输入/解码下比较完整回答。正向改善支持该模型该开发任务的可修补性；无合法改善则记录失败；保护失效说明候选代价不被合同接受；验收失败只说明实现未通过。到50轮或真实不可继续的阻塞结束，不自动扩任务、模型、剂量或预算。

项 判定及理由
C01 通过：保持C任务稀疏权重修补，没有转成新机制或其他赛道。
C02 通过：新增Gemma家族上的方法适用证据或阴性边界。
C03 通过：复用Qwen C引擎/合同/数据及官方Gemma模型卡和已安装实现，来源哈希记录。
C04 通过：Qwen阳性不保证Gemma阳性，Gemma基线和收益未知，允许无改善。
C05 通过：各候选相对原始W0的真实BF16权重变化；不固定Qwen选点。
C06 通过：模型内图片来源、文字、模板/解码固定，补丁后的正常前向响应不冻结。
C07 通过：原生共享权重不拆分；旧checkpoint名称只做别名映射，字节不改。
C08 通过：估计Gemma模型内开发改善，不能分离家族/训练/分词/视觉预处理贡献。
C09 通过：合法改善、无改善、保护失败、工程失败有不同判读，不伪造互斥机制解释。

C12 通过：旧Qwen结果无法给出Gemma修补效果；只加用户指定的一个模型。
C13 通过：固定revision/哈希/数据/合同；64独立源组；开发数据不伪装独立确认。

与上一设计相比，仅加入一个不同家族及必要模型/原生处理器适配；保持核心问题、同源数据、预算与选优指标。历史错误：E01保持问题；E02不移植层号；E03相同绝对稀疏度不等于相同扰动；E04/E19工程验证非发现；E10/E11不混指标；E12保护不代表无所有损伤；E14不推必要充分；E16保留阴性；E20不伪设互斥机制；E21不因跨家族阳性直接宣布novelty；E22明确开发选择和源组；E23自查/测试/真实验收/排队/完成分开；E24/E25不扩完整机制矩阵。E05–E09、E13、E15、E17–E18、E26属于缓存拼接或形成读取归因，本轮不做，故不适用。

反方最强反例：Gemma阳性仍可能是同开发集自适应搜索，不能推出未知样本泛化；不同家族的收益差可能来自不同基线、训练、模板或图像编码，不能归因于单个架构因素；候选高分可能伴随保护失败，不能用全程最高值替代合法保留结果。处理：明确开发身份、分模型W0配对、保留所有轮次与拒绝理由、用原规则选优，不扩大本轮承诺。负向结果不会自动触发更多轮次。

设计自查结论：通过上述方法复用范围；工程状态以 audit/ 及运行回执为准。执行授权来自用户本次直接指令，不由自查产生。零GPU检查通过与后台排队都不等于50轮实验完成。
