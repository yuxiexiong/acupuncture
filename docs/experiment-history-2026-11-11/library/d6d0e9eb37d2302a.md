## 2. C 数据不变，统计代码补齐

C 沿用已审核的160组、D64/H96、320张图与6,400个输入。此次没有重新选样、改提示、重划集合。重建输入与gold后逐字节比对原准备文件，三项 SHA-256 均不变，见收据。D/H共享45个对象名称，H96组中55组至少有一个D已出现名称；来源图组与无序对象对隔离，不代表物体全未见或严格IID。

[statistics_c.py](https://github.com/yuxiexiong/acupuncture/blob/2ed333ea1e2f4ae2358f081ee37dbaf3c26c6274/experiments/wsp-vlm-screen-prep-v2-2026-11-05/statistics_c.py)只读取已保存答案，复用v1严格名称解析器，完成：

- 五条件各格正确率、五条件同时正确率；B0/B1、T0/T1、两种顺序分别报告。主格使用每来源组预先固定的名称顺序，不固定取顺序0。
- 原图通常问句与反事实图通常问句的配对 b/c/Δ、单侧精确McNemar、按来源组10,000次bootstrap的95%区间（seed=20261105）。bootstrap区间不冒充零假设分布。
- 固定 A/B/C 三项 Holm 校正；未运行候选p=1，不能删掉A缩小检验家族。只有C结果时输出保守的暂时校正；B结果到齐后使用完整家族重新汇总。
- 模板/顺序一致性、B1逐条件修对与改错、挑战正确率与联合正确率；一致性中的 `same_parsed` 包含双方均无法解析，须同时看 `both_format_valid`，不能把它当正确性。
- C预登记错误模式的分母与计数：无图通常、原图通常和反事实视觉均对，反事实通常却输出反事实视觉答案。D至少8例、H至少12例的解释要求沿用方案；程序计数本身不证明已经在打开H前登记了诊断。
- 既定优先级门槛及暂不优先规则；任何整臂截断率或格式失败率>5%，先输出测量协议失败。格式错误、拒答、截断记错且单列；基础设施失败、缺失、重复或未知ID直接拒绝统计，不能偷偷缩小分母。

模型输出接口：一行一个JSON，至少含 `request_id`、`text`（字符串）、`truncated`（布尔值），可含 `status:"ok"`；其他status代表基础设施失败。模型只接收输入记录中的text/image，不接收gold或条件标识。完整分析入口核对gold与原冻结清单完全相同。

D与H的顺序仍须遵守：先仅分析D，登记错误描述与规则，然后才打开H。CLI默认只接受D预测；`--split all`用于H已按方案打开后的完整汇总。它不是推理运行器，不自动执行或证明这个时间顺序。

## 3. 离线验收及运行方式

已核对466张所选本地图片（B146＋C320）的RGB像素哈希；[本地PNG文件清单](https://github.com/yuxiexiong/acupuncture/blob/2ed333ea1e2f4ae2358f081ee37dbaf3c26c6274/experiments/wsp-vlm-screen-prep-v2-2026-11-05/audit/local_image_manifest.json)另存实际PNG字节哈希，供搬运校验。v1的 `bytes_sha256` 是上游编码图片字节哈希，导出的PNG编码可以不同，不能误当成本地PNG字节哈希；验收中发现这一字段语义差异后已修正，未改动上游记录。

[测试](https://github.com/yuxiexiong/acupuncture/blob/2ed333ea1e2f4ae2358f081ee37dbaf3c26c6274/experiments/wsp-vlm-screen-prep-v2-2026-11-05/test_offline.py)覆盖9项：B冻结可重建、精确检验方向/已知尾概率、Holm/Wilson、缺失/重复/未知/基础设施错误、全对阴性夹具、明确缺口阳性夹具与门槛、指定顺序及提示副作用、格式失败、D-only入口无需H输出。全部通过。[accept_offline.py](https://github.com/yuxiexiong/acupuncture/blob/2ed333ea1e2f4ae2358f081ee37dbaf3c26c6274/experiments/wsp-vlm-screen-prep-v2-2026-11-05/accept_offline.py)又用实际6,400格结构运行10,000次来源组bootstrap验收：全对夹具判暂不优先，人工构造的缺口夹具判行为缺口优先。收据明确标为 `SYNTHETIC_NOT_MODEL_RESULTS`。这些数字不属于Qwen实验结果。

环境：Python3.9.6、NumPy2.0.2、Pillow11.0.0（实际版本以验收执行环境为准）。仅使用CPU；目标模型加载0次、推理0次、GPU时间0。

## 5. WSP在哪里进入

本轮先筛查“固定模型在什么条件下稳定失败”，尚不修改模型。若某候选满足行为缺口条件，再让研究者AI根据逐题失败与对照反馈提出内部诊断，定位可影响该失败的层/头/通道，使用受预算约束的稀疏权重修补并根据开发反馈迭代。定位是待做的工作，不能把原作者层号或两层结构直接搬过来。

内部信息可读出只是线索；探针阴性不作硬淘汰，阳性也不证明少量权重能修好。后续须用干预检验与补丁泛化、保护题及等预算搜索对照判断。强提示若已解决问题，应重新评估权重固化的实际价值；强提示无效也不意味着WSP一定有优势。本次统计代码最多支持进入诊断的优先级，不能支持修复成功、机制发现或论文贡献已成立。
