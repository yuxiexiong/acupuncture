共用口径（所有检索者开工前必读）

日期：2026-11-06。检索截至 2026-11，重点 2024–2026；含 arXiv 预印本与 CVPR/ICCV/ECCV/NeurIPS/ICML/ICLR/ACL/EMNLP 正式论文。

我们在找什么

为一篇 CCF-A 级论文选题，对象是视觉语言模型（VLM / MLLM / LVLM）。要找的候选必须同时满足两条硬标准：

  1. 现象跨模型：同一个失败现象，在至少两个不同模型族上被实测到（模型族不同指视觉编码器不同或语言骨干不同，例如 LLaVA 系、Qwen-VL 系、InternVL、PaliGemma/Gemma、Idefics、Phi-vision、MiniGPT/InstructBLIP、闭源 GPT/Gemini/Claude）。
  2. 根因跨模型：造成该现象的内部原因（某类部件、某种结构性安排、某种训练造成的偏置）也有跨模型证据。证据强度分三级，必须标明： - 因果：对内部部件做干预（激活修补、消融、缩放、编辑）后行为按预期翻转，且在 ≥2 个模型族上做过； - 相关：内部读数与失败相关（探针、注意力图、logit lens），≥2 个模型族； - 论证：只有结构性推理（"因为都用了 X 所以…"），没有内部测量。

手段是次要的。我们不预设用哪种修复方法；重点是根因问题本身。

优先关注"干净"的失败：模型内部其实有所需信息（探针能读出、对照题能答对），但没用上；以及换提示修不好的失败。纯粹"能力不够"（编码器根本没看到）的也记录，但单独标出。

每个候选的记录字段（逐项填，没有就写"未找到"）

  • 现象：一句话；用什么基准/任务测的。
  • 现象的跨模型证据：哪些模型族、关键数字、出处（论文 + 章节/表号）。
  • 根因主张：一句话；位于模型哪一部分。
  • 根因的跨模型证据：哪些模型族；证据级别（因果/相关/论证）；出处。
  • 不同论文对根因的说法是否一致：若有相互竞争的解释，逐条列出。
  • 竞争者（已有修法）：逐个写——谁、方法一句话、在哪些模型上、效果数字、作者自认的局限或留给未来工作的话（尽量逐字引用原文）、是否开源代码（给 URL）。
  • 剩余空间：最好的已有方法之后，离人类/上限还差多少；哪些条件下现有方法失败。
  • 便宜办法：换提示/提高分辨率/换问法是否已被证明修不了。
  • 数据与基准：名字、规模、是否公开。
  • 阅读层级：每条证据后标 F（取到正文并核对了对应章节或表）、A（只读摘要）、S（只有检索片段）。关键数字必须来自 F。

纪律

  • 标题和摘要片段不算读过。最接近的论文必须取正文（arXiv HTML 版 https://arxiv.org/html/<id> 或 PDF）。
  • 网页摘要工具可能把你的提问当成引文回显或编造引文。凡是逐字引用，二次核对（例如 curl 取 PDF 后 pdftotext，再 grep）。
  • 不给等级、分数、"值得做/不值得做"的结论。不写"没人做过"，除非同一句里说明是哪一层（方法层/对象层/结论层）以及查了多少条查询。
  • "前人见过这个现象"是先例支持，不是坏消息。坏消息只指两类：事实约束（实测否定了某条路）与竞争解释（同一现象有另一个已发表的解释）。
  • 每个推断标档位：推导（有论证链）/ 类比（相邻领域证据）/ 推测（需独立验证）。
  • 轴要分开："多少"、"何时"、"在哪"不能互推。
  • 找作者留下的开口：future work、leave open、do not distinguish、remains unclear、fails when、limitation。有就摘出来。

文末必须附的检索日志

  • 查询条数与查询清单；
  • 取到正文的论文清单（带 arXiv 号或 DOI）与只读摘要的清单，分开数；
  • 没覆盖到的范围（在审稿件、非 arXiv、非英文、闭源模型内部无法验证等）。
