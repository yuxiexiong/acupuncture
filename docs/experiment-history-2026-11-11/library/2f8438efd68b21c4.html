NQ-01（按条目名查询 × 记录顺序）合同 r01

日期：2026-11-02。设计：计划 v2（评审撰写，54c8b3b）+ 自查 v2。授权：用户 2026-11-02「要是没有什么太大的问题就写合同写代码做测试然后上卡实验吧。如果有需要小修补的地方，你直接修补就好。」词汇与 f0 编号绑定来自 SP 面板（已见）；54 条按名提问的提示是新组合，此前无任何模型输出。

1. 面板（data/inputs-r01.json，make_inputs.py 生成）

6 场景 × 3 种轮换顺序（ABC、BCA、CAB）× 3 个被问条目，共 54 条。模板：{被问条目}的编号是什么？\n{记录前缀}：{条目1}编号为{编号1}，{条目2}编号为{编号2}，{条目3}编号为{编号3}。\n请根据上面的记录，简短回答，只需给出编号。；记录内无目标标签。条目—编号绑定在场景内固定。真实分词器审计（data/tokens-r01.json，冻结）：b = 记录行末 token；54 条的注入窗口 token 完全相同（20 个：固定指令 + 模板尾）；被问条目名全在 b 之前；无跨界 token；三个编号共同首 token、第二 token 互不相同。

2. 操作

模型/revision/分词器/BF16/内核、L0 四方向 N4146/N1210/R0/C1343、剂量 −1、形成窗口 b+1..n−2 沿用 SVQ-01。校准每场景一次（参考提示 NQxx-ABC-A），同场景 9 条与四方向共用；正式 NQ01 校准须等于预检。每输入：C 与四个 T 共用同一份无 hook 的窗口前缓存（哈希核对）；C_nat 一条；每方向 T_nat、T_V（14 个深层 G 层卷积 V 通道 4096–8191 取 C，q/k 取 T）、T_F（整个深层卷积取 C）。恢复只在起点一次；贪心、停止 {248044, 248046}、最多 32 新 token、不强制不屏蔽。每条轨迹另做同前缀诊断分叉（首步后喂共同首 token 一次前向；不进入自然交付）。全矩阵一次运行，不按结果补跑或删臂。

3. 判据（冻结，nq_core.py）

  • 每个格：Y_delivery（完整目标且无其他编号）、Y_strict、唯一输出编号（恰一个不同编号时）。
  • 场景（9 格）类别：≥8 格交付目标 → 跟随查询；≥8 格唯一输出首列编号 → 跟随首位；≥8 格唯一输出同一个编号 → 跟随固定身份；否则混合。方向标签：某类别 ≥5/6 场景，否则混合。
  • 适用性（自动判读）：C 场景合格 = 9 格 ≥8 交付；面板合格 = ≥5/6 场景。损伤迁移（按方向）= ≥4/6 场景中 C 交付且 T_nat 未交付的格 ≥6。面板不合格 → 各方向“基线不足/不可判”；方向未迁移 → “效应未迁移/不可判”；不可判不算机制阴性，全部格仍公布。
  • P_pos（推测档）：T_V 方向标签 = 跟随首位，在固定 4 个方向中 ≥3 个支持。P_target（推测档）：T_F 方向标签 = 跟随查询，≥3/4 支持。T_F 是参照，不是 T_V 的上限。
  • 同报：各臂互斥分类、唯一输出的位置频数、目标不在首位的 36 格中目标/首列计数、配对改善数（C 交付、T_nat 未交付、该臂交付）、T_F 对 T_V 逐格配对表、首步共同首 token 相对停止最大值的分差。
  • Q 只作描述：Q_ij = ((z_i − z_j)[问 i] − (z_i − z_j)[问 j]) / 2，z 为诊断分叉中各条目编号第二 token 的分数；每场景 9 个；并列报告 C、T_nat、T_V、T_F，C 是阳性参照，不是零分布；不设门槛、不进入任何判据。
