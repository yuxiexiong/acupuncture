WSP搜索策略升级v1：覆盖操作、保留分支、按证据分配预算

Material Passport

  • Origin Skill / Mode: academic-research-suite / experiment-agent plan，按项目上下文内联规划。
  • Date: 2026-11-06；Version: policy-design-v1。
  • Verification Status: 逻辑设计自查通过（同助手）；未实现、未做新数值验收、未执行。
  • 用户本次询问可如何升级搜索策略；当前Gemma v9 C继续累计30轮。本文件不修改其合同，也不授权新GPU运行或扩轮。

设计卡

  1. 主线与问题。 保留“AI依据模型失败自主选择非梯度静态权重修补，在保护约束下改善完整回答”。本次设计如何减少过早集中单一操作、单一分支，以及把缺测/路径差异误当科学阴性。不是要求每次都解释完整机制，也不是只追求训练集最高分。
  2. 增量。 将开放研究者的自由选择变成可审计、可复用的候选分配策略，保留AI的失败分析、位置选择与假设生成。成功应体现同预算更好的合格结果或更高效发现有效候选，不以模块更多/测量更细自证成功。
  3. 依据与反例。 已交付跨模型审计220976b4f：Gemma C26/30为decoder norm、仅1次embedding幅度；Qwen早期词方向混合并未对应复测；Gemma B反而有不低的增幅；细致v9目前没有稳定胜出。新增18:23控制提示保留方向可随机化而复现特定修复，不能执着于最初命名方向。30轮不是随机独立抽样，历史面板已被反复查看。
  4. 操作。 拟在独立新版本中复用现有静态绝对值补丁/内容hash/回滚、原数据/评分/保护体系；每模型重新取得本机token身份、模块映射和失败证据，不移植层号。未来选用哪个模型、任务、具体候选与可用确认数据须在新运行清单中冻结，本策略不是未填完参数却声称可执行的合同。
  5. 估计对象。 搜索政策的产出和成本：合格最佳完整开发分数、正确性损伤、发现该候选所花生成/研究者预算、修复类别覆盖。新政策与历史单次运行的差只能作描述比较；证明政策更优需另有预算匹配的前瞻比较，不能宣称当前方案已胜出。
  6. 判读。 宽覆盖有新合格收益→支持策略值得继续；只在既有norm分支有收益→广度未显示增量；组合损伤→拒绝组合，保留父候选；随机对照同样好→候选可作为开发修补保留，但撤回方向专属性；新数据不复现→不宣称泛化。数据不足不伪造机制结论。
  7. 范围与成本。 先复用现有完整评价作CPU筛选可靠性审计；本次实际新增目标模型调用0。未来以一个任务最多30个不同非零完整开发候选作可选示例，不是追加授权。每候选仍完整D，基线另计：B31×464=14384、C31×2560=79360条生成；工程、诊断、重载、失败、研究者调用及独立确认另计，不能藏在30轮里。未确定具体运行前不报虚构GPU小时。
  8. 退出。 达到新运行预算即停止；无效允许保留W0。局部无增益暂停该分支而非自动扩轮；技术失败保持原日志/partial，核边界后仅最小工程修复；最终收尾不占GPU无限等待。当前用户指定必须完成30轮的C不受新策略的“最多30”约束替换。

升级内容与优先级

第一优先：明确不同操作，给重要类别真实探索机会

为每个候选记录 failure class / parent / module / operation / direction source / support / dose / expected change / control。词向量方向混合、向量幅度缩放、视觉接口增益、内部norm、MLP/attention投影是不同操作；一种失败不能自动关闭整个大类。不要只统计“做了embedding”或“做了measure”。

先依据失败选少量适用类别，跨模型固定操作语义和规则，模型内重新发现token、层及方向。Qwen词混合成为方法设计时已见的线索，应用到Gemma仍是开发验证，不是盲迁移。不能把所有模型强行改同一层或相同绝对范数，也不能为覆盖表硬造没有失败依据的候选。

第二优先：保留几个不同分支，不让一个当前最佳支配全部预算

原系统已经保留候选、parent和评分，支持从W0或既有候选继续；不是每轮随机清零，也不是历史都丢掉。本升级是加强分配策略：常驻一个合格最优候选，另保留至多两个修复对象/操作明显不同的备选分支。原始候选不删除；候选库与部署选优分开，未过保护的分支不得成为部署结果。

备选按修复/损伤ID重叠、操作类别和完整保护反馈选择，而非只取总分相近的三个同类剂量。每分支最多连续3次完整候选没有刷新合格最优或改善受保护损伤结构，就暂时让出后续预算；这是调度启发式，不是证明分支永远无效。若所有分支无效，允许停止并保留W0，不无限换层救结果。

第三优先：阶段性分配预算，细化依据行为收益

一个待验证的30完整候选上限示例：10个用于有依据的操作覆盖，12个用于至多3条分支局部细化，4个用于互补组合/去掉组件，4个用于对照和减小补丁。不是必须凑满各格的最优比例；没有合法候选时停止或依事前预算规则重分配，不能事后改规则解释所有结果。初版先不新增复杂学习调度器。

相邻剂量只在实际BF16权重不同且对预计行为有区分度时值得测；记录真实参数变化、注入处响应和完整答案，避免围绕一个粗略分数无休止二分。每3次无增量便让出分支预算，保留后续回访可能。

组合仅从互补修复、保护可接受的少量父候选生成：始终从W0构造明确联合补丁，对重叠张量/坐标规定组合顺序与实际绝对值，不把两份含W0的参数直接相加；重新验收非零/支持/哈希并完整评价。保留A、B、A+B比较，组合不等于收益相加，更不允许按单题gold切换补丁。组合后能否安全删组件，仍需真实完整评价。

第四优先：效果搜索与机制结论分别记账

效果搜索允许合同范围内的embedding、视觉桥、norm和定向编辑竞争。内部测量用于生成可区分的候选、校准剂量、识别控制，而非要求每条路线先完成唯一机制证明才准修。最终是否部署仍由完整评价与保护决定。

如果未来采用开放动作加内部诊断，应作为单独新政策，不冒充原v9复现；原v9禁止的整张张量统一缩放/embedding等不在当前运行中偷放开。内部稀疏norm不是全部禁用。对照发现提名方向不必要时，应撤回特异性解释并调整搜索，而不抹去合法开发收益。

第五优先：小样本筛选先验收，不能现在直接套用

自适应资源分配有成熟先例，如Hyperband将有限资源分配给候选并提前停止差候选；但其论文结果不证明本静态修补任务也能获得相同加速。

本项目已有diagnose逐条与正式batch32差异。若以后做低成本筛选，必须先用现有完整候选的逐题结果，按来源组/失败类型/保护条件固定抽样，在CPU上检查被淘汰的真实合格候选比例、全量最佳保留率、损伤漏检和节省量。用同一批历史候选调筛选规则再测试属于开发拟合；须按候选家族或时序保留内部审计集，仍不能称新数据确认。

真实执行小面板还必须保持每条输入原完整评价的batch伙伴、位置、模板、图像和数值路径：以完整既有batch为执行单位并仅对选定组计分，计费包括额外伙伴。否则小面板换了padding/伙伴就无法把历史CPU筛选等同真实运行。工程尚未验收前，默认继续全量评价；小样本成绩不能直接成为最终best/freeze，也不计完整修补轮。

第六优先：升级“找分”同时升级“验分”

所有已查看的D都属于开发；现在把它重新拆一块不能变成未见确认。未来确认集需新来源组、冻结候选/协议后一次性评分，不能把确认错误反馈回同一个搜索再称独立确认。是否同时测试多个候选、是否做政策比较，都应先固定，避免择优确认。

模型选择偏差研究指出在有限样本上反复优化选择标准也可能过拟合。它支持独立评估的必要性，不给本项目具体偏差量。组级划分/区间以58或64来源组为单位，不能把重复问法当独立样本。跨模型比较须固定政策与预算，重新诊断目标模型，报告每模型结果和阴性；当前Gemma已参与开发，不能再标为完全未见家族。

反方最强质疑及修正： 1. 更宽搜必然更好？不成立。保留有效分支预算，按未改善暂退，前瞻收益未知；不以规则复杂证明优越。 2. 用Qwen成功配方引导Gemma，是不是跨模型后拟合？是开发方法线索；记录已见身份，撤回盲迁移说法，未来确认不使用已见来源。 3. 小样本淘汰错过罕见修复？先CPU评估漏淘汰/保护漏检，保留全量默认；未验收不部署筛选，不引用Hyperband加速倍数给本任务担保。 4. 候选都根据同D择优，更多搜索只是过拟合？所有分数保持开发身份，新来源确认另外冻结一次；无确认就不升级泛化结论。 5. 开放操作比v9好只是换搜索空间？明确为新政策；如以后比较“调度”须锁相同操作空间和预算，不能用开放vs受限结果单独归因调度。 6. 固定3分支/10+12+4+4比例有理论最优？没有。它是可复核的首版启发式例子，性能须另验证；当前只通过逻辑可判读性审查。

结论：作为策略升级设计通过自查；当前不具备“新实验已验收/已运行/已证明更优”的身份。没有新增入口命令，避免把讨论变成自动启动。建议实现优先顺序为操作身份账本→多分支分配→剂量/组合→CPU筛选审计；独立确认协议应在任何新搜索前预留，不等找出高分后再改规则。
