## 1. 目标、起点与总工期

总目标不变：研究者AI根据实际失败反馈，发现并修改VLM中少量权重，修复可重复的问题。本轮先在固定Qwen3-VL-4B-Instruct上确认B空间条件计数、C视觉与常识冲突是否有值得修补的稳定失败；本轮不定位内部模块或修改权重。

**以正式获准执行、且单张GPU可用的时刻为T0，目标用2个工作日完成本轮筛查与报告，日历预留第3日用于排队延迟或报告收尾。** 这是工作安排，不是已测ETA；没有设定今天开跑或自动定时任务。GPU等待不算已完成工作，GPU执行仍遵守累计12小时硬上限。故障恢复若要新增尝试，先核账并确定恢复范围，不因为有第3天就自动重跑或扩预算。

目前无需再补数据或下载模型。CPU输入与代码验收完成；真正缺的是GPU加载/生成实测和64条P0结果。CPU分析与整理预计投入4.5–7小时，属于工作量估计，不是实测；GPU耗时由P0粗估，再用正式D结果校正。

B/C在同一研究阶段推进，但**只使用一张卡串行运行**，不将“同步推进”解释成两卡并跑。顺序固定为P0 → B_D → C_D → 两任务诊断登记 → B_H → C_H → 汇总。

优先进入诊断的条件沿用原方案：D主差>0；H主差≥15pp、固定三项Holm校正p<.05、挑战错误率≥20%、控制正确率≥70%，其他B0变体主差均>0；C还要求无图通常正确率≥70%。D中模式≥8组、H中模式≥12组用于判断诊断线索强度，不替代总体差异检验。D模式不足时登记不足，不临时捏造模式；无模式也可按冻结总体终点完成H并报告线索弱。

整臂格式失败或截断>5%先判测量问题；基础设施错误/缺失不当答错或缩小分母。小缺口、非特异失败、方向不稳、证据不足均可结束本轮，不能为时间表凑“成功”。强提示修好不自动淘汰，强提示无效也不自动增加WSP可修的可信度。

D允许研究者检查全部成功/失败输出并提出新模式；在任何H输出前登记可观察的描述、计数规则与分母，不把预设类型设为白名单或把登记当机制定论。新模式按探索性复核报告，不改变主终点及Holm口径。不根据D正负选择删掉一个本来可完成的H；例外仅是测量协议、工程或资源不可行，这类停止须记录，不能算科学阴性。H结果不用于选择本轮补丁，因为本轮没有补丁；未来补丁的独立终验另留新数据。

## 4. 耗时估算与预算核对

固定总量：正式7,568＋P0 64＝7,632；另有最多256次基础设施恢复预留，尝试总上限7,888。一次调用前写attempt日志，中断在途也计入；错误答案不重试。12 GPU小时包括各次加载、失败与恢复，不是单纯生成时间，也不是云服务租赁账单。

若只为理解量级，假设所有正式请求具有相同平均耗时：

| 假设均耗时 | 7,568条正式请求 | 加20%余量（尚未含加载、P0、失败） |
|---:|---:|---:|
| 1秒/条 | 2.10小时 | 2.52小时 |
| 2秒/条 | 4.20小时 | 5.05小时 |
| 4秒/条 | 8.41小时 | 10.09小时 |
| 5秒/条 | 10.51小时 | 12.61小时，已超过总预算 |

**不能把P0简单几何图的均速当真实图吞吐保证。** 原运行器有P0均速外推门，但那只是粗估。执行安排补充以下人工核账，不增加模型请求、不修改科学样本或自动预算控制代码：

1. P0完成后，分别记录B图像32条、C图像16条、C无图16条耗时，并按正式请求权重粗估；加载/初始化另外记录。若粗估就超限，D不启动。
2. B_D完成后使用真实B请求时长更新B剩余估计；C仍只能暂用P0粗估。C_D完成后使用真实C有图/无图耗时，开H前再次核对。
3. 已用时间记为S秒，尚需加载次数为k，已观察的单阶段加载/初始化开销取最大值L；B、C无图、C有图剩余请求数为n_B、n_C0、n_Ci，相应已观察均时长为t_B、t_C0、t_Ci。人工准入估计：`S + 1.2 × (kL + n_B*t_B + n_C0*t_C0 + n_Ci*t_Ci) ≤ 43,200`。该式是带余量的估算，不是完成概率保证。
4. 两个D完成后，剩余H为B704、C无图768、C有图3,072，k=2；正式全量对应B1,168、C无图1,280、C有图5,120。每次阶段结束更新，不用算术情景代替真实receipt。
5. 预测超限时不启动下一完整阶段，报告资源不可行与剩余任务；不删保护格、不选择快题、不改变token上限、不另开run_root重置预算。即便预测可行，进程级累计硬期限仍生效。资源不足造成的未完成候选保持未决。

256次恢复是尝试额度预留，不是已分配的额外时间；恢复也必须落在同一12小时内。20%余量不是统计功效，也不为此增加样本。

B修补必须保留普通计数，不能靠统一减少数字；C必须同时保留图中判断和通常知识，不能靠统一忽略图像。冻结补丁后还需新数据、强提示和适用编辑/适配方法比较，若主张AI研究增量再比较同预算脚本搜索。
