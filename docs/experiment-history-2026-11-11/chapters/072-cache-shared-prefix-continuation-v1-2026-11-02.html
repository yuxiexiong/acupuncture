1. 设计卡与依据

本轮问：消除首字母唯一定位目标的捷径后，强制共同首token是否仍能恢复正确编号选择？同时检验完整深层卷积恢复能否迁移。 增量：FC-01的T_q0 47/48正确但所有干扰编号首字母不同；T_F 48/48严格交付、T_nat 0/48、首步禁停8/48。新面板区分“提供唯一目标线索”和“提供所有候选共有的起点”；不判断记忆是否完整或信息是否删除。 已核FC报告、合同、正式verification；前计划6486eff。基础事实按canonical工作区基础审计：生成反馈使文本和状态共同变化，短卷积有限宽不等于模型影响有限长。旧logits不能提供新面板自由续写，故需要新测量；先做CPU文本/分词审计。 估计对象：各操作对配对完整交付的总效果；共同前缀仍提示答案格式，不是无信息干预。正面结果只支持该提示条件下的内容选择；反面结果保留未交付/选错/预算不足等区别。

SP-01（共享首 token 面板上的条件续答与卷积恢复）结果报告

日期：2026-11-02。合同 r01；决策 D1–D5；计划 v1（评审撰写）。代码 1341c93，freeze-r01 20136829…70cd。新面板，此前无任何模型输出（SP01 在预检中先被看到）。同一助手实现、运行与撰写。

1. 结论（不利的先说）
  1. P_A2 不成立（0/4 方向）：去掉首字母捷径后，强制正确的共享首字母不再能恢复正确编号。 T_shared 每个方向只有 4–5/12 正确交付，其余 7–8/12 输出的是干扰编号（同字母、不同数字）。FC-01 中 T_q0 的 47/48 不能迁移到去掉该捷径的面板，原解释必须降级；两轮换了面板，首字母唯一性本身的因果贡献没有单独估计，所以不说“完全由捷径造成”。“干预只改变了回答起点、后续内容完整”这个解释在这里不成立：给定所有候选共有的起点后，干预状态下的模型选不出目标条目。
  2. 合同外的描述性发现（事后核对，未预注册）：T_shared 在 47/48 个单元输出的都是记录里列在第一位的编号，与目标在哪个位置无关；它那 4–5 个“正确”恰好是目标列在第一位的情景（SP01、SP04；C1343 多 1 个）。对比之下，T_F 的输出按目标的实际位置分布（首/中/末 = 4/4/4，R0 为 6/4/2）。也就是说，干预之后，模型在被迫开始写编号时退回到“记录里的第一个编号”，而不是读出目标条目对应的编号。
  3. P_A1 成立（3/4 方向）：只恢复深层卷积，在新面板上也恢复完整交付。 N4146、N1210、C1343 都是 12/12 正确且严格只给编号；R0 为 10/12（2 例输出了列在第一位的干扰编号），判为未支持（4/6 情景）。
  4. 先决条件都满足：干净基线 12/12 正确且严格；C 的首 token 在 12/12 个输入上等于共享首字母（C_shared 与 C_nat 逐位相同）；干预损伤在四个方向都是 6/6 情景（T_nat 全部未交付）。所以新面板上原干预效应稳定迁移，P_A2 的失败不是“面板不可用”。
  5. 第二步数字优势 M（C 首 token 等于共享首字母，12/12 都可算）：干净运行中目标第二位数字领先干扰 2.5–11.1 logit；T_shared 中，目标列在第一位的情景仍为正（约 +2 到 +3），其余情景为负（约 −0.1 到 −2.6，C1343 有 1 例为 +1.9）。这与第 2 条一致：强制首字母后，第二位数字的竞争偏向第一位编号。

4. 按计划 §4 的解读
  • “T_shared 失败而 F 恢复”：状态恢复提供了单个共同起点 token 没有提供的条件。在这组输入上，干预损伤不只在回答起点，也在“读出目标条目对应的编号”这一步；恢复深层卷积历史后两者都恢复。
  • 修正上一轮的叙述：FC-01 中“给定正确首字母就能接出正确编号”不能迁移到首字母不唯一的面板（是否“依赖”首字母唯一性未单独估计）；去掉这一捷径后，干预状态下模型系统性地退回到第一个编号（合同外描述）。不能再说“后续内容完整、只有开头受损”。
  • 也不能反过来说“目标信息被删除”：模型可能仍能在别的提示下读出目标，只是在强制开头、32 token 内的这个条件下没有读出。
