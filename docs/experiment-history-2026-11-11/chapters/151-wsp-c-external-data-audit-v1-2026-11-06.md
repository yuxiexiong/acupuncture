#### 外部数据容量核查自查

日期 2026-11-06；依据 `docs/experiment-design-self-check.zh-CN.md` v1。使用 academic-research-suite 的实验验证思路与 Ponytail full 的最小脚本原则。本助手自查和读图，不是独立审查，也不是两名人工审核。

设计卡：主线仍是第一轮 C 冻结补丁在新来源、新问法下是否有效且有比较优势；本轮只回答两个指定公开数据能提供多少合格候选、哪些任务匹配。新增认识是实际来源复用、可用数量、接口与金标准问题。固定公开 revision，读取已有 WSP 曝光证据；无权重操作、供体、hook、模型反馈或测试输出选样。估计对象是保守候选容量，不是补丁效应。到来源清单、审计和交付完成即停止，不触发模型运行。

最强反方检查及修正：

1. **名字不同可能只是旧图改名。** 初始名称匹配仅覆盖366行；改为全旧库pHash候选加RGB误差，553个大小行全追回旧图。旧初稿保留，最终账本覆盖它。
2. **两库相加能凑更多。** 明确追溯VLind context及重生成编号；合并后扣28，大小扣8。没有用图像变体扩样本量。
3. **近图误报会冤枉大量天平题。** 不把相似性宣布为真实重复；本版保守合分量，报告它低估扩展容量，未据此断言理论最大值。大小112不受影响。
4. **只审一个代表不能证明其他变体都坏。** 同意。改称固定代表面板容量，列“未审变体”，不把其余行自动标坏。ROME189张穷尽审查单列。138上限独立于这项保守性。
5. **质量规则主观且有普通例外。** 记录逐题理由、典型物体/图示天平前提及唯一助手身份；没有伪造独立金标准。故正式双审门仍未通过，候选不是终验已验收。
6. **方法可在公开train训练，验证会有泄漏。** 67个通过的train代表单列；未来任何方法是否见过这些来源仍要核对其训练/拟合范围。本次关键词零命中只覆盖可见WSP记录。
7. **假定统计独立后算功效会夸大。** 表格只是条件SD情景；来源组、共享模板、生成器风格及未知预训练均不等于独立。保留“范围不足/区间太宽”结论。
8. **有新反事实图就可以照跑原五条件。** 不成立。WhatIf正常配对图未提供核验，VLind正常图尚未语义审核；明确只能准备Jcf，完整协议未就绪。
9. **数据审核看过题，是否还算未曝光？** 明记审计员看图/标签。它不是目标模型推理曝光；此后不得将面板用于补丁/提示选择再回称确认集。

统计谬误检查：不以汇总替代题型分层；不以行数替代来源数；承认质量选择与代表选择限制外推；不按模型失败/收益选样本；不假设新失败率；不将开发集12.5pp当真实新收益；保留全部排除/未审；敏感性保留五比较校正；明确保守合并不是唯一正确分组；没有相关到因果或反向因果推断。

工程记录：初次哈希脚本使用当前Python不支持的 `int.bit_count` 而停止，已改标准 `bin(...).count('1')` 并成功重跑；没有因此删除任何图片或运行模型。摘要断言核对3125/421/302、全部索引、旧曝光160一致、无读错/变动、553旧图对应、面板无旧图候选及无重复像素。公开包包含哈希、固定来源与脚本，CPU重放验收另见 `validation.json`。

最终判定：**数据审计逻辑通过，CPU核验完成；独立语义认证、完整验证协议工程验收与模型执行均未完成/未授权。** 这不是一份新的可直接执行实验合同。

公开交付：自动审批将初始文件名匹配清单判定为含内部逐路径信息并拒绝发布。该初稿留本地，公开包移除它及其清单引用，保留最终公共上游图像身份、公开 C ID 和曝光汇总；不要求用户追加授权。

发布边界补充：自动审批进一步拒绝旧图逐项对应/曝光分类清单。完整 image-dedup 与 old-pixel-mapping 仅留本地；公开 public-dedup 删除 cross_old 明细，public-overlap-summary 仅有聚合计数。公开重放可以复算新面板并核对汇总，不能冒充逐项重验旧曝光映射。

#### WhatIfVis 与 VLind-Bench：第一轮 C 的新来源容量核查

2026-11-06。**已完成只读曝光核查、CPU 图像查重和单助手图文审核；未运行任何实验模型。** 本文是容量审计，不是补丁效果报告，也不修改原 T200 执行合同。

##### 结论

比原有 24 组有明显改善，但仍凑不出 200 组同任务的新来源。保守筛选后的验证候选面板为：

| 数据 | 保守来源组 | 其中大小任务 | 仅作其他任务扩展 |
|---|---:|---:|---:|
| WhatIfVis，排除官方 train | 447 | 98 | 349 |
| VLind-Bench | 162 | 22 | 140 |
| 两套合并、扣掉 28 个共同来源组 | **581** | **112** | **469** |

这里的“候选”指通过本轮单助手质量审核、来源与保守近重复规则的固定代表面板，**不是双人认证金标准，也不是已证明统计独立的样本数**。除 ROME 大小子集穷尽审核外，其他来源每组只审一个确定性代表；失败组的其他变体没有逐一尝试救回，故这是可复查的保守容量，不是全部可能可用量的精确最大值。

大小任务的 112 组是 **90 个 ROME 对象对＋22 个 VLind 场景**。WhatIfVis 的 98 组已经包含其中 8 个 VLind 场景，不能再把 98＋22＝120 当作新来源数。即使撤销我们所有大小题质量排除，在作者质量门槛内也只有 **109 个 ROME 对象对＋29 个 VLind 大小场景＝138 组**；因此“不到 200”并非单助手筛选太严才出现。

##### 哪些能检验 C，哪些属于扩展

1. **最接近第一轮 C：WhatIfVis 的 90 个 ROME 大小对象对。** 它们直接提供图中大小与日常大小冲突，可构造同一图的 visual/usual 两类问题，检验原主指标 Jcf 和新问法迁移。这是任务匹配，不是已经可以把原程序直接接上。
2. **近任务补充：22 个 VLind 大小场景。** 包括 bigger、taller、wider、longer，原始接口主要是判断陈述真伪。需要统一比较维度和问法；不可把长度/宽度问题未经说明都改叫“大小”。WhatIfVis 已有的 8 个合格改写不增加来源数。
3. **其他 469 组只能作为扩展。** 涉及计数、颜色、场景/历史、食性、重量等，能考察修补是否迁移到更广的视觉—常识冲突；不能补足大小任务的 T200，不能与大小题混成一个支持原 C 的总成功率。

**完整五条件终验目前仍未就绪。** WhatIfVis 的 ROME 子集仅提供此次核查的反事实图，没有核验配对的正常图；它支持 Jcf 数据准备，不足以直接验证原图无损伤、J4 或 J5。VLind 的 302 张正常图已下载并校验文件身份，但本轮语义审核只覆盖 302 张作者 best 反事实图，不能声称正常图配对审核通过。原计划的独立双审、模板/解析器验收、提示与已有方法的公平适配仍是未完成事项。

##### 固定来源与真实容量

###### WhatIfVis

采用作者公开仓库 [jaagli/WhatIfVis](https://huggingface.co/datasets/jaagli/WhatIfVis/tree/2cd5ec5eda49f033d0c36a0930d9f8ddeabec4d6)，revision `2cd5ec5eda49f033d0c36a0930d9f8ddeabec4d6`，CC BY-NC 4.0。该快照 11 个 JSONL 共 **3125 行、3118 个图片路径**。作者 [代码仓库](https://github.com/jiaangli/visual-context-sensitivity) 的链接关系已核对；不把论文旧版本中的 3049 与此快照混用。

| 图片来源目录 | 行数 | 本轮处理 |
|---|---:|---|
| visual_counterfact | 816 | 553 个大小行确认回到旧 C；263 个颜色行按旧语料谱系保守隔离，未称它们全部已曝光 |
| rome_size | 189 | 109 个对象对，全部逐图审查；161 张通过，覆盖 90 对 |
| vlind | 443 | 按原始 context ID 并组，与 VLind-Bench 联合去重 |
| generated | 900 | 850 个 VLind 场景变体并回基础 context；50 个重量例按对象对计 |
| vilp | 338 | 181 个基础 ID；重复现象另做保守并组 |
| vlms_are_biased | 189 | 按实体/品牌族并组，而非把每张图视为新来源 |
| weight_z_image_turbo | 250 | 按对象对并组，并审核物体、数量和天平图示 |

非旧语料、非 ROME 部分共选取 **786 个固定代表**，全部由本助手看图及核对问题/两种标签。291 个代表因歧义、不成立的常识冲突或图文不符排除；495 个通过中，67 个代表来自官方 train，单列为开发/扩展库存，不进入上表验证面板。余下 428 个代表加 ROME 90 对，在别名、重复现象和保守近图合并前为 518 组，合并后为 **447 组**。

447 组按题型为：大小 98、计数 114、颜色 3、空间/时间类 67、重量 165。公开 train 并非我们的目标模型已见证据；单列它是为了不把官方训练材料混作建议验证集，也防止未来与在该 train 上训练的方法比较时发生不公平。

###### VLind-Bench

采用作者 [klee972/VLind-Bench](https://huggingface.co/datasets/klee972/VLind-Bench/tree/0aa47d9387f4c9a554d56067dd51900315954c81)，revision `0aa47d9387f4c9a554d56067dd51900315954c81`，CC BY-SA 4.0。原 JSON 有 **421 个 context**，不是 421 个已通过作者审核的来源；其中 **302 个**至少有一张图获得 ≥2 个 good votes。分别下载作者 best 图与正常图，共 604 张。

审核了这 302 个 context 的 best 反事实图及其陈述，保留 162，隔离 140。保留分布为：大小 22、重量 19、颜色 3、气候 10、食性 30、栖息地 29、历史 6、地标 16、地点 2、时代 25。未纳入的 119 个原始 context 沿用作者质量门槛，未重新挑图救回。

[作者论文](https://aclanthology.org/2025.findings-naacl.231/)和[代码](https://github.com/klee972/VLind-Bench)还包含知识、视觉感知、常识偏向、逻辑等分步检查。本轮不是官方完整评测的复现；这些 162 组也不是“已经通过目标模型知识/视觉前测”的数量。未来方法比较应使用共同冻结分母，不能让每个方法各自通过不同前测后只比其条件正确率。

##### 曝光与图片去重的证据

本节图像身份、哈希与来源清单仅指作者公开发布的数据，不包含任何内部实验记录文件的逐路径信息或哈希。内部曝光核查只发布公开 C ID 与汇总计数。

- 用户已授权只读扫描指定服务器上的既有 WSP 记录。远端扫描 9541 个文件、6,714,329,841 解码字节；本地扫描 8683 个文件、5,041,460,424 字节。两边均恢复 **160 个旧 C ID**，数据集名称/路径关键词命中均 0，读取错误及读取中变化文件均 0。
- 扫描限定于既有 WSP 实验证据；排除模型缓存、原始数据和对话材料。完整内部范围仅留本地，公开包不含内部逐路径信息。结果仅说明这份可见记录未发现使用痕迹，**不证明未知调用、重命名副本或预训练中完全没有这些图**。本助手此次看图属于审计曝光，不是目标模型试跑；本面板不得随后拿来调补丁再称留出。
- 比较 **1454 张旧 C 图片与 3722 张新下载图片**：新图片由 WhatIfVis 3118 张与 VLind 604 张组成。保存字节 SHA256、RGB 像素 SHA256 与 64-bit pHash；跨旧库逐对比较 5,411,788 次。
- WhatIfVis 大小子集的 **553 行／547 张唯一图全部找到旧 C 对应图**。最小 pHash 距离为 0/2/4；归一尺寸后的 RGB 平均绝对差最大 4.030/255，足以核对这是旧图的重编码版本，而不是 553 个新来源。按旧账本映射，136 行回到已曝光组、300 行共享曝光素材，其余 117 行也是旧语料库存。此前仅靠文件名漏掉的 187 行，现由图片对应关系补齐。旧文件名匹配初稿仅留本地，不发布其逐项路径清单；最终逐图对应表同样留本地；公开结果以 `public-overlap-summary.json` 汇总为准。
- 其余新来源未命中旧库的 pHash≤6 候选。整图查重不能证明所有局部素材均不同；我们还按公开 context/对象对/实体族合并，且没有把共享对象名字等同于重复图片。ROME 通过对象对与全部 727 行旧 C 对象标签对无精确匹配；VLind 大小对象对另见清单。
- 新库全量检出 1455 对 pHash≤6 的候选，大量是同来源及同天平构图。验证候选之间的 **82 条跨基础组近图边**采取保守连通分量合并，每分量留一个固定代表。此举可能过度合并，**不是宣称 82 对都已证实为重复图**。它不影响 98/22/112 的大小容量，只使扩展数量更保守。

两数据集共有的 28 个保留来源已经在合并数中扣除。并组、选代表和质量决定均不读取新模型输出。

##### 质量判定与边界

排除理由保存在逐题账本，主要是：图中物体/数量与题目不同；常识答案缺少唯一、稳定的普通解释；视觉与常识答案不互斥；静态图片无法证明功能、历史事件或精确地理位置；问“哪个物体”却以无指代的 bigger/longer 作为答案；计数或透视不清。

例如 VLind context 113 的视觉陈述与常识陈述谈论不同主体；部分 ViLP 题把“毛毛虫变成蛾”与“变成蝴蝶”当作唯一冲突；重量图会把一粒玉米画成整根玉米，或把一片薯片画成多片。它们不是适合直接裁决补丁输赢的金标准。排除只针对本轮严格验证用途，不是宣布整个原基准无效。

保留的重量题也仅适用于**按图示天平/跷跷板编码读轻重**的扩展，不能由一张失衡、未知力臂的生成图推出现实质量。图中袋子/容器名称按题目提供的身份解释；不得包装成开放物体识别或物理质量估计。所有单助手边界项仍可被独立复核否决。

##### 这轮容量足以验证到什么程度

核心大小来源从 24 提高到约百组，有价值，适合准备一轮范围明确的外部验证；仍不支持直接把原 T200 标记完成，更不支持据此认定方法已经足够发论文。

作为量级参考，在**假设来源独立、配对差值 SD=0.35、五项比较校正、近似 80% 功效**时，可检出差异约为：24 组 26.1pp；98 组 12.3pp；112 组 11.5pp；200 组 8.5pp。这是未观测方差下的规划情景，不是本补丁的真实功效或收益预测。更小优势、模板相关性、共享生成风格都可能使比较不确定；不显著不能写成与提示或已有方法等效。

因此本轮交付的判断是：**百组左右的大小验证有实际价值；扩展来源充足；完整五条件和比较方法尚待验收；当前不跑模型。** 不自动增加第三轮修补、不用扩展题凑 200、不把 581 当成 581 个独立大小样本。
