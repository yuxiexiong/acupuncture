#### 跨通道计划的旧数据核对：执行前自查

2026-10-31；仅 Python 标准库读取本地旧 JSON，不加载模型/张量，不联网执行服务器程序，不运行 GPU。用户授权核对已有多针多剂量数据并编写下一轮计划。

设计卡：主线是针如何改变写入/缓存/读取；本审计为跨通道选择提供真实覆盖，避免把十通道单剂量当十通道多剂量。对象为 4B、L0、旧十点调查和正负剂量调查正式记录、共享基线、采样/选择清单、协议与收据。核对文件哈希、唯一条件、剂量、题目覆盖、首 token EOS、空正文、128-token 截断、与基线 token 完全相同数。后四者是机械读数，不作能力或语义判断。输出 JSON 和原始回答摘录、来源 manifest。全部十通道保留，不依这些结果筛掉弱通道。只扫描既定来源，缺失/哈希失败停止汇总，不自动补跑。当前查看过少量记录结构，非盲分析；正式全表汇总尚未执行。

#### L0 跨通道计划的旧数据核对

2026-10-31；先完成 SELF_CHECK.zh-CN.md，再用 audit.py 标准库读取旧 JSON。无模型加载、前向、GPU、新生成。result.json 保存逐条来源、SHA256、token 与回答，原始数据未改。

##### 1. 已核验到什么

三个历史正式调查的 4B/L0 记录：十通道 +1 的80条，N4146 四个新增正档32条、五个负档40条，共152条修改记录，加共享原版8条。全部记录字节 SHA256 与所属正式 worker 收据一致；19个通道—剂量格，每格八题且题目/token输入身份对应。六份正式收据均为completed/checks_passed。没有据旧合同里的“尚未运行”否认后续收据；也没有把已保存 token 的机械分析叫独立模型复现。

范围不等于全项目：本轮逐记录核验只覆盖上面三来源的 L0/4B；其他层/模型未重审。早层输入控制和缓存定位的后续证据另按归档报告/汇总核对，不声称逐条重验全部11,890或6,576条。

##### 4. 后续多通道证据，按归档来源核对

固定读取 Git `dbb2f984400c865210b7430dfd91bd5a35e1235c` 的 early-input-control 报告和 early-state-localization 报告/confirmation-r01.json。精简汇总保存在 earlier-cache-summary.json。

- 输入控制固定面板包含L0/N1210与N4146，开发六档±0.25/±0.5/±1，确认±0.5/±1；报告记录完成。不是其他九个L0通道的完整网格。
- 后续全前缀缓存定位确认面板（24输入）：N1210−1的A0首步EOS为14/24，N4146−1为24/24；只洗递推或只洗卷积后两者均0/24。N1210+1的A0为6/24，N4146+1为24/24。这是另外一种时窗和全层缓存操作的归档结果，不能冒充同输入晚段、深层V形成检验。
- 所以已有“停止并非唯一通道现象”和“至少另一个通道有缓存干预证据”，缺的是**同一当前机制协议下的跨通道比较**。
- 尚未逐条重新哈希该后续实验的原始模型记录；这里明确为归档汇总核对，不抬升成此次独立复现。

##### 5. 对新计划的约束

保留原十通道全名单，不按79/80结果再选强者，不额外补抽“好看”的通道。主比较固定当前−1，+1仅作符号桥接，−0.5作固定弱剂量敏感性；不把某通道调到停止再说机制一致。全部通道都报告，包括只有其他输出变化或读数不足者。先检验相同V形成—深层输出关系能否跨通道成立，暂不把缓存八组合复制十遍。

本报告完成的是旧数据审计，不是下一轮跨通道实验结果。具体计划与完整自查见 docs/cache-cross-channel-validation-plan-v1-2026-10-31.zh-CN.md。
