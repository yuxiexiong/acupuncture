候选布局 token 位置（CPU 审计，真实分词器）

2026-11-02。只切 token，不运行模型。脚本 layout_audit.py，逐条结果 layout-audit-r01.json。文本来自 NQ-01 的 54 个“场景×顺序×查询”格，各有按名、标签两种规格。

布局
  • L0 问题 → 记录 → 指令（NQ/NB 式，参照）
  • L1 记录 → 问题 → 指令（QC/QCD 的 NA、LA）
  • L2 记录 → 指令 → 问题；指令改写为“请根据上面的记录，简短回答下面的问题，只需给出编号。”（多 2 个 token）
  • L2s 记录 → 指令 → 问题；指令与 L0/L1 逐字相同（只挪动问题）

候选窗口（都在读出位 n−1 之前结束）：B = 记录后到 n−2；E20 = 记录后前 20 个；N20 = 读出前最后 20 个；Q = 恰好问题本身的 token。

事实
  1. 四种布局、两种规格下没有任何跨段 token；同一输入的问题 token 在各布局中逐位相同（108/108）。问题长 6 个 token（标签全部；按名 33 条），按名另 21 条为 5 个。
  2. L1 与 L2s 的提示长度 n 完全相同（只是重排）；L2 因改写指令多 2 个 token。
  3. L0 的问题在记录之前、位于预填段内（Q 窗口不在形成窗口里），现有形成期注入不能只打在 L0 的问题上。
  4. L2 的 E20 只覆盖问题的 5/6 个 token，把问题切开，不宜作候选。
由此可构造的配对（各自的残余差别）
配对 相同 不同 残余混淆
Q 窗口：L1 vs L2s（同内容、不同时刻） 问题 token 逐位相同、长度 5/6、剂量可同 窗口末端到读出 22 对 9 个 token；窗口后未注入更新 21 对 8 步 问题之前的上下文不同（L1 紧跟记录；L2s 跟在指令后）；问题与指令的先后不同；之后处理的内容不同
N20：L1 vs L2s（同时刻、不同内容） 长度 20、都在读出前 1 位结束、之后 0 步未注入；模板尾 8 个 token 相同 L1 覆盖整条指令 12 个；L2s 覆盖指令末 5–6 个 + 换行 + 问题 5–6 个 两个布局本身不同（问题位置），C 基线需分别检验；被替换掉的是指令前半段，不是“空白”
E20 / B：L1 vs L2s（同组成、不同顺序） 覆盖的段与 token 数相同（问题 6 + 换行 + 指令 12 + 模板尾 1；B 再加 7 个模板尾） 段内顺序：L1 问题在前，L2s 指令在前 同上；E20 结束后仍有 7 步未注入更新（两布局相同）

这些只是 token 层面的可比性；问题位置改变本身会改变模型此前见过什么、问题与记录的关系和任务难度，任何配对都不是只改了“覆盖内容”或只改了“时刻”。L2s 的指令出现在问题之前，干净基线是否成立必须实测（LB 曾因模板变化没过基线）。
