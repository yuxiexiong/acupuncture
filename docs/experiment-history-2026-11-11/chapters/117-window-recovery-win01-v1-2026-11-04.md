##### 1. 问题

项目级问题：

> **为什么"开头/交付层面的恢复"和"正确答案的恢复"会分开？这种分开随干扰位置、任务和缓存背景怎样变化？**

本卡的直接目标是**识别一条能跨条件检验的依赖关系**，不以把 R1 的 L0 分歧解释圆为成功标准。

- **W 块（关系 A 的条件）**：同一任务、同一针，只改形成窗口，看恢复关系是否随之改变。
- **B 块（关系 B 的延伸）**：事实任务上，跨版本移植干净状态能否把答案带成供体的事实。

两块共用工程，各自判定成败和后续价值。D（写入/读取）不在本卡。

##### 2. 依据

- **推导**：NCC 系列先对 0..b 做一次无针前向，所以记录句及之前位置的 KV 在每一层都与干净运行逐位相同。阶段二在 0..n−2 全部加针。
- **推测**：编号任务上恢复 S 有效，可能依赖"记录句之前的历史原本没受干扰"这一条件。
- **类比**：QC-01、QCD-01 在编号任务上表明，窗口覆盖什么比总剂量更重要。
- **限制**：改窗口同时改变施针位置、位置数，以及后续形成的 S、卷积和 KV。所以窗口效应本身不指定由哪个缓存承载。

##### 3. W 块：窗口下的恢复

**输入**
- 事实：阶段二开发 24 条＋历史 24 条（都已接触过）。
- 编号：LVK 新面板 48 条（已见）。
- 两任务都是"记录句＋问题＋指令"。b 统一取记录句最后一个 token：编号沿用 `c1p_core` 的 `boundary_text`；事实取"\n问题："之前的部分。冻结前用真实分词器逐条导出事实的 b。

**针**
- L0/N4146/−1：R1 分歧所在。
- L1/N2765/−1：**按已见差异选的对照**（事实上只恢复 KV 就修好，与 L0 相反），不代表跨深度推广。
- 两针都来自阶段二固定 32 点面板。剂量沿用各自家族的校准：事实用本题 f0 版，编号用 NQ-01，以保住逐位桥接。每位置写入范数实测相近（差 <10%），每条记录都写入实际值。跨任务比较时，校准文本不同保留为限制。

**形成窗口**

| 窗口 | 加针位置 | 编号上的位置数 | 用途 |
|---|---|---|---|
| W_all | 0..n−2 | 55–59 | 阶段二方式 |
| W_post | b+1..n−2 | 26–27 | NCC 方式 |
| W_pre | 0..b（**模板＋记录句**） | 29–32 | 只干预记录句之前的历史；位置数与 W_post 接近，可部分缓解位置数混淆 |

事实上各窗口的位置数等 b 导出后补上。若 W_pre 与 W_post 的位置数相差很大，就在报告里作为混淆写明。

**臂**（以 T 为背景，在切点 τ 一次性替换）

| 臂 | 替换 | 卷积 | 对照来源 |
|---|---|---|---|
| T | 无 | T | 原生 |
| R_all | 全部线性层递推 | T | 阶段二 TCT |
| S_deep | G 层递推 S | T | NCC TS |
| KV_all | 全部 KV 层 | T | 阶段二 CTT |
| R+KV_all | 递推＋全部 KV | T | 阶段二 CCT |
| **R_all＋KV_pre** | 递推＋**只换 0..b 位置**的 KV（全部 KV 层），b+1 之后的 KV 保持 T | T | 新增：同一窗口内的缓存归属 |
| C | 干净运行（每输入一条） | — | — |

R_all＋KV_pre 只在 W_all 下做（W_post 下 0..b 的 KV 本来就等于 C）。读法：
- 它能救回答案、而 R_all 不能：在这个混合背景里，直接支持"记录句之前位置的 KV 历史"参与答案恢复；
- 它救不回来、而 R+KV_all 能：KV 的作用不限于记录句之前的位置；
- S 是累积状态，不能按位置切，所以这一臂只回答 KV 一侧。

**桥接与结构闸门**（任一失败即停）
- 事实 W_all 下的 T、R_all、KV_all、R+KV_all，t1 logits 与生成 token 逐位等于阶段二已有记录。
- 编号 W_post 下的 T、S_deep，逐位等于 NCC 的 T、TS。
- W_post 下 0..b 位置的 KV 在所有层等于 C；所有窗口下第 0..L 层缓存等于 C。
- R_all＋KV_pre 只改 0..b 位置的 KV，其余张量逐位等于背景。

**读数**
- 首步：是否停止，首 token 分类。
- 自然完整回答：
  - 统一生成 128 个 token；
  - 编号用 `y_full`，另报前 32 个 token 处的判读，以桥接 NCC；
  - 事实用预写规则自动判读，加抽样盲读核对（冻结前在阶段二已有标签上演示一致率）；另报两选一候选分数作辅助。
- 逐格报告：救回数、改坏数（相对 T）、停止数、异常类型。不合并成单一比例。
- 逐输入配对；场景分层 bootstrap（2000 次，种子 20261103）只给描述性区间。零点用 C 和同格 T 标定，不用"大于 0"作判据。

##### 4. B 块：事实任务上的跨版本移植

- 每个情景的 f0/f1 两版事实互换、正确项互换，正好互为供体。
- **位置对齐要先核对**：24 对里 22 对提示 token 总数相同，但这只说明张量形状兼容。冻结前用分词器逐位比对，只有"仅在事实词位置不同"的对才进入位置相关的移植（KV、全部缓存）；其余对只做与长度无关的递推移植。
- 接收者为一版的干净运行，在 τ 换入另一版的干净状态，两个方向都做：
  - Bx_R：全部递推；
  - Bx_S：深层 S，对应编号的 CSx；
  - Bx_KV：全部 KV，只用于位置对齐的对；
  - Bx_all：全部缓存，只用于位置对齐的对，作参照。
- 读数：回答变成供体事实、仍是接收者事实，或其他。编号任务的 CSx（38/48 改坏，32 条变成供体答案）是已有参照，不重跑。

| B 块观察 | 能说 | 不能说 |
|---|---|---|
| Bx_S 或 Bx_R 让多数回答变成供体事实 | 在这套操作下，递推状态的移植把答案选择带到了事实任务，关系 B 有了非编号证据 | 答案只存在递推状态里 |
| 只有 Bx_KV 或 Bx_all 带得走 | 在这套操作下，KV 移植实现了转移，递推移植没有 | 答案主要存在 KV 里 |
| 都带不走 | 这套移植操作没有实现转移 | 关系 B 不适用于事实任务 |

**B 块成功标准**：在位置对齐和失配限制写清的前提下，得到可判读的转移或不转移结果。

##### 5. 预留条件（冻结时写死，看到 W 块结果后不再挑）

用于检验 W 块得到的依赖关系能否预测**尚未检验的条件**：

- **未测的针**：阶段二固定面板上的 L2/C5251/−1、L3/C7666/−1、L5/C2467/−1，在两个任务上都没做过窗口比较。它们在阶段二全前缀下的损伤结果已经看过，但窗口比较的结果没有看过。
- **同幅随机方向**：L0 上一个与 N4146 每位置写入范数相同的随机方向，构造沿用 EH-XC，冻结时抄录。Proposal v3 要求把随机方向当作主动比较对象。
- 这些条件**不在本卡运行**。W 块出结果后，先按得到的依赖关系对它们逐格写出方向预测（哪种窗口下哪些臂能救回答案），冻结后再另卡运行。

##### 6. 开跑前写死：每种结果导向哪里

**W 块成功标准**：识别出一条能对预留条件提出预测的依赖关系，例如"恢复递推能否救回答案，取决于干预窗口是否覆盖记录句之前的部分"。

| W 块主要观察 | 能说 | 下一步 |
|---|---|---|
| 同一任务内，W_post 下 R_all（或 S_deep）的答案恢复明显好于 W_all 或 W_pre | 窗口改变了恢复关系；依赖"记录句之前的历史是否受干预"（不指定缓存） | 对预留条件写预测并冻结；R_all＋KV_pre 的结果决定是否把 KV 归属列为候选环节 |
| 加上 R_all＋KV_pre 能救回、R_all 不能 | 在全前缀混合背景里，记录句之前位置的 KV 历史参与答案恢复 | 同上，KV_pre 列为候选计算环节，但要等预测兑现后才深入 |
| 两种窗口下差异都不大，任务间差异仍在 | 窗口解释不了 R1 分歧 | 保留为任务条件分支；转向 B 块与任务结构比较，不归因于单一缓存 |
| 结果随窗口、任务、深度混合变化 | 存在交互，暂无单一依赖关系 | 只按格报告，先讨论；不自动加格、加针 |
| L0 与 L1 在窗口下的响应不同 | 深度是条件之一 | **不直接选 L1 深入**；把"深度如何改变依赖关系"写成对 L2/L3/L5 的预测，先兑现 |

**通用规则**：
- 预测兑现后，才选计算环节深入；没兑现，就把这条关系记为条件分支。
- 无损伤、不适用、没拿到结果、合同执行失败分开记录。
- 结果弱或不可判时，不加针、不改剂量、不换题。

##### 7. 规模与成本（粗估，以预检实测为准）

- W 块：每输入 2 针 × 3 窗口 × 5 臂，加 W_all 下的 R_all＋KV_pre 2 条，再加 C，共 33 条轨迹。两任务 96 输入，约 3,170 条，生成上限 128。事实 W_all 中约 384 条可与阶段二逐位桥接复用，但仍要重跑核对。
- B 块：48 输入 × 最多 4 格 × 2 个方向，约 380 条。
- 参照 NCC 实测（32 token 下每条约 2 设备秒），估计 2–5 GPUh，双卡；预检后给出上限。

##### 8. 冻结前的零 GPU 准备

1. 用真实分词器导出事实的 b，以及各窗口的位置数。
2. f0/f1 逐位比对，确定位置对齐的对。
3. 事实自动判读规则在阶段二已有标签上的一致率演示（6.2：要演示能判对，也要演示能判出错）。
4. 照抄随机方向的构造和预留条件清单，写入合同。

完成后按惯例推进：合同和代码 → CPU 测试与冒烟 → 冻结 → 预检。预检通过后汇报，不直接开正式运行。

#### WIN-01 合同 r01：形成窗口与恢复关系、事实任务跨版本移植

2026-11-04。依据：[设计稿 v2](https://github.com/yuxiexiong/acupuncture/blob/7d6bdf84ab74062ac9ab55bc8201b5a6586b92c8/docs/cache-mechanism-r2-first-experiment-plan-v1-2026-11-04.zh-CN.md)、[冻结前准备](https://github.com/yuxiexiong/acupuncture/blob/7d6bdf84ab74062ac9ab55bc8201b5a6586b92c8/experiments/window-recovery-win01-v1-2026-11-04/prep/PREP.zh-CN.md)、[协议差异清单](https://github.com/yuxiexiong/acupuncture/blob/7d6bdf84ab74062ac9ab55bc8201b5a6586b92c8/experiments/cache-mechanism-alignment-r1-v1-2026-11-04/PROTOCOL_DIFFS.zh-CN.md)。用户授权（2026-11-04）："同意，推进吧，直接跑完实验后再汇报"。探索性，两面板都已接触过，作者执行，未经独立评审。档位：**推导**＝有论证链；**类比**＝相邻证据；**推测**＝待验证。

##### 0. 要回答什么

- **W 块（关系 A 的条件）**：同一任务、同一针，只改形成窗口，恢复臂相对 T 的效果是否随之改变。只回答"窗口是否改变恢复关系"，不区分"干预了哪段内容"还是"干预了多少位置"。缓存层面的解释只来自同窗口内的 R_all＋KV_pre 比较。
- **B 块（关系 B 的延伸）**：事实任务上，在 τ 换入另一事实版本的干净状态，这套移植操作是否把回答带成供体的事实。
- 两块共用工程，分别判定。D（写入/读取）不在本卡。

##### 1. 固定条件

- 模型、引擎、聊天模板（`enable_thinking=False`）、停止集合、贪心解码：与阶段二、NCC 相同（共用 `early-input-control` 的 ControlEngine 与 `early-state-localization-v1` 的 `localize.py`）。不使用 fla/causal-conv1d 等非 torch 内核。
- 切点 τ：处理最后一个提示 token 之前。最后提示 token 与生成全程不加针、不挂钩子。
- **针**：
  - L0/N4146/−1：R1 分歧所在；
  - L1/N2765/−1：**按已见差异选的对照**（阶段二事实上只恢复 KV 就修好），两层通道不同，只能说"这两个针条件响应不同"。
- **剂量**：各沿用原家族校准。事实：本题 f0 版提示上的 `engine.calibrate`（阶段二规则）。编号：NQ-01 对应题的 `QCR.nq_calibration`（NCC 规则）。每条记录写入实际每位置写入范数与位置数。跨任务比较时，校准文本不同保留为限制。

##### 2. 输入

- 事实：阶段二开发面板 24 条＋历史复核面板 24 条（12＋12 个情景各两版），b、n 取 [`prep/tokens.json`](https://github.com/yuxiexiong/acupuncture/blob/7d6bdf84ab74062ac9ab55bc8201b5a6586b92c8/experiments/window-recovery-win01-v1-2026-11-04/prep/tokens.json)（48/48 与阶段二 width 一致）。
- 编号：LVK 新面板 48 条（6 个情景），b、n 取 LVK 账本。
- b = 记录句（含换行）的最后一个 token（C1-P 规则，两任务相同）。

##### 3. 形成窗口

| 窗口 | 加针位置 | 事实实现 | 编号实现 |
|---|---|---|---|
| W_all | 0..n−2 | 单次前缀前向，`masked_injection` 全 True 掩码 | 0..b 单次前向用全 True 掩码加针，再在 b+1..n−2 逐 token 加针（NCC 的 `form`） |
| W_pre | 0..b（模板＋记录句） | 单次前缀前向，掩码只在 0..b 为 True | 0..b 单次前向加针，b+1..n−2 逐 token 不加针 |
| W_post | b+1..n−2 | 单次前缀前向，掩码只在 b+1..n−2 为 True | NCC 原方式：0..b 无针，b+1..n−2 逐 token 加针 |

- 每个任务内三种窗口用同一条代码路径，只差加针位置。两任务的形成实现不同（单次前向 vs 分段），只在数值噪声级别上不同，这一点记为限制。
- 窗口位置数逐题写入记录。事实上 W_pre 与 W_post 的位置数逐题相差 −14 到 +13；报告分面板给出，并作为限制写明。

##### 4. 臂（以该窗口的 T 为背景，在 τ 一次性替换，donor = 同输入的 C）

4. **替换**：目标张量（或位置切片）等于供体，其余张量与簿记逐位等于接收者，供体与接收者前后不变。S_deep 的目标集合等于 NCC `targets('S')`。

- 记录句位置的 KV 是唯一或天然的损伤载体（只有同窗口内的恢复充分性证据）；
- 窗口效应来自"干预了哪段内容"而不是"干预了多少位置"（位置数逐题不同）；
- 深度规律（L0、L1 通道不同）；
- 推广到其他针、任务、模型；
- 事实 W_post 下 S_deep 16/48 对编号 48/48 是任务差异（形成实现、校准、生成长度都不同）。

你是一名盲读判读员。任务：按事先写死的规则，给中文问答模型的回答打标签。你不知道、也不要猜测这些回答来自什么实验条件。

输入：一个或多个 JSON 包文件（路径见下）。每个包含：
- `instructions`：判读说明与统一规则（必须照做）；
- `items`：每题有 `prompt`（题面）、`expected_answer`（题面事实对应的答案）、`other_fact_answer`（另一事实版本的答案）、`truth_explanation`，以及 `responses`（每条有匿名 `id` 和 `text`）。

对每一条 response 输出一行 JSON（JSONL），字段：
`{"id": "...", "fact": "follows_fact|other_fact|other_wrong|not_delivered|unclear", "contradiction": true|false, "repetition": true|false, "note": "≤30字具体描述"}`

要点（以 instructions 里的统一规则为准）：
- 核心答案 = 回答中**最后一个明确结论**。
- 最后结论与 expected_answer 一致 → follows_fact；与 other_fact_answer 一致 → other_fact；其他具体答案 → other_wrong；最后结论是"无法确定/题目矛盾/不能回答" → other_wrong。
- 在给出任何最终结论前中断、且出现了相互冲突的候选 → unclear。
- 没有任何可判定答案（空、乱码、跑题、只复述题目、中断前未出现答案）→ not_delivered。
- 回答在结论之后复述题面里其他物品/人物的信息，不改变结论（例如"钥匙在红抽屉，而票据在蓝抽屉"仍是 follows_fact）。
- 只看题面与回答本身；`<think>` 空块忽略。
- 每个 id 恰好一行，不要遗漏、不要重复、不要输出其他内容。

做法：用 Read 读包文件（大文件分段读）；逐条判读；用 Write 把全部 JSONL 写到指定输出路径（每个包一个输出文件）。写完后自查：输出行数等于该包 responses 总数，id 集合一致。最后只回复每个包的条数与标签分布，不要复述回答内容。
