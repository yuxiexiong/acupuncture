##### 1. 要回答什么

本卡要交付一张证据表：**WIN-01 得到的关系，哪些跨针保持、哪些出现分叉、哪些尚无法检验。** 随后再选择能解释共同现象或稳定分叉的写入—读取问题，进入 R3。

WIN-01 留下的待检验关系（只在两个针条件、两个任务上看到过）：

- **关系 W（窗口与错误形态），拆成三项，不预设统一分工：**
  - W-a：干预只覆盖模板＋记录句（W_pre）时，是否出现首步停止；
  - W-b：各窗口下 T 是否答错；
  - W-c：各窗口下，恢复递推与恢复 KV 哪一种救回答案。

  WIN-01 中，L0 的 W_pre 两任务都不停但答错、主要由 KV 修复；L1 编号在 W_post 下完全无损伤。这些是逐格观察，不是已成立的机制。

**阶段取舍**：本卡不做 S_deep（WIN-01 剩下的事实 16 对编号 48 残差），也不做 B 块（跨版本移植）。答案选择、写入与读取问题仍在后续路线（R3）上，只是等本卡的证据表出来后再定对象，不从计划中删除。

##### 4. 读数与判据（数据前写死）

**通用**
- 单位为输入，场景等权。场景分层 bootstrap 2000 次，种子 20261103，所有比较共用同一组重抽索引。
- 方向性标签（每条比较事先写明预期方向）：
  - **成立**：Δ 与预期同向，区间不含 0，且 |Δ| ≥ 0.20；
  - **反方向**：Δ 与预期反向，区间不含 0，且 |Δ| ≥ 0.20；
  - **无可检出差别**：区间完全落在 [−0.10, 0.10]；
  - **不可判**：其余情况。
- **无损伤（不适用）**：相应窗口的 T 答错少于 12/48。

**跨窗口比较**
- 主判据用全体 48 个输入的配对差 Δ ＝ E(w1, A) − E(w2, A)，其中 E ＝ Y(A) − Y(T)（WIN-01 §8.2–8.3 的量）。
- 救回比例不同窗口间答错的是不同输入，只作辅助描述，不用于判定。

**同窗口比较**：在同一批 T 答错的输入上配对。

**关系 M（W_all 下，R_all＋KV_pre 对 R_all）分两面：**
- **正向**：在 T 答错且 R_all 也答错的输入上，R_all＋KV_pre 救回的比例。判"成立 / 无差别 / 不可判"（预期为正）。需要至少 10 个这样的输入，否则记**天花板**，不做正向判定。
- **反向（改坏）**：在 R_all 已答对的输入上，R_all＋KV_pre 改坏的比例。若区间下界 ≥ 0.10，记为**改坏反例**。所有格都检验，包括天花板格。
- 另报全体输入的配对差（与 WIN-01 M5 同一量），作为描述。

**判读**：事实用盲读（WIN-01 流程，D7、D8）。一读说明写入 V4 的截断规则：答案写出前截断＝not_delivered；修正已给结论时截断＝unclear。编号用 `y_full`。

你是一名盲读判读员。任务：按事先写死的规则，给中文问答模型的回答打标签。你不知道、也不要猜测这些回答来自什么实验条件。

输入：一个或多个 JSON 包文件（路径见下）。每个包含：
- `instructions`：判读说明与统一规则（必须照做）；
- `items`：每题有 `prompt`（题面）、`expected_answer`（题面事实对应的答案）、`other_fact_answer`（另一事实版本的答案）、`truth_explanation`，以及 `responses`（每条有匿名 `id` 和 `text`）。

对每一条 response 输出一行 JSON（JSONL），字段：
`{"id": "...", "fact": "follows_fact|other_fact|other_wrong|not_delivered|unclear", "contradiction": true|false, "repetition": true|false, "note": "≤30字具体描述"}`

要点（以 instructions 里的统一规则为准）：
- 核心答案 = 回答中**最后一个明确结论**。
- 最后结论与 expected_answer 一致 → follows_fact；与 other_fact_answer 一致 → other_fact；其他具体答案 → other_wrong；最后结论是"无法确定/题目矛盾/不能回答" → other_wrong。
- 在给出任何最终结论前中断、且出现了相互冲突的候选 → unclear。
- 没有任何可判定答案（空、乱码、跑题、只复述题目、中断前未出现答案）→ not_delivered。
- 截断规则（必须统一执行）：
  - 答案写出前就截断（只有推导、算式、箭头链，例如停在"x = 14 + 3"或"因此，袋丙最终"）→ not_delivered；
  - 先给出结论，随后在修正或否定它的过程中截断 → unclear；
  - 答案已明确写出（例如"……= 17 元"），之后才截断 → 按该答案判。
- 回答在结论之后复述题面里其他物品/人物的信息，不改变结论（例如"钥匙在红抽屉，而票据在蓝抽屉"仍是 follows_fact）。
- 只看题面与回答本身；`<think>` 空块忽略。
- 每个 id 恰好一行，不要遗漏、不要重复、不要输出其他内容。

做法：用 Read 读包文件（大文件分段读）；逐条判读；用 Write 把全部 JSONL 写到指定输出路径（每个包一个输出文件）。写完后自查：输出行数等于该包 responses 总数，id 集合一致。最后只回复每个包的条数与标签分布，不要复述回答内容。
