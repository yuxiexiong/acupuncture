R3 第一步设计稿 v2：在固定恢复背景中，改变补入前段 KV 的供体事实，能否定向改变答案（KVC-01）

2026-11-05。设计稿 v2（v1 见提交 f43cd22，按 11-05 评审修订；用户已授权按 v2 执行到实验结束）。

v2 相对 v1 的改动 1. 问题不再写成"恢复作答条件，还是提供答案内容"：两种作用可以同时存在。两个 M 臂都恢复了递推、都补入了干净的模板部分 KV，两臂之间只差记录句里事实词及其后位置的 KV。 2. 结果标签改为描述性名称；不写"内容来自别处""路径不同""失配/不兼容"等机制结论。 3. B_pre 不转移只读作"前段单独替换不足、全部 KV 替换有效"，不自动追加后段实验。 4. 针之间、受针背景与干净背景之间的差异，用同一批接收者的配对差直接判定，不凭"一组过阈值、另一组没过"宣布分叉。 5. 写明本卡是连接"状态恢复"与"答案选择"的一步桥接，不检验原有 v/k—写入—递推—读取链是否在新条件下复现。

依据： - WIN-01 报告（含更正） - WIN-02 报告（含更正） - WIN-02 评估（7f9ba4c） - Proposal v3

档位：推导＝有论证链；类比＝相邻证据；推测＝待验证。

1. 要回答什么

WIN-02 的关系 M：全前缀受针以后，先从同一输入的 C 恢复全部递推，再补入模板＋记录句位置（0..b）的干净 KV，完整回答进一步恢复：

条件 只恢复递推 再补前段 KV
事实 L3/C7666 35/48 48/48
事实 L0/N4146 10/48 47/48
事实 R0（L0 随机） 20/48 46/48

本卡问：在固定的接收背景中，改变补入前段 KV 的供体事实身份，能否定向改变完整答案？这种响应在三根针及干净背景之间是否不同？

它检验的是"这项恢复操作是否具有答案方向上的选择性"，是连接状态恢复与答案选择的一步桥接。它不直接检验原有的 v/k—写入—递推—读取链；要把这里的作用接到具体的写入、状态处理或读取计算上，是后续步骤。

WIN-01 B 块显示：在干净接收背景里，换入另一事实版本的全部位置 KV，回答 44/44 跟随供体事实。但 B 块的背景和替换范围都与 M 不同，两个阳性结果不能直接拼成一条机制。本卡把两者对齐到同一背景、同一位置范围，判断它们是否依赖同一读取。

本卡不定位层或注意力读取。那是下一步，按本卡结果另立设计。

2. 操作

任务与输入：只用事实任务（编号任务没有可按位置对齐的事实版本对）。阶段二两面板中位置对齐的 22 对（44 个接收者），对齐由 WIN-01 prep 确定：两版只在事实词处有 1–2 个 token 不同，n、b 相同。

针（全部全前缀 W_all，剂量与校准同 WIN-01/02）： - L3/C7666/−1：代表条件（原生针；M 正向 13/13、无改坏；严重损伤不依赖首步停止）； - L0/N4146/−1：L0 型原生针，全前缀下首步停止； - R0_L00/−1：与 N4146 共享恢复关系、但错误形态不同的随机方向。

格（v 为接收版本，o 为另一版本）：

格 背景 递推来源 位置 0..b 的 KV 来源 其余 KV、卷积 作用
M_same T(v)（W_all） C(v) C(v) T(v) 即 WIN-01/02 的 R_all＋KV_pre；阳性对照，逐位桥接旧记录
M_other T(v)（W_all） C(v) C(o) T(v) 主格：只把前段 KV 换成另一版本的干净 KV
B_pre C(v)（干净） C(v) C(o) C(v) 干净背景下只换前段 KV（对应 WIN-01 B 块，但位置限定为 0..b）
  • 只恢复递推（R_all）的格已有记录（WIN-01/02），作基线引用，不重跑。
  • 推导：两版模板部分 token 相同，C 无针，所以位置 0..b 中模板部分的 KV 在两版间逐位相同。M_other、B_pre 实际只换了记录句里从事实词开始到 b 的位置的 KV。这一点作为工程闸门逐位核实。

规模：3 针 × 44 × 2 格（M_same、M_other）＋ 44（B_pre），共 308 条生成（≤ 128 token）＋候选打分。按 WIN-01/02 实测约 0.3–0.5 GPUh。

3. 读数与判据（冻结前写死，经 6.2 合成演示）

读数：每个接收者的回答盲读后归入三类： - 接收者事实（R）：v 的事实； - 供体事实（D）：o 的事实； - 其他：答错、未交付、无法判断。

判读规则与截断规则同 WIN-02。

零点：D0 ＝ M_same 中回答为 o 事实的比例。M_same 的 KV 来自本版，理论上应接近 0。

判定（场景分层 bootstrap 2000 次，种子 20261103，单位为接收者，22 个情景等权）：

标签（描述性） 条件 只能说
定向转移 M_other 的 D 比例区间下界 ≥ D0 ＋ 0.20 在该背景中，补入前段 KV 的供体事实身份定向影响完整答案
恢复保留但未跟随 M_other 的 D 比例上界 ≤ D0 ＋ 0.10，且 R 比例相对 M_same 的配对差区间下界 ≥ −0.10 在当前背景下没有观察到回答跟随供体事实，接收者事实仍能恢复；恢复与供体事实跟随可以分离
恢复减弱且未跟随 M_other 的 D 比例上界 ≤ D0 ＋ 0.10，且 R 比例配对差区间上界 ≤ −0.20 跨版本替换后恢复减弱，且未发生定向转移（"不兼容""支持信号被破坏""其他历史占优"等只是候选解释）
不可判 其余 —

B_pre 用转移判据（转移 / 未转移 / 不可判），零点是 C(v) 本身的 D 比例。

条件之间的差异（直接比较，不比阈值）：三根针用的是同一批 44 个接收者。对每一对条件（L3 对 N4146、L3 对 R0、N4146 对 R0，以及每根针的 M_other 对 B_pre），逐个接收者计算"是否跟随供体事实"的配对差： - 区间不含 0 且 |差| ≥ 0.20：记"响应不同"； - 区间在 ±0.10 内：记"未检出差异"； - 其余：记"不可判"。

4. 预测（数据前登记，推测）
  • M_other 在三针上都判"定向转移"。依据：WIN-01 B 块全部位置 KV 44/44 转移；两版在 0..b 内只在记录句的事实词及其后位置不同。
  • B_pre 判"转移"。依据同上，但 WIN-01 B 块换的是全部位置，只换前段能否转移没有测过。
  • 预测失败照实记为科学失败。
5. 结果导向（数据前写死）
观察 能说 不能说 下一步
M_other 定向转移 前段 KV 在该背景中具有与事实相关的答案影响 答案只由这部分 KV 携带；补回的 KV 只提供内容、不恢复作答条件 研究这部分 KV 怎样被读取：层组与读取侧，另立设计，与原有写入—读取链比较
M_other 恢复保留但未跟随 恢复与供体事实跟随可以分离 内容来自别处；M 与 B 块不是同一路径 先讨论，不自动追加实验
M_other 恢复减弱且未跟随 跨版本替换后恢复减弱，且未发生定向转移 失配、不兼容（只是候选解释） 先讨论
条件间配对差判"响应不同" 这些条件对同一操作的响应不同 机制分叉（还需要计算层面的证据） 围绕这个差异另立设计
B_pre 未转移 前段单独替换不足以在干净背景改变答案，而全部 KV 替换有效（WIN-01） 答案载体在后段 KV 不自动追加后段替换；先讨论
B_pre 转移 在干净背景里，前段 KV 的供体事实身份也能定向改变答案 M 与 B 块依赖同一读取（只是相容） 与第一行一起进入读取研究

措辞限制： - 每针 44 个接收者、22 个情景，结论只限这三根针和这批题。 - 不说明自然受针运行中信息怎样丢失。

6. 工程闸门（任一失败即停）

  2. 结构： - 两版 C 在位置 0..b 的模板部分 KV 逐位相同（§2 的推导）； - M_other 与 M_same 只在记录句从事实词起到 b 的 KV 上不同； - 其余张量逐位等于背景。
  3. 对齐：只用 prep 判为位置对齐的 22 对，接收者与供体的 n、b 相同。
  4. 供体、接收者在替换前后不变；自换不变（预检）。

KVC-01 合同 r01：在固定恢复背景中改变补入前段 KV 的供体事实

2026-11-05。依据：设计稿 v2及 11-05 评审。用户授权（2026-11-05）："同意，改成 v2 后直接推进到实验结束再汇报"。探索性，面板已接触过，作者执行，未经独立评审。

0. 要回答什么

在固定的接收背景中，改变补入前段 KV 的供体事实身份，能否定向改变完整答案？这种响应在三根针及干净背景之间是否不同？

本卡是连接"状态恢复"与"答案选择"的一步桥接，不检验原有的 v/k—写入—递推—读取链是否在新条件下复现。

1. 固定条件

模型、引擎、模板、停止集合、贪心解码、切点 τ、事实任务的形成实现（单次前缀前向加掩码）、生成（≤ 128 token）与候选打分，全部同 WIN-01/02。

2. 输入与针
  • 输入：阶段二两面板中位置对齐的 22 对事实题（WIN-01 prep：两版只在事实词处 1–2 个 token 不同，n、b 相同），两版各作一次接收者，共 44 个接收者、22 个情景。
  • 针（全部全前缀 W_all，剂量与校准同 WIN-01/02）：L3/C7666/−1（代表）、L0/N4146/−1、R0_L00/−1。
3. 格（v 为接收版本，o 为另一版本）
格 背景 递推 位置 0..b 的 KV 其余 KV、卷积
M_same T(v) C(v) C(v) T(v)
M_other T(v) C(v) C(o) T(v)
B_pre C(v) C(v) C(o) C(v)
C C(v) — — —

C 与 M_same 逐位桥接旧记录（阶段二 CCC；WIN-01 N4146、WIN-02 L3/R0 的 R_all＋KV_pre）。每对 16 条生成，共 352 条。

4. 读数
  • 事实盲读，流程同 WIN-02；读者说明沿用 WIN-02（含截断规则）。
  • C 与 M_same 的回答与旧记录逐位相同，沿用旧标签（按来源：C 与 N4146 取 WIN-01，L3/R0 取 WIN-02）。
  • 其余回答新读；同题同文本共用一个标签，但 WIN-01 与 WIN-02 标签冲突的文本一律新读（DECISIONS D3）。
  • 每个回答归三类：
  • R（接收者事实，follows_fact）；
  • D（供体事实，other_fact）；
  • O（其他）。
5. 判据（数据前写死，经 6.2 合成演示）

场景分层 bootstrap 2000 次，种子 20261103，单位为接收者，22 个情景等权。

M_other（每针），零点 D0 ＝ M_same 中 D 的比例： - 定向转移：D 比例区间下界 ≥ D0 ＋ 0.20； - 恢复保留但未跟随：D 比例上界 ≤ D0 ＋ 0.10，且 R 比例相对 M_same 的配对差区间下界 ≥ −0.10； - 恢复减弱且未跟随：D 比例上界 ≤ D0 ＋ 0.10，且 R 配对差区间上界 ≤ −0.20； - 不可判：其余。

B_pre，零点为同一批接收者 C 的 D 比例： - 转移：下界 ≥ 零点 ＋ 0.20； - 未转移：上界 ≤ 零点 ＋ 0.10； - 其余为不可判。

条件间差异（同一批接收者"是否跟随供体"的配对差；比较 L3 对 N4146、L3 对 R0、N4146 对 R0，以及每针 M_other 对 B_pre）： - 响应不同：区间不含 0 且 |差| ≥ 0.20； - 未检出差异：区间在 ±0.10 内； - 其余为不可判。

不凭"一组过阈值、另一组没过"宣布差异。

6. 预测（数据前登记，推测）

M_other 三针都判"定向转移"；B_pre 判"转移"。失败照实记为科学失败。

7. 读法限定（设计稿 v2 §5）
  • 定向转移：只说前段 KV 在该背景中具有与事实相关的答案影响；不说答案只由它携带，也不说它不恢复作答条件。
  • 恢复保留但未跟随：只说恢复与供体事实跟随可以分离；不说内容来自别处、路径不同。
  • 恢复减弱且未跟随：只说跨版本替换后恢复减弱且未转移；"不兼容"等只是候选解释。
  • B_pre 未转移：只说前段单独替换不足、全部 KV 替换有效；不说载体在后段，不自动追加实验。
  • 条件间响应不同：只说响应不同，不说机制分叉。
  • 结论只限这三根针、这 44 个接收者。
8. 工程闸门（任一失败即停，报告用户）
  1. 桥接：C 等于阶段二 CCC；M_same 等于 WIN-01/02 的 R_all＋KV_pre 记录。比对内容为生成 token、t1 logits sha、候选对数似然。
  2. 结构： - 两版 C 在位置 0..（第一个不同 token − 1）的 KV 逐位相同，且记录句部分存在差异； - M_other 与 M_same 只在 KV 的位置 [第一个不同 token, b] 上不同； - 第 0..L 层缓存等于 C。
  3. 替换：目标等于供体，其余逐位等于接收者；接收者、供体前后不变；预检自换不变。
  4. 写入审计：误差 ≤ 1%，掩码位置数为 n−1。
9. 预算与停止
  • 预检：RD01 一对，单卡，上限 0.3 GPUh。
  • 正式：双卡，上限 2 GPUh，存储 4 GiB。
  • 工程闸门失败＝合同执行失败，停止并报告；预检允许一次有记录的修复，正式不修不重试。
  • 结果弱或不可判时，不加针、不改剂量、不换题。

你是一名盲读判读员。任务：按事先写死的规则，给中文问答模型的回答打标签。你不知道、也不要猜测这些回答来自什么实验条件。

输入：一个或多个 JSON 包文件（路径见下）。每个包含： - instructions：判读说明与统一规则（必须照做）； - items：每题有 prompt（题面）、expected_answer（题面事实对应的答案）、other_fact_answer（另一事实版本的答案）、truth_explanation，以及 responses（每条有匿名 id 和 text）。

对每一条 response 输出一行 JSON（JSONL），字段： {"id": "...", "fact": "follows_fact|other_fact|other_wrong|not_delivered|unclear", "contradiction": true|false, "repetition": true|false, "note": "≤30字具体描述"}

要点（以 instructions 里的统一规则为准）： - 核心答案 = 回答中最后一个明确结论。 - 最后结论与 expected_answer 一致 → follows_fact；与 other_fact_answer 一致 → other_fact；其他具体答案 → other_wrong；最后结论是"无法确定/题目矛盾/不能回答" → other_wrong。 - 在给出任何最终结论前中断、且出现了相互冲突的候选 → unclear。 - 没有任何可判定答案（空、乱码、跑题、只复述题目、中断前未出现答案）→ not_delivered。 - 截断规则（必须统一执行）： - 答案写出前就截断（只有推导、算式、箭头链，例如停在"x = 14 + 3"或"因此，袋丙最终"）→ not_delivered； - 先给出结论，随后在修正或否定它的过程中截断 → unclear； - 答案已明确写出（例如"……= 17 元"），之后才截断 → 按该答案判。 - 回答在结论之后复述题面里其他物品/人物的信息，不改变结论（例如"钥匙在红抽屉，而票据在蓝抽屉"仍是 follows_fact）。 - 只看题面与回答本身；<think> 空块忽略。 - 每个 id 恰好一行，不要遗漏、不要重复、不要输出其他内容。

做法：用 Read 读包文件（大文件分段读）；逐条判读；用 Write 把全部 JSONL 写到指定输出路径（每个包一个输出文件）。写完后自查：输出行数等于该包 responses 总数，id 集合一致。最后只回复每个包的条数与标签分布，不要复述回答内容。
