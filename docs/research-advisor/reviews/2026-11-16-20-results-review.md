# A020：旧记录结果与下一项辨别关系审查

2026-11-16；同一独立上下文 Advisor。读取 `continuous-result.json`、`tensor-result-r02.json` 的既有逐层/场景摘要、CPU norm 审计、对应脚本及报告，承接 A020 初审。未新增模型/GPU、统计检验、层头筛选或实验矩阵。下文排序是研究辨别价值判断，不是机制概率排名。

**结论：已有数据带来实质推进；不能收束为单一“门更开”解释。** 指定分子用途的连续背景差已经对齐；真实门前净读数在多层就有差异，门后局部转换又有额外差异，其中既有门算子本身的变化，也有向量与门的适配。简单统一基底尺度放大被降级，净读取与门转换仍需与任务因果作用分开。

若下一步只选择一个关系继续具体论证，**优先保留“门场对指定 J 分子用途的条件作用”作为窄因果候选**，净读取系数交换保留为上游竞争。不是因为 L26 是热点、门比值最大或实现方便；理由是双固定向量参照已把“算子不同”从“输入向量不同”中分离出具体证据，而它是否承担刚测到的分子用途 D−Y 背景差仍未知。这里认可继续论证这个候选，不是完成模型方案，更不是运行授权。当前结果本身足以形成一次认识更新，无须为了交付闭环立即追加模型。

## 1. 新证据把解释目标推进到了哪里

既有四臂的连续读数表明：C1 在 C/H 分别为 .481120/5.911133，背景差 5.430013；C0 背景差 5.455729。六个已见场景的 C1 背景差均为正。这修补了 A019 的具体缺口：现在不是只知 11−U 的总响应差较大，而是指定分子用途的连续条件作用本身也在 H 更大。

`δR=.803385` 仍需保留；`δe=δC1+δS0+δR` 等恒等式不能变成约 87% 的自然中介解释。两种端点顺序一致支持一个描述性模式，不产生新的确认区间。下一项真正需要解释的是 **11−01 的分子用途操作响应为何跨背景不同，并由 10−00 提供端点佐证**。

原生 11 内固定驱动的局部有限差不等于完整 11−01 轨迹差；联合 G14 操作会改变高层驱动。局部结果只能约束这项操作差异的计算来源，不能直接填成全网 logit 贡献。

## 2. 局部结果支持了不止一个具体因素

### 原始净读取差异确实已经存在

多数层 H 的净 raw d 范数较大；早期若干层 Jᵀq 较大，指定 J 的 E/D 较小、净值/D 较大。因而“两个背景到门前都得到近似相同的信号，只是输出门不同”的全线简单版本不合实测。

但 H 的 α 有效增益在早层反而较小，如 L13 为 .621 对 C 的 .815，L14 为 .673 对 .809。不能把净读取较大简化为“保留系数更大”。L21/L24 净 raw 方向的幅度模式又反向，保留了异质性。E 小只指对 J 的当前读出更新项，不是全状态遗忘较少。

实际 J 的跨背景差很小，与同一请求写入基本保留其数值身份相容；它不是证明所有任务效应对这点舍入误差都不敏感的行为控制。raw oracle 通过说明条件分解对象匹配，不把公式校验当机制发现。

### 门算子变化与向量适配不能合并成一句“门增益”

- L26：固定 d_C、d_H 的两种参照，H/C 门算子范数比约 4.189/3.920，六个已见场景均呈较大的同向比值。这是明确的局部算子差，不仅是 H 原向量更大。
- L22：实际 gated0 的 H/C 均值范数比约 7.166，固定向量换门只有约 1.223/1.201。其大幅度差不能都归到门场本身改变；向量与既有坐标加权的适配仍很重要。
- L24：换门对 d_C 的比约 .984，对 d_H 却约 1.441，直接说明参照依赖。不能从一个向量得出普遍“开门更多”。

SiLU(z) 是逐坐标、可带负值的算子，范数变大不等于概率门更开放，也不等于任务方向更正确。以上均是局部算子事实，尚未经过 W_o 及后续任务作用的因果连接。它们支持继续辨别，不能直接宣布门承担了 5.43 logits。

### 简单统一尺度放大可以降级

固定向量与门的 r0/r1 比较，其逐层平均比约在 .88–1.15，明显不是所有局部幅度倍增都来自一个统一尺度因子的模式。可降级“普遍更小基底分母把同样读数统一放大”这一简单故事；不可称等效、排尽归一化，或复活已退出的 J 额外分母用途强解释。不同头/向量权重仍有边界，且任务敏感度不由平均范数比决定。

## 3. 比较两个后续候选，而不因可做就同意

| 候选关系 | 当前有力依据与增量 | 最危险的过度解读 |
|---|---|---|
| 指定 J 分子用途使用哪一个背景的门场 | 两个固定 d 参照已发现真实算子差；若能改变同一分子用途任务响应，可把一个具体局部因素接到已经对齐的行为对比 | 不能因 gated 幅度大就认为门场差是主因；L22/24 已表明适配与参照依赖。阴性不排除共同门对不同 d 的选择性作用 |
| 指定 J 的净读取系数 `w=α[q−βk(kᵀq)]` 使用哪一背景 | raw d 多层已不同，q 读取与 E 作用都有具体证据；可检验上游净读取配置是否参与背景差 | w 是读取、衰减和擦除耦合后的整体；阳性不能命名为单独 q、α 或 β。直接交换整个输出向量又可能夹带内容/方向，需与系数交换区分 |

门场候选优先的意义是提出一个较窄、已有固定输入算子证据支持的未闭合关系；不是说净读取次要或门更可能是唯一答案。净读取候选也有实质依据，但此时直接把它扩成多因素交换会返回宽泛读者扫描；旧 BRC 的 D-only αq 不能替代净 w，也不自动复活。

**不建议据 L26 数值大小改成单层/单头热点实验。** 当前证据来自原 G14 联合用途；热点本身不提供任务作用或定位识别。也不建议门场候选一旦阴性就自动启动净读取候选。先把一个关系的正、反结果能改变什么讲清，再判断是否值得新预算。

## 4. 门场候选若继续，需要先解决的识别定义

作者提出“只在指定 J 分子增量上双向使用 C/H 门场，保留自身基底与分母”有辨别价值，但必须保持以下含义，否则不能算最小有效测试：

1. **只改变增量的局部作用，不整门替换。** 整个 z 换成另一背景会同时改变基底 u，阳性不能再专指 J 分子用途。所谓保留基底只在当前局部调用成立，不表示后续高层与状态不响应。
2. **来源门场须有固定身份。** 使用同一配对/层/时刻原生 11 的已记录门场，与让另一背景在改后轨迹同步重算，是不同政策，不能混写。门场还可能包含 J 与上游变化的后果；它不是独立静态权重或纯标量增益。
3. **精确有限差必须定义。** 不能把理想 `A d/r` 当成原 BF16 端点差后直接替换，声称其余计算完全保持。需要同一局部分母下的原算子端点及“使用自身门场时回到原生”的身份条件；具体 cast/重组契约属于后续设计，不在本次批准执行。
4. **结论限定为条件参与。** 双向改动若相应改变分子用途连续背景差，是门场这一局部成分的有用因果证据；仍不说明针最初怎样产生该门场、自然中介比例或唯一来源。只有一边有效、无效、反向或交付退化都必须保留，不能要求补层/补剂量救故事。

此处是在指出一个明确、最小的因果缺口，不追加完整实验矩阵。当前已有张量不能产生这些新条件的任务 logits；反过来，也不能因为 W_o/任务雅可比缺失而说当前所有局部认识无价值。

## 5. 数值与汇总必须保留的两项区别

**CPU/GPU 一 ULP 差与实际有限精度分账误差不是一回事。** 审计记录在 39,911,424 个原生 norm 值中有 3 个 CPU/GPU 差异，各为一 BF16 输出 ULP。r02 明确改称 CPU 诊断且没有修改原 GPU 运行门槛，是合理处理。该核对针对有保存 GPU 输出的 x1 原生端点，不能把未保存 GPU 对应输出的 x0 端点和整个有限差也声称已被一 ULP 界住。

另一方面，`cpu_finite_num1` 与理想 gated1 的差在若干早层并不小。例如 L13 的平均范数分别约 .02718/.02572，而向量差范数约 .00814（C）；这与上述 3 个平台差异不同。后续门用途定义必须尊重中间 cast，不能因平台审计看起来很小就忽略原模型有限精度。

**均值范数之比不等于逐对比值的均值。** 作者所列 L22/L26 gated0 比约 7.166/5.635，是 H 与 C 各自接收者等权均值范数之比；结果文件 `HC_ratio_gated0` 的等权逐对比均值约为 7.840/8.533。固定 d 的换门摘要也采用局部比值再平均。二者都可描述，但需标清，不能混乘、相除来算“门贡献倍数/份额”。
