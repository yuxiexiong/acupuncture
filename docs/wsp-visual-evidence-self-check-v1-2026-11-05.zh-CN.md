日期：2026-11-05。设计编号 WSP-VE-01。引用规范：[experiment-design-self-check v1](experiment-design-self-check.zh-CN.md)。审查对象：[研究方案](wsp-visual-evidence-plan-v1-2026-11-05.zh-CN.md)。

身份：同一设计助手的设计审查与反方复查，**非独立评审**。用户授权只包括方案、自查、文档交付，不包括实验。当前实现/数值/资源验收均未通过，因为尚未进行；不能把它们写成科学失败。

## 1. 设计卡

| 项目 | 本版决定 |
|---|---|
| 主线 | AI 根据反馈进行后训练稀疏权重修补，改善图像与先验冲突时的证据使用 |

## 3. 历史错误对照

- E01：保持用户选择的第一方向；任务入口变化由可访问资产决定，并在方案中解释。
- E02：核主模型36层MLP配置，扫描开发线索而非搬用旧L12/神经元编号。
- E03：支持数、标量数、范数分别报告；不把128列等同128参数或自动小扰动。
- E04：ridge和ΔW·activation只是工具，不作为机制发现。
- E07/E08/E14/E15：没有缓存混合或路径拼接；完整权重补丁只估总行为效果。
- E09/E10/E11：关注图像双正确和通常知识，拒绝由内部差异、答案分数或翻转率推断完整能力。
- E12：事实/反事实配对不能自动消除损伤，因此A_f、A_typ、额外保护项和正确→错误转移独立列出；随机支持不是精确零分布。
- E16/E18：所有失败有可接受结论，静态未成功不证明信息不存在或其余机制成立。
- E19：零补丁/重载等仅是工程验收，不当科学增量。
- E20：动态可控制性和静态稀疏可行性可以同时成立，位置稀疏与扰动幅度分别限制。
- E21：本轮重新核直接近邻代码可得性，不能靠旧报告宣布DARE已可运行或没有相似方法。
- E22：两图×四类回答×顺序与重复搜索均不能扩独立样本；同物体对按组，公开基准暴露明示。
- E23：设计自查、代码验收、模型运行、外部复现严格分开。
- E24：不要求完整机制；有真实留出改善和强比较就有应用研究价值。
- E25：先单模型单属性；color/第二模型属正式阶段；计数、注意力、视觉编码器不默认扩展。
- E05/E06/E13/E17/E26：本版不操作缓存共享变量、供体、状态减法或形成/读取分离，因此其特定错误不适用；相应一般风险由C05–C08总效果定义覆盖。

## 4. 与前版比较

前版为 2026-11-05 [选题核查报告](literature/wsp-vlm-two-directions-assessment-2026-11-05.zh-CN.md)，不是已执行协议。保留研究目标、成对正确性、能力保留及强近邻压力；本版补充操作与推断合同。

实质修改：CounterCount未有可核验下载入口，改用公开Visual CounterFact；公开数据727/493与论文计数不同，按实际版本设计；DARE仓库404，因此不可声明官方实现已准备；不因这些限制改成“输出偏好只要动了就成功”。

## 5. 反方审查、内部修正与复查

| 最强反例/硬伤 | 为什么影响结论 | 本版处理与剩余边界 |
|---|---|---|
| 列一个不能获取的数据集，却写成马上能跑 | 可执行性凭空建立 | 主入口改为可核验数据卡和文件；全量语义核对仍列P0，不冒充通过 |
| 使用字段名correct_answer给两种图都打同一标签 | 会把正确视觉变化评错 | P0按图片与问句类型构造答案表、检查作者代码及至少30对；不清楚即停 |
| 改成所有题都偏向反事实，也能涨CF分 | 没有修复正确证据使用 | P_img要求两图均对，通常知识单列；最终四问题联合正确；不把CF涨分当门 |
| 永远选物体X、左边物体或某个答案位置 | 成对题仍可能被格式捷径利用 | 反事实改变正确物体；V/T双顺序，输出物体名并报告顺序不一致；位置/图像编辑风格仍是数据分布限制 |
| 把源图片和物体组合拆进训练与测试 | “泛化”可能是记住组合 | 按同源场景及无序物体对合并组；只称组合留出，不假称单物体全未见 |
| PvP强效果已能完成任务，稀疏没有价值 | 新意可能只是实现变化 | 正面对比PvP、静态投影、脚本和正式LoRA；不能以去掉hook或参数少取代优势 |
| 原始PvP仅救错题，我们也只救错题再报数 | 总体损伤隐藏 | 拟合目标可选开发错误，但D/V/T全体评估；正确题零目标和保护项显式存在 |
| 老基线在Qwen3上被错误适配 | 伪造领先 | 实现验收独立列门； task-adapted命名；DARE缺代码不假装已赢 |
| AI能用双层但脚本只有单层，收益被归因于AI推理 | 算子自由度混杂 | 首轮只比较整体发现流程；单独的AI推理优越性需要自由度匹配，不能由该对照推出 |
| 动态修复不行就不试权重，错过WSP | 一个算子的失败不否定另一个 | P1动态无效仍允许预算内静态投影；阴性仅限操作族和搜索预算 |
| 要求带反事实图的一般知识题先有80%正确率 | 会把PvP已指出的过度视觉干扰直接排除 | P1改为要求无图文本常识参照≥80%；带图A_typ保持被测及保护终点，不设入场高分门 |
| 12个补丁的失败无法证明不存在稀疏解 | 过强否定 | 结论限定预算内未发现；退出本版而非宣布整个方法不可行 |
| AI生成目标变化太大，只靠破坏常识抬视觉分 | 可能学到简单偏好而非修复 | 限范数、保护目标、A_typ和正确→错误统计；真正证据仍是留出表现，不把约束本身当证明 |
| T样本不够，却用“没显著下降”证明无损 | 低功效掩盖损失 | 事前2点界、单侧区间；区间宽则保留结论不成立，不能靠事后扩样过线 |
| 同一数据的公开案例已在论文中读过 | “完全未见”不实 | 明示T只对本项目搜索留出；公开污染与合成风格限制保留 |
| 全部预期成立，但只是公开合成图的线索 | 不能外推自然视觉机制 | 仍可支持范围明确的任务修复；广泛主张需color及其他数据，机制不硬凑 |
| 挑三次中最好一次，同时隐藏搜索代价 | 运气与成本伪装成方法能力 | V预定选择、三次全报、AI/前向/失败均计费；T不参与再搜索 |
| 候选数上限都跑满，导致确认/重载没有预算 | 只有开发收益而无法判定静态留出效果 | 固定6,000请求预留给V/保护/重载，先停止新增搜索；必要比较未完成不宣布胜出 |
| 保留能力与主终点都不差，就宣称更省 | 静态稠密编辑同样无额外推理 | 正式价值路径B必须有测得的损伤改善或含搜索成本≥2倍优势，单纯支持稀疏不够 |

内部审查修正记录：最初的“CounterCount直接作主数据”“沿用论文分母”“仅CF涨分判断”“把动态阳性设为静态必要前提”“稀疏小于某百分比即有贡献”均未进入交付判据。修正后重查C01/C02/C08/C10/C11/C13/C14，仍回答同一研究问题。

## 6. 最终判定与四种状态

2026-11-05论证补充复查：方案§1.1–§1.3新增“痛点特征→WSP适配→失效边界”论证，未改变模型、任务、编辑范围、指标、预算或执行权限。C01/C02复查通过：仍研究图像与先验冲突的能力修复，明确其学术增量；C04/C08复查通过：把“可能已有信息可利用”和“少量权重足够”分开，后者为待验证假设；C09/C14复查通过：适配理由分别落到既有P1/P2/P3，失败仍允许停止。新增最强反例是“同类错误反复出现，但产生它的计算分布广泛，无法稀疏修复”；方案明确不能从错误有规律推出故障稀疏。此次仍为同一助手自查，没有模型实验。

**设计逻辑：通过。** 通过的是有明确前提、失败分支、统计限制的研究方案，不是实际数据足量或实现正确的认证。当前没有已知逻辑硬伤留待用户发现。

**工程验收：未完成。** 仍缺完整数据标签/分组、模型与软件哈希、PvP/Nullu适配、保护题固定清单、评分器、零补丁/重载及显存吞吐。P0不通过不进入模型科学比较。DARE官方实现当前不可访问的限制已经影响比较主张，不能靠免责声明忽略。

**执行授权：没有。** 用户明确只做方案和自查。预算是未来拟上限，禁止据此启动模型、GPU、下载权重或替用户联系作者。

**实验结果：没有。** 文献阳性仅是他人报告；本项目尚无该模型×该任务的基线或补丁。最早有意义的下一证据是P1/P2的开发可行性，而不是直接宣称论文贡献成立。
