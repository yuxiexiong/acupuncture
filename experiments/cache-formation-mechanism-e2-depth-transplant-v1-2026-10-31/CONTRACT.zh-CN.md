# 缓存形成机制｜CFM-E2 v1 合同 r01

## 1. 对象

| 项 | 取值 |
|---|---|
| 模型、内核、校准、针的写入算术 | 与 CFM-S1–S3 相同（Qwen3.5-4B 851bf6e8、BF16 eager、transformers 5.20.2 torch 路径；阶段一 `masked_injection`） |
| 输入 | 留出情景 VAR03、VAR04、VRD03、VRD04、VRL03、VRL04 × f0/f1（12 个） |
| 原生运行 | 00（无针）；L0·01、L12·01（只在晚段 L = 事实段末之后到 prompt[:−1] 末开针，掩码规则同 CFM-S2）；L0·11（prompt[:−1] 全部开针） |
| 浅层 / 深层 | 第 0–12 层 / 第 13–31 层。切分点由 L12 针的位置决定：L12 针作用于第 12 层 MLP，第 0–12 层的缓存不受影响 |
| 缓存组合 | 在 τ 处把指定层的全部缓存字段（KV、递推状态、卷积缓冲）换成另一原生运行的值，撤针后（末提示 token 与候选）照常计算 |

格：

- a = 00 浅层 + L0·01 深层；
- d = L0·01 浅层 + 00 深层；
- b = L0·01 浅层 + L12·01 深层；
- 闸门 1 = 全部 00；
- 闸门 2 = 全部 L12·01。

## 2. 硬闸门（任一不过即停，不重试、不改阈值）

1. **校准与参照复现**：校准、00 与 L0·11 的提示 token 哈希、τ 处全部 64 个缓存张量的清单、首步 logits 哈希 / top5 / 停止优势、候选逐 token 对数概率，与 II-B 归档（`data/reference-heldout-r01.json`）逐值相同。
2. **结构**：L12·01 第 0–12 层的全部缓存张量与 00 逐位相同；第 0 层在四个原生运行间逐位相同；四个原生运行的缓存管理状态（S2 `other_state`）相同。
3. **完备性**：闸门 1、闸门 2 的首步 logits 哈希与候选分数，必须分别逐位等于 00 与 L12·01。
4. 内核身份、钩子与权重未改动（同 S1）。
5. preflight（VAR03-f0）全部通过后才进 formal。

## 3. 读数

情景层面（两事实合并）：

- D = 两事实首步停止优势的均值；EOS = 两事实中首步停止的个数；
- S_fact 按 S2 定义，作描述，不入判读。

## 4. 适用条件

某情景若 [D(L0·01) − D(00)] < 0.5 × [D(L0·11) − D(00)]，该情景不进入判读。**所有情景都报告**，剔除的情景写明原因与原始数值；剔除后不足 3 个情景，E2 记为"不可判"。不得在冻结之外再剔除情景。

## 5. 判读（事先写死；设计 r4 §4）

保留量 S_格 = [D(格) − D(00)] / [D(L0·01) − D(00)]。≥ 0.7 为强，≤ 0.3 为弱，其间为部分。逐情景报告；EOS 作辅助。

| 结果（每个进入判读的情景） | 可以支持的认识 | 不应推出的结论 |
|---|---|---|
| a 强 | L0 深层缓存能够在干净浅层的背景中承载较强效应 | 浅层在原来的形成过程中不重要 |
| d 强 | L0 浅层缓存能够在干净深层的背景中承载较强效应 | 只有浅层针才能产生该行为 |
| a、d 都弱，而 L0·01 强 | 效应可能依赖两部分配合；当前交换没有找到能单独承载的部分 | 两部分各自无作用，或实验失败 |
| a、d 都强 | 存在不止一种能够维持效应的缓存组合 | 原生运行必然通过两条独立、冗余的路径起作用 |
| a、d 一强一部分，或都部分 | 如实报告连续值；按"部分承载"描述 | 任何单一承载结论 |

- b 格单独报告，只描述"L0 浅层 + L12 深层"组合下的效应，不作为"只改变深度"的证据。
- 汇总：逐情景列出 a、d、b 的 S 与 EOS，以及所属行。不设"多数情景成立"的总判决，只报告各行的情景数。

## 6. 事先登记的预期（推测档）

S3 中 L0 晚段"只在首组（L1–L3）撤除"最多恢复 0.43，"只在其后各层撤除"恢复约 1.0。据此推测：a 为强或部分，d 为弱或部分。这只是推测，不影响判读。

## 7. 规模与停止

- 规模：12 输入 × 9 条运行 = 108 条（preflight 另 9 条）；2 个 worker（每卡 1 个）。
- 停止：preflight 不过不进 formal；formal 任一输入的闸门不过即整轮停止，保留部分记录。

## 8. 失败类型

- 闸门失败：合同执行失败，信息量为零。
- 不可判：不满足适用条件的情景过多，作为结果边界报告。
- 判读为"部分"：没拿到明确结果，不是负面证据。
