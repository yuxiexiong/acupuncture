# NSR-01 决策日志

**D1（冻结前）实现方式。** 运行器从 NCC-01 冻结的 `ncc_run.py` 改出来：替换函数、首步读数、首 token 分类、`check_arm`、`changed` 和记录加载都直接调用 NCC-01 冻结代码（`NCCR`、`ncc_core`），新增的只有接收者对调、CSx 供体和异常分类。端点（C、两针 T）桥接到 NCC-01 正式记录，NCC-01 本身已桥接到 CGV 与 NVB。

**D2（冻结前）CSx 供体规则落实。** 同场景（base_id）内按 item_id 排序，取下一条，末条取首条；48 条构成同场景内的置换，每条输入恰好当一次供体（测试与就绪检查均核对）。

**D3（冻结前）预算口径。** 每条输入 4 次形成（C、两针 T、供体 C）。正式的形成 token 为 4 × 1278 = 5112（1278 是全部 48 条的窗口长度之和；供体也构成置换，所以总和相同）。预检两条输入的窗口都是 27，供体窗口为 27 与 26，所以预检上限为 3 × 54 + 53 = 215。
