# WSB-01：写入差值与接收背景的最小交叉比较

2026-11-11，设计 v1。Material Passport：用户授权设计与自查，明确“先不要上卡”；本轮只有协议／源码核对、CPU 计数和合成代数检查。模型调用与 GPU 小时均为 0。科学设计通过作者侧自查；模型实现、数值预检、正式冻结和运行授权均未完成。本文件不是执行合同。

## 1. 目的与能增加的认识

主线不变：解释稀疏激活干预怎样改变历史形成、写入、旧状态处理和读取，最终改变完整回答。

**本轮问题：供体历史对答案的作用，是会随它实际形成的写入差值一起迁移，还是固定同一份差值后，仍强烈依赖接收运行的背景？** 两者可以同时成立；不要求把整个针效应分成互斥、可相加的自然机制份额。

SPF 已有缓存级背景依赖；DWB 已有受针相关背景中一次指定供体写入的作用；DWC 已有同端点的后续读取确认。只补一个干净背景的供体臂，仍把“生成了不同信号”和“对信号的响应不同”混在一起。本轮固定实际加到状态上的写入差值，补上两类条件的可干预比较。阳性最多支持指定混合背景内的可转移写入效力／背景响应；不自动解释原生停答、纯读取作用或唯一自然路径。

这不是新写读公式或首次缓存编辑。近邻 [WriteSAE v4](https://arxiv.org/abs/2605.12770v4)已有写入替换，[How Linear Attention Remembers](https://arxiv.org/abs/2609.33093v1)已有写入和读取因果分析，[Who Asks, Who Answers](https://arxiv.org/abs/2611.01909v1)已有检索查询与状态移植。这里争取的是受针后同一来源选择关系的具体解释增量；本轮核查作者原始摘要并沿用先前相关章节审计，未独立复现或宣布穷尽首次性。

- 针：仅既有主要方向 `N_L00_C4146_D-1`；L0、B1 窗口 `[b+1,n−2]`、冻结校准。t1 是最后提示 token，之后无激活施针。不新增方向或剂量；选主要方向是既有主线顺序，不是本轮筛选结果。
- 面板：原 LVK/SPF/DWB 的 48 已见输入、6 场景。同场景其余输入全部作为供体，共 348 有序配对：AL=84、BD=84、KS=96、RS=84；冲突 AL/BD 共 168。完整名单和哈希见 `design-audit.json`。不把配对、轨迹或 token 当独立题目；不是新材料确认。

- 复用 DWB 的面板、token 账本、原 C/T 形成流程、校准、供体定义、解析器和旧原文。旧数字 C0/OO 均 48/48 正确；受针背景 DO 的 D_tr=.882。新实验需重建状态以记录此前没保存的写入差，重建全部计费；不把旧输出当新反事实。

## 3. 接收背景：两个都能正常作答

对接收输入 i，在 t1 前形成：

- **C：** 完整干净缓存。
- **H：** 受针缓存 T，但 G 层整个卷积缓冲 q/k/V 换回本输入的干净缓冲。其余受针缓存不改。它就是 DWB 的 OO 背景。

C/H 在 G 层起点使用同一份自身干净卷积历史；H 不是原生受针 T。当前输入、递推状态、其他层及 KV 等仍可不同。两者的无供体参照分别记 `U_C/U_H`；不以原生停嘴作为利用侧比较的地板。

不改变写入 k，不移植整份供体 S，不留存供体卷积历史，不添加 DWC 的 k 去偏移。t1 之后所有分支自由响应，无进一步钩子。任何分支首 token 停止也保留在计划分母中。

## 4. 如何生成一份可固定的写入差值

对每个相同的接收者 i／供体 d 配对，分别从 C、H 跑一次来源参考 `R_C/R_H`。沿用 DWB 的 DO 定义：在每个 G 层，以当前分支输入和供体干净 V 历史计算影子 v_d，原生 v_o 来自本分支实际缓冲。影子不写回缓冲。

在**同一次层调用、相同输入／旧 S／q／k／β／衰减**下，用原冻结 kernel 顺序计算两份局部后状态：

- `S_native`：v_o；
- `S_shadow`：只在新值写入中使用 v_d；旧状态处理及其他量相同。

来源参考实际继续使用 `S_shadow` 和与它一致的当步输出。即时记录该层差值：

`ΔW_s(l) = FP64(S_shadow) − FP64(S_native)`，s∈{C,H}。

它在实数条件下对应 `β k (v_d−v_o)^T`；实际保存的是 FP32 kernel 后状态的 FP64 差，包含有限精度差别，不强行压成秩一近似。两份 kernel 计算都是当前局部输入上的计算，**不是拿两条完整轨迹的末态 S 相减**。来源参考的上游层已经受到自己的供体写入影响，因此这是一份按来源轨迹生成、可重放的 14 层差值集合，不是脱离背景的纯语义向量。

与实数写入公式的差异必须记录并满足 FP64 oracle 归一误差 ≤1e−5；这用于工程正确性，不作机制证据。

## 5. 四格交叉怎样执行

对每个 i,d，各来源差值集合只生成一次并锁定。同一份文件用于两个接收背景，绝不按接收者重新计算、缩放、归一化或翻转。

从接收背景 r∈{C,H} 的 t1 前缓存独立深拷贝重新前向。到每个 G 层时，先按该**接收分支当下**的输入与缓存计算原生 `S_native,r`，再执行：

`S* = cast_FP32(FP64(S_native,r) + ΔW_s(l))`。

当步输出严格从同一个 S* 与当前接收分支的归一化、缩放后的 q 计算；持久递推状态也存 S*。不将“修改当步输出”和“修改留存状态”拆成两套值。更高层输入、q/k/v/β、KV、卷积新槽和后续生成均正常响应。

| 接收背景 r \ 差值来源 s | C 来源的 ΔW_C | H 来源的 ΔW_H |
|---|---|---|
| C | F_CC：同源重放 | F_CH：交叉 |
| H | F_HC：交叉 | F_HH：同源重放 |

**固定的是每一层额外加入的 ΔW，不是最终总状态、后续所有写入或 q。** 因此背景比较的名字是“接收运行对固定写入差值的响应”，不能缩写成“纯读取差异”。该响应包括已有状态、当步读取、更高层更新和未来计算，不进一步定位哪个部件。

同源对角 F_CC/F_HH 必须分别重放 R_C/R_H：所有 G 层 S、t1 完整缓存、logits、首 token、自然 token 序列及终止方式一致（只允许记录过的 ±0 位差）。其依据是层序归纳：相同初始背景、相同低层输出时，当前原生计算相同，加回保存差值应恢复来源后状态。仍必须实际数值验收；不能只靠代数口头放行。

## 6. 最小性与为什么不再添臂

科学比较是四格，每格 348 配对；另有 2×48 自身参照、2×348 来源采集／对角校验参考。后两组是重建和工程成本，不是额外科学样本。来源生成与同源重放的重复是检验“固定同一信号”必需的验收。

- 不做完整 SPF 四格、OD 逆向矩阵或 DWC 的 D/E 交叉：本轮不声称定位纯 t2 路径或删除必要性。
- 不加等范数／随机方向：本轮检验完整实际差值能否迁移，**不区分幅度、方向或内容特异性**；D_tr 检查来源相关的选择，而非只看损伤。
- 不上 9B，不增加 N1210，不挑新材料：先在已有可靠端点上识别这项条件关系；科学阴性不触发扩充。

## 7. 主要读数、比较与不确定性

每格复用冻结 SPF `d_transfer`：接收者内，AL 供体对应行的命中减去其他不预测该行供体下的命中。任何与供体无关的固定答案（含首行／自身／停止）都为零。48 接收者等权平均，与 DWB 相同；6 场景为重抽单位，**不是六场景等权改变旧量尺**。

F_rs 为该格 D_tr。全部报告下列配对差：

- 来源差：`S_C=F_CH−F_CC`、`S_H=F_HH−F_HC`；固定接收背景，改变写入差来源。
- 背景差：`B_C=F_HC−F_CC`、`B_H=F_HH−F_CH`；固定差值集合，改变接收背景。
- 交互：`I=S_H−S_C=B_H−B_C`。
- 同源差：`G=F_HH−F_CC`。恒等式 `G=S_C+B_H=B_C+S_H` 只是量表算术；不算自然机制比例，不以两条分解路径挑更漂亮的解释。

逐接收者先算差，再整场景配对重抽 20,000 次、种子 2026111101：每次有放回抽六个场景，携带其中全部接收者和四格配对，同场景重复抽到就重复计入；在该次所有接收者上等权平均。四格点估计和普通 95% 区间全报；六个上述对比另用同一重抽中“最大绝对中心化偏差”的 95% 分位构造共同宽度区间，减少从多项中挑一项宣称成功。仅六个已见场景，仍是开发性近似不确定性，不能称严格总体覆盖或已做功效充分保证。并列所有场景点估计，不筛选族。

预先定义：有关注量级的正／负差要求上述共同区间完全位于 ≥+.15／≤−.15；实践近零要求共同区间完整落在 [−.10,+.10]；其余为未定。`.15` 是净转移 15 个百分点的本轮关注尺度，`.10` 是较小变化带，两者均非显著性定义；小样本可能无法确认近零，届时如实未定，不用“没显著”代替“相同”。同源差 G 未达关注尺度时，不得声称找到了“受针增加来源作用”的机制；四格的条件作用仍可报告。

**完整交付护栏：** 每格同时报告有效编号、答自身、供体行、其他行、首停、后停、其他／多编号及截断；168 冲突配对另列自身正确。停止／其他不剔除、不延长生成预算。比较若任一格有效完整编号率低于 .90，主选择机制标签降为“交付退化混入，未定”，保留所有连续值。

即使达到 .90，也不靠阈值假定剩余退化无影响：对所有无有效答案的配对，分别允许填入任意列表行，利用 D_tr 对逐配对类别指标的线性权重求极端上下界，再沿同一场景重抽传播到对比。具体为把每个对比展开成逐格、逐配对的行指标系数；有效答案固定，无效答案在三行的该项系数中分别取最小／最大，再加总得到该对比的下／上界。每次重抽重新按其接收者权重计算界；十二项边界统计量采用同样的最大绝对中心化偏差共同区间，不独立挑选各格的有利填补。明确的正／负选择标签还要求最不利边界区间保持相同符号；近零标签要求整个边界区间也落在 [−.10,+.10]。这是保守的敏感性核查，不修改主评分，也不将填充值当实测答案。实现时用穷举小例验收权重算法，不新增模型臂。

## 8. 不同结果意味着什么

以下是条件解释，不把非互斥关系硬分成唯一赢家。所有“正／近零／负”均按§7区间和交付护栏，不凭裸点估计贴标签。

| 数据模式 | 允许的认识 | 退出／下一判断 |
|---|---|---|
| S_C/S_H 均正，B_C/B_H 均近零 | H 来源差值在两种背景中都更能驱动供体选择；效应随差值来源迁移，接收背景残余差在本尺度较小 | 保留“来源条件改变实际写入效力”的局部解释；不称是 β、方向或全机制 |
| B_C/B_H 均正，S_C/S_H 均近零 | 固定任一差值后，H 接收背景仍更容易随供体；在本尺度内，差值来源变化不是必要解释 | 保留背景响应解释；不把它定位为某个 q、S 或 KV，也不自动切层 |
| 两类差都有实质作用 | 写入差的变化和背景响应都参与指定操作效应 | 分别报告，禁止单因归因和机制百分比 |
| 只有 H/H 强，两种交叉都弱，I 有实质作用 | 关系依赖差值与背景配合；单独迁移不足，不能说单方主导 | 保留具体条件依赖，不立即扩大配对矩阵 |
| C/C 与 H/H 都强，G 近零 | 本局部来源操作并没有需解释的明显背景增强；SPF 更宽缓存四格不能直接投射到本对象 | 停止本分支的“针增加这项局部依赖”叙事；已有条件性写读结果保留 |
| 交叉反向或强烈不对称 | 简单的“受针差值一概更强”或“受针背景一概更易跟随”不成立 | 报告对应边界，不将全部异号称为支持 |
| 区间宽、近零未确认、交付差或极端填充改变符号 | 这次没有分清所承诺的关系 | 停止本卡，不自动扩样、延长、换针救结果 |
| 重放／源码／数值／哈希验收失败 | 无有效科学结果，属于工程失败 | 停止，不当成候选被否定 |

弱工作预期：B_H>0，即同一 H 来源差值放回 H 比放入 C 更能转移选择；理由是 SPF 提示背景依赖。但来源生成也随背景改变，现有证据并不保证此预测，S_C/S_H 不预押符号。预检不以这个预期的成败决定放行。

## 9. 必存数据与工程验收

只扩展新版本钩子，不改冻结 LVK/DWB。复用其形成、shadow-v 和自然生成工具；新增的仅是同输入双 kernel 差值采集与固定差值重放。当前未实现运行器。

工程验收必须同时覆盖：

1. 模型 revision、源码、依赖、原材料、校准及形成本体哈希与旧运行一致；C/H 自身参照及 R_H 的完整输出重放旧 C0/OO/DO。旧所有相关原文均复用，不按新效应挑子集。
2. 两背景起始 G 卷积槽确为同输入干净值，其余部件只按§3来源组成；供体、接收者、场景身份对齐。
3. source 双 kernel 输入相同，唯一 v 差按定义；实际 ΔW 与写入项公式 oracle≤1e−5；delta 以 FP64 保存、校验 hash；量值有限，未归一化或阈值截断。
4. 同源重放精确通过§5；零差重放在 2×48 参照上与原生 t1 完整缓存/logits一致。数值不合格就停，不能改为“相同答案就行”。
5. 交叉支路按自身原生 kernel 后状态加同一冻结 delta；FP64 求和／cast 与输出读回一致；源文件和缓存不被修改。
6. t1 每个 G 层正好一次消费 delta，t2 起无 hook；所有状态、全注意力 KV 与卷积随后自然响应；源权重、原核身份和句柄清除通过。
7. 数据量、计数和预算不超上限；首 token 停止也计一条完整计划轨迹。旧 DWB 的 trajectory 计数存在首停漏计（3729 对计划 3816），本卡不用该数作分母。

保存原始回答、每个配对两份 FP64 delta、来源同层 q/k/v_o/v_d/β/α及 state/logit hashes、跨背景的 delta 验收摘要、当前自然 t1 输出与逐步 token/停止信息。记录全层 delta 范数及两来源余弦只用于描述，不据几何相关宣布机制。无需完整保存每一步全模型状态或调用梯度。

按已归档维度（32 value heads、128×128、14层）每份 dense FP64 delta 为 56 MiB；正式 696 份约 38.063 GiB，预检及一次重试各约 3.281 GiB，总约 44.625 GiB，加记录与小向量后硬上限 **64 GiB**。大张量保存在实验服务器、按清单 hash 交付，不入 Git；不清理旧资产。实现前核对实时配置和空间，不同维度或超限不得静默压缩精度。按配对流式处理，不把全部 delta 同时放显存。

依据：旧 DWB 正式 wall=1346.877秒，计划3816自然运行，含形成与加载；机械按2184缩放约771秒，只能作为偏乐观参考。它的总 decode+形成步为18877，对应约.07135秒/步。按本卡最大 decode+形成上界换算约5185秒（1.44小时），尚未单独覆盖新增双 kernel／FP64差值和约40GiB存盘，所以不能直接承诺“13分钟”或保证小于2小时。预计1–2小时是资源规划判断，不是实测置信区间。

以后获准预检时，记录加载、前缀预填、单步形成、来源 t1、重放 t1、零差 t1、自然 decode、FP64复制和存盘的实际时间；取各类已测最大单价，按上表上限、全部续写可达32 token及产物上限外推，另乘1.25余量。总式为 `1.25×(加载+各类次数×最大单价+未包含的存盘成本)`；已包含存盘的单价不重复相加。外推正式>2.2小时、总耗时可能>3小时或产物>64GiB即停止报告，不减样本、删验证或放宽上限。这是保守计划值，不是数学耗时保证；进程硬超时仍必须独立生效。
