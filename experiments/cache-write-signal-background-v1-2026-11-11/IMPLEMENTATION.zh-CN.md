## 1. 实现了什么

| 文件 | 内容 |
|---|---|
| [wsb_core.py](wsb_core.py) | 同局部输入的双 kernel 差值采集；固定 FP64 差值重放；冻结 SPF 量尺的权重展开、最不利填充边界、配对场景重抽、共同区间及未定／退化判读；计数与预算外推 |
| [wsb_run.py](wsb_run.py) | 复用 DWB/LVK 的形成、影子卷积、自然生成与旧结果桥接；四格流式执行、原始差值存盘、缓存与 logits 重放检查、原文保存、计数、源码清单、预算和超时控制；离线完整回答分析 |
| [test_wsb.py](test_wsb.py) | 纯 CPU 张量和合成数据测试；可显式选择上游 kernel 核对，仍不加载权重 |
| [authorization.disabled.json](authorization.disabled.json) | GPU 授权关闭、允许阶段为空；本轮没有创建启用授权 |

没有修改旧 LVK、KUC、SPF、DWB 或 NGC 代码。标准库负责计划、文件、统计和控制；张量计算沿用项目 PyTorch，不添加依赖。依照 Ponytail full 复用冻结实现；Serena 本会话不可用，使用源码检索与直接调用核对。

执行顺序是：每场景仅形成一次 C/T → 构成 H → C/H 自身参照与零差 t1 检查 → 每配对采集 C/H 来源差值 → 从同一文件重放两个接收背景 → 检查同源对角与旧 C0/OO/DO → 保存所有自然回答。t2 起没有干预 hook。失败不改旧证据，不从中途效应决定续跑。

当步输出从修改后的同一状态读取，留存状态也使用它；所有 G 层使用同一来源文件的固定增量。缓存张量的形状、dtype、数值及管理标量都纳入对角检查；仅签名零差别单列记录。原始差值文件及逐层 hash、范数、两来源余弦保留，几何量仅作描述。

## 3. 卡时与失败控制

预算提案仍为单 H20、预计全包约 1–2 GPU 进程小时，总硬上限 3：预检 1440 秒、至多一次另行确认的工程重试 1440 秒、正式 7920 秒。不存在自动重试或自动从预检转正式。

- 独立父进程对本次 worker 施加硬超时；到期只终止该子进程，保留部分文件、退出码和回执。单 worker 文件锁防止本卡同时起两个 worker。计时显式同步所选 GPU，避免使用 GPU1 时误等 GPU0；CPU mock 已检查设备参数与计时包装恢复。GPU 非空闲或空间不足直接退出，不排队。
- 所有已发生的预检（含失败）通过带 hash 的回执入账；正式必须同时匹配成功预检、代码清单、上游 CPU 验收和明确的新授权，且预估不超 2.2 小时／总预算。
- 实测每类前向的最大单价：前缀 token、形成 token、来源 t1、重放 t1、自身 t1、零差 t1、后续 decode。形成、接收者、配对的残余开销分别计时，包含存盘、重读和 hash；结束后的权重／来源完整性检查和产物复核另计，避免漏账或将已计 I/O 重复相加。
- 按正式全部 32-token 上界、全部来源和重放数外推，再乘 1.25。最终仍靠独立超时兜底，不将小样本耗时外推称作数学保证。
- 原始 dense FP64 差值预计正式 38.063 GiB；两次预检加正式的差值合计 44.625 GiB。总产物硬上限 64 GiB，失败产物一起计入。大张量按 hash 清单保存在未来实验服务器，不入 Git。

这些是实现好的控制及预算提案，**当前并未授权或实际消耗新的 GPU 小时**。
