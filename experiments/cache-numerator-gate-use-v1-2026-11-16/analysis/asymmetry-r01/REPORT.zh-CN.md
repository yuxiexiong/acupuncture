# A022：为什么两方向换门不对称——已有数据的具体约束

2026-11-16。沿用固定168冲突配对、48接收者、六已见场景、G14全部层。仅旧记录CPU分析；**0模型forward、0新回答、0 GPU**。未追加NGU实验。

**主要判断：H换C门与C换H门，在局部就不是等强的正负操作。净读取幅度解释一部分模式，但在若干层即使H读取更小，对同一门差的响应仍更大；去掉幅度并固定归一化尺度后，读取向量的坐标配置仍与门差更匹配。输出投影这一已核环节未显示统一的大额C侧范数压制。** 这约束了局部解释，但不能把它折算为最终logit不对称的机制份额。

## 1. 不改变原实验的任务结论

[NGU正式报告](../../REPORT.zh-CN.md)中，H换C门使D−Y下降G_H=1.403646，同时95%区间[.864236,1.943056]；C换H门上升G_C=.237630，区间[−.301780,.777040]。H方向有支持、C未得到正向支持且排除预定+1量级；C不等于零。没有另作G_H−G_C的专门推断。本报告所说“不对称”首先指这一已见模式及新局部描述，不新增显著性主张。

H完整供体转移D_tr从.881944降至.590278，C仍为0；两方向全部有效编号。原分子用途背景差5.430013，在只H换门后仍4.026367。这里只解释此条件关系，不升级为原生针的完整机制。H是原实验定义的混合背景，不是原生受针T。

## 2. 比较的究竟是什么

门前读取分开两种：raw1−raw0是kernel原始净读数；d=x1−x0是两个已cast端点之差。二者在BF16下不能互换。以原生C11/H11构造共同门差gΔ=SiLU(z_H)−SiLU(z_C)，理想几何为M_B=γ inv_r,B gΔ d_B。实际NGU补丁则来自已保存的GPU patch−native，保留端点和最终加法舍入；高层当前驱动也已经响应更早操作，不能把M等同实际补丁。

适配比较把每层32×128拼接向量d用一个整体L2范数单位化，保留头间能量配置；在同一gΔ和共同inv_r参照下比较H/C输出范数。两个共同参照rC、rH都报告。它识别的是坐标方向/头分布对门差的局部几何适配，不是语义匹配或任务方向。

## 3. 对三个具体解释的判断

**净读取幅度：有支持，但不足以统一解释局部差。** 多层H原始净读数较大，实际补丁在全部14层的加权平均范数也都较大（H/C约1.30–4.79）；不是每个配对都如此，也不意味着门前幅度导致全部任务差。L21的raw/cast比为.886/.894，实际补丁比1.303；L24为.749/.752，却产生1.746倍补丁；L29为1.006/1.008，却产生1.956倍补丁。这些是“各层只因为H读得更多”的直接反例。

**向量—门差适配：得到区别于总读取幅度的具体支持。** 去掉cast d总范数并采用共同尺度后，L22的H/C为2.365/2.329，L24为2.398/2.092，L28为2.557/2.456。三层六场景在两个参照下的描述均值均>1，最小分别1.890、1.591、1.762。这是既有面板的描述一致性，不是独立确认或显著性。固定单位方向仅换尺度的14层均值范围.877–1.105，不能把上述约2倍适配统称统一分母增益。局部幅度相等仍可方向不同。

L26提供必要的反例：以前整门H/C比约4，不代表它是本次门差不对称的特殊原因。新共同门差的单位方向适配约1.05/1.05，输出方向cos约.99；它的实际补丁比1.973与raw1.873/cast1.868幅度模式更接近。不是把热点从L26换成L24，而是纠正“整门增益＝本次交换差”的对象混淆。

**后续计算：只排查了一个明确环节，不能宣布整体无作用。** 同一个W_o映射前后，实际补丁H/C比的变化因子为.861–1.087；L28的2.549变为2.195，L24的1.746变为1.898，未形成各层统一的大额C侧范数衰减。W_o权重两边相同，差别来自输入对这个矩阵的适配。这里按全头拼接投影，包含头间抵消；FP64静态几何不是原BF16 GEMM重放。任务方向可以在范数差很小时大变，后续MLP、全注意力、最终读出仍未识别。

## 4. 顺序操作和有限精度限制了哪些说法

- 首操作层L13的实际当前x0/x1/z/inv/native与旧原生11逐位一致。因此其实际局部不等（H/C=1.344）在更早NGU操作的传播之前已经存在，不能全部推给后续累积。这仍不量化其最终任务贡献。
- 高层X与原生11的x0漂移加权均值约.3%–2.4%；小cast d的相对漂移可达.704，不能全叫作净读取w改变。实际X缺raw0/raw1，且两方向当前门也都漂移；实际与固定场差异不能只归于d。
- L13实际补丁与已存意图端点差的舍入相对误差C/H约.189/.141；理想M与CPU有限端点差的相对误差约.434/.364。早层的理想实数分解不能冒充实际精确机制。有GPU原件可比的native x1端点重建最大绝对误差4.768e−7，不把这个界推广到未保存的x0跨门端点。
- 当前native_X−native_11和直接patch_X−native_X在FP64中精确相加为总差。这是记录拆分，不是自然路径归因。多数层两项平均cos接近0；范数比||u+p||/(||u||+||p||)约.7也可能只是正交，不能叫强抵消。较明显负向反而在H：L24投影后cos约−.304（C−.062），L30约−.248（C−.050）。没有支持“C被后续统一抵消”的局部图景；也不能用这些局部cos排除任务logit抵消。

## 5. 认识增量与缺口

应当修正的原解释是“门H强、门C弱，因此换门应对称搬运效果”。交换的作用取决于**同一门差乘上各自读取向量**，两个方向产生的物理改变量在早层就不等，高层又叠加不同轨迹。在部分层，关键差别存在于读取向量如何分布在门差更强的坐标上，而不只是读取总量。已有数据因此把“背景依赖”具体化成可区分的局部关系。

但仍不能说这解释了G_H/G_C的多少，不能计算“净读取占x%、适配占y%、后续占z%”。缺的不是更多局部范数，而是这些具体方向对最终D−Y的响应。原NGU九字段与RCS记录没有逐tap任务梯度、相同实际扰动的跨背景后缀测量或可离线重放后缀的全部状态。局部量与最终分数同源相关不足以填补。

最小缺测建议见[任务方向近似测量卡](MINIMAL_MEASUREMENT.zh-CN.md)：仅在原C/H端点取得任务梯度，用已存实际补丁无拟合预测已有有限效果；逐对/接收者且两背景各自通过后，才解释同方向的交叉线性响应。不是BF16离散导数或已测有限跨背景效果；近似失败则退出，不自动积分/扫剂量。[同一Advisor初审及修订复核](reviews/measurement-review.md)逻辑通过；工程未验收，本轮不实现或运行模型。
