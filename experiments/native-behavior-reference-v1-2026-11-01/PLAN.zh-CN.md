## 1. 目的与认识增量

总问题不变：少数通道激活干预如何改变写入、旧状态处理和后续读取，最终造成显著回答变化。

本批独立问题：**对于两个已经用于机制研究的锚点，在固定操作定义下，停止、事实跟随失败、未交付和其他回答变化，在更广但明确有限的输入面板上怎样分布？较低剂量及同层随机方向能否显示其边界？**

不是重复证明“针能改回答”。新增信息是对有限机制情景之外的覆盖、失败方式的分离、原版会不会与插针后还会不会的配对证据，及正常/失败边界。它为后续机制提供需要解释的对象，并不直接证明状态的形成、读取或中介路径。若两个锚点只有旧情景有效，这个边界同样值得保留。

采用目的性覆盖，不宣称对真实用户问题分布无偏抽样，不计算总体发生率或总体显著性。72组成对题不是72种独立认知机制，更不是144个独立样本；同类题结构仍相关。12题/类是覆盖安排，不是功效分析得到的样本量。

|---|---|---|---|---:|
| 原版C | 无钩子 | 0 | 无 | 1 |
| 原生锚点 | L0/N4146；L12/N3621 | −1、−0.5 | P、F | 8 |
| 同层随机方向 | L0/V0、L0/V1、L12/V0、L12/V1 | −1、−0.5 | P、F | 16 |
| 总计 | | | | **25** |

两根锚点来自既有S2/形成研究，不重新按新输出挑选。两档只检查原强度与一个较低强度，避免只观察强度饱和；不宣称描绘剂量曲线，不追加正剂量或更小档。

V0/V1逐值复用`experiments/early-input-control-v1-2026-10-29/data/directions.json`中的两个2560维单位向量，同一个方向用于两个层，来源SHA在conditions.json。它们是既有有限随机参照，不是一般随机方向分布或严格零分布；不用结果选择第三条方向。同层比较优先，不以L0和L12差异推出早层总体规律。

### 4.1 两种时段的边界

设模板化完整提示token为`x[0]…x[N−1]`。

- **P（prompt_except_last）：** 仅处理`x[0]…x[N−2]`时注入，处理最后提示token `x[N−1]`前撤钩子，预测第一个输出及后续生成均无针。原生缓存自然保留，不替换、不清洗、不重建。
- **F（full）：** 处理全部提示位置以及之后每个实际读入的生成token时注入，直到EOS或128新token上限。
- 最后提示token是聊天模板中的最后位置，不一定是用户最后一个汉字。所有条件统一采用`prefix[:-1]`块prefill＋最后提示token单步＋逐token解码，batch=1；C也走同一形状。
- **F−P同时包括最后提示位置及后续生成是否受针的差别。** 它不是纯decode阶段效应、不是等累计剂量的时段敏感性，也不是把历史状态归零的对照。若一开始EOS，两条件根本没有后续生成暴露，必须报告这一事实。
- 本批P不等于最新bridge的“事实后晚段L=b+1…N−2”，新题/整段prefill路径亦不同。不与旧bridge数字直接相减，不声称完成了同协议外部确认。

### 4.2 校准与数值身份

固定Qwen/Qwen3.5-4B revision `851bf6e806efd8d0a36b00ddf55e13ccb7b8cd0a`；BF16、eager、greedy、batch=1、4 CPU线程/worker、seed=0、repetition_penalty=1、无采样与强制最少生成长度。环境和tokenizer以历史已验收资产再核对；任何不一致在运行前报告，不静默替换。

每组事实只用f0的清洁完整提示做一次校准，两事实、两档、两时段、全部方向共用；每道开放题各一次，共96个清洁校准前向。沿用旧调查的实际`torch.quantile(norm, 0.5)`：对clean block输出排除第一个token，各位置L2范数取线性插值中位数；不是换用`torch.median`的下中位数。只需保存L0/L12的尺度及来源，过程不使用任何插针输出。不同情景尺度不同，所以跨情景结论针对“按情景参考尺度标准化”的干预，不是全批同一绝对位移。

原生针在MLP `down_proj`输入指定通道加`dose * scale / ||W_down[:,n]||₂`；随机参照在同层MLP输出加`dose * scale * Vj`。未操作的所有层、状态和当前驱动正常响应，权重不修改。剂量从未舍入值独立计算，随后转模型dtype。

范数匹配指实数公式下请求写入的范数，不保证实际BF16位移或有效损伤相等。保存请求量、BF16量、逐位置实际通道输入差标量及其列向量预测范数、随机输出加法前后位移的L2范数和写入位置数；随机向量只保存来源/哈希，不逐位置保存完整向量。列向量预测不冒充重新计算的完整BF16输出差。输入加法与输出加法的实现差异必须披露，不能据此声称只改变了方向这一唯一变量。随机参照用于有限的量级/现象参照，不承担“证明原生通道特异性”的结论。

## 5. 比较什么、如何读结果

原始回答是主资产。每条保存含特殊符号的raw文本、可读文本、全部生成token、实际输入token/哈希、模板、条件与校准身份、结束原因、耗时、hook计数、权重身份和异常。每输入C只生成一次，页面重复引用不增加样本。

自动技术读数：首步EOS、总生成长度、EOS结束/长度截断、精确token重复率。重复率固定为`1−distinct_4grams / all_4grams`，少于4 token为NA；仅是描述，不设阈值把它当“崩溃”。首步保存D=max停止logit−max非停止logit、两类赢家ID、top32及其logits；停止ID从固定模型配置读取（旧配置为248044/248046），若不同须停在身份检查。D只为连接旧端点，不以D代替真实停止或答错。逐步保存被选token的logprob，不保存所有位置全词表logits、全缓存或全层激活。

语义阅读在全量原文完整性核验后按匿名条件进行。先锁定单条观察及证据引文再揭盲；同一助手的模型辅助阅读不冒充独立评审。字段分开：任务交付、核心答案符合给定事实、核心错误、附语矛盾、无法判断、格式约束、明显离题/重复。技术失败不算不交付；EOS/截断与语义字段可并存。不自动调用新的判分模型。

| 比较 | 有用读法 | 不允许的替代 |
|---|---|---|
| 每条件对同输入C | 逐条会→不会、不会→会、两者都对/都错/不明；停止与交付另列 | 只报告原版正确子集，删掉原版本来错的题 |
| 同题干f0/f1 | 两事实均正确、只一边正确、两边错/未交付，以及核心答案是否随事实改变 | 答案文字变了就证明理解；答案相同就证明内部信息被抹去 |
| 同层、剂量、时段的原生针与V0/V1 | 有限方向参照下效应与失效方式的相似或差异 | 两方向当随机总体分布；均无效即证明等效或原生针专属 |
| 同方向−1与−0.5 | 强度改变时有无饱和/转变，以及题间差异 | 两点证明单调曲线、最佳剂量或弱扰动极限 |
| 同方向、剂量P与F | 两个预定运行策略在同题上的总行为差 | 将差别唯一归给当前针、历史缓存或生成反馈 |

按6个事实任务族和6个开放任务族分别展示，不混合为一个能力/人格总分。事实统计的基本配对单位为题干；全体144事实输入和“原版两边都正确”的题干子集分母同时报告。两个事实、25条件、两个GPU和重复阅读都不是新增独立样本。本批不报告总体p值/置信区间，不将目的性面板外推为真实用户任务频率。

## 6. 不同结果怎样改变认识

- **多类输入稳定出现同类变化：** 增加机制需要解释的覆盖范围；不自动推广为共同机制。后续须在新输入冻结预测。
- **仅少类/少题出现：** 收紧适用条件，保留正常反例；不能按失败题重新筛选一批“更灵敏”的题并混入本批。
- **−1几乎全停止，−0.5显示差异：** 强档只登记饱和边界，较低档提供可观察区间；不得为救假设继续减剂量。
- **两档都全停止或都正常：** 这批仍给出有限范围结论，但不能据此解释读取；停止扩张本批，不能自动加层、题、剂量。
- **随机方向也出现类似结果：** 限制通道特异性，保留一般扰动解释；不是机制课题失败，也不是所有方向等效。
- **P/F不同：** 登记具体策略依赖及暴露位置数；机制归因留给后续方案。P/F相同也不证明缓存或当前针不重要。
- **开放题与事实题不同：** 分别报告；不将流畅改写当作整体能力保留，也不把格式偏离称为事实损失。

## 7. 规模与算力账本

正式：`(72×2+24)×[1+2层×3方向×2剂量×2时段] = 168×25 = 4200`次生成，其中168原版、4032干预；最大537,600新token。全部≤128，正常EOS提前结束，不延长、补写或采样重试。另96校准前向，不含于4200。

计划中的技术预检使用三个专属短提示（“请计算8加5。”；“只回复测试完成。”；“记录：瓶子在左柜。瓶子在哪里？”），不进入正式168题。每卡每提示8条：C、原生零针P/F、随机零针P/F、一个非零原生、一个非零随机、移除钩子后C。两卡合计48生成、6校准，最多6144新token。非零覆盖依次为：L0/N4146/−1/P与L12/V0/−0.5/F；L12/N3621/−0.5/F与L0/V1/−1/P；L0/N4146/−0.5/F与L12/V0/−1/P。零针分别使用同题对应非零方向的层/通道，覆盖P/F边界。预检输出不用于改题、选方向或调剂量。

预算证据来自本地已有X配方双卡预检48条：4518生成token，282.00275生成秒；其中至少32token的记录，中位吞吐为16.07938 token/s/worker。**这些是旧英语短提示、旧生成器的测量，不是本批测速。**只作量级估算。

|---:|---:|---:|
| 32 | 2.32 | 1.16小时 |
| 64 | 4.64 | 2.32小时 |
