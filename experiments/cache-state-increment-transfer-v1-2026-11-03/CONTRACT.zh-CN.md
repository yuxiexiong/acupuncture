1. **只报连续值**，不贴“转移成功／失败”或任何二分标签。删除方案 §4 中按“大、小、可观”分支的读法。
2. 报告 A0、A1、逐场景符号，以及相对 G=DS1−DS0 的**描述性比例**；G<0.5 时不算比例；C1343 单列。

## 1. 问题

恢复输出背景（c=1）产生的留存状态增量，放进原生输出背景（c=0）的接收者后能否改变 k 操作的目标竞争与完整回答？反向放入时又如何？

## 2. 范围

继承 NVB 合同与冻结 r02：Qwen3.5-4B（revision `851bf6e806efd8d0a36b00ddf55e13ccb7b8cd0a`）、BF16、eager、batch 1、torch 原核；LVK 新面板 48 条（已见开发面板）、六场景；四方向 N4146 / N1210 / R0（缺口方向）与 C1343（诊断，单列）；R 族冻结 μ、形成流程、校准、停止集合、解析器、MAX_NEW=32。不增加输入、模型、针、剂量或方向。

## 3. 操作

NVB 八格 B(c,a,b)：c 是 t1 输出所用 v（0 原生 v0，1 局部 v1），a 是 t1 留存状态所用 v，b 是写入键（0 k0，1 冻结 μ 操作后的 k1；擦除键恒为 k0）。S(c,a,b) 指整个 t1 结束后 14 个 G 层 [13,14,16,17,18,20,21,22,24,25,26,28,29,30] 的递推状态。

- **八个旧格**：用冻结的 NVB `NHook` 重算 t1。t1 bf16 logits、t1 token、C 路线 t2 bf16 logits 和 M 必须与 NVB 正式记录逐位相同。旧格的 N 路线不重跑，直接复用 NVB 正式记录（逐文件 sha 核验）。
- **增量**：ΔS(s,b)=S(s,1,b)−S(s,0,b)，同一输入、同一方向、同一 b。
- **四个新格**：接收者 r、增量来源 s，(r,s)∈{(0,1),(1,0)}，b∈{0,1}。在接收格 B(r,0,b) 的 t1 末缓存深拷贝上，对全部 14 个 G 层一次性赋值 S*=S(r,0,b)+ΔS(s,b)：先用 FP64 求和，再一次 cast 回缓存原 dtype（float32），不缩放、不归一化。卷积缓存、KV、位置、t1 logits 与 token 一律来自接收者。t2 起不挂任何钩子。
- **C 路线**：输入冻结的共同首 token fF，读 t2 的 M（NVB 定义：目标第二 token 减竞争者，目标在首列时减第二列）。
- **N 路线**：输入接收者自己的 t1 token，贪心续写，到停止或共 32 token 为止；t1 已停止的不续写。
- 新格计数：48×4×4=768 条 C t2，至多 768 条 N 轨迹。

## 4. 读数与报告（冻结；实现见 `sit_core.py` / `sit_analysis.py`）

### 4.1 目标竞争 M（主读数）

逐输入计算：F(r,s,b) 为移植格的 M，其中 F(r,r,b)=M(B(r,1,b))；Z(r,b)=M(B(r,0,b))。

- H(r,s)=[F(r,s,1)−Z(r,1)]−[F(r,s,0)−Z(r,0)]。H(0,0)=DS0，H(1,1)=DS1，与 NVB 定义一致。
- **A0=H(0,1)−H(0,0)**：保留原生输出背景，把增量来源从原生换成恢复。
- **A1=H(1,1)−H(1,0)**：在恢复输出背景里，把来源从恢复换回原生，损失多少。
- G=H(1,1)−H(0,0)=DS1−DS0，只作量尺。
- 同时报告每个 b 的直接效应 F(r,s,b)−Z(r,b)、A1−A0、以及各格均值。

汇总方式：逐输入算，再六场景等权。报告场景等权均值、六个场景均值及正负个数、逐输入正负个数，以及场景分层 bootstrap 区间（输入在场景内重抽，2000 次，种子 20261103，取 2.5% 与 97.5% 分位，仅作描述）。比例 A0/G、A1/G 只在场景等权 G≥0.5 时计算，允许反号或大于 1。主子集为目标不在首列的 32 条；全 48 条和首列 16 条作补充，不重选子集。三个缺口方向逐一报告，不做多数计数；C1343 单独完整报告。

### 4.2 完整回答 Y

QST `y_full`，48 条全部进入分母。报告每格正确数、每个 b 的改对/改坏/净变化及涉及场景数、H_Y(r,s)（与 H 同样的差分，求和）、A0_Y、A1_Y，以及接收端在 b=0、1 两格 t1 都未停止的子集（分母、正确数、H_Y）。

**数据前已知事实**（来自 NVB 正式记录，`readiness/cpu-check-r01.json`）：四个方向合计，c=0 接收格在 t1 停止 166/192（b=0）和 174/192（b=1）；c=1 为 0/192。因此 r=0 一侧绝大多数输入的 Y 在构造上无法改变，可继续生成的子集按方向单列。M 改善而 Y 不变，照实报告。

### 4.3 一阶参照（看数据前登记，带条件）

**构造**：NBR 重投影 JSON（`nbr-reproject-r01.json`，sha 记入冻结）中，逐层求 g·(XI_s1−XI_s0) 后按层求和。

**计算条件**：
- XI(cs,cq)=α·I_S(cs)ᵀq，即 t2 直接读出项，不含擦除修正项。
- 读者 q、α 取自接收背景的 (r,0,0) 格。
- g 是在单一格上计算的 ∂M/∂o（t2 各 G 层输出）。
- q 不随移植响应；不含高阶项；各层求和只作同口径比较。

A0 的参照取 r=0 一侧的 g000 / g011，A1 取 r=1 一侧的 g100 / g111，两个线性化点并列：

| 方向 | A0 参照（g000 / g011） | A1 参照（g100 / g111） |
|---|---|---|
| N4146 | 0.300 / 0.363 | 0.306 / 0.613 |
| N1210 | 0.286 / 0.332 | 0.308 / 0.330 |
| R0 | 0.321 / 0.398 | 0.353 / 0.461 |
| C1343（诊断） | 0.648 / 0.498 | 0.746 / 0.204 |

**已知校准**：同样的构造给出的 DS0 是 0.04–0.22 / 0.31–0.51 / 0.50–0.76，NVB 实测是 0.247 / 0.488 / 0.622；DS1 是 0.37–1.44 / 0.67–0.90 / 0.93–1.38，实测 2.122 / 1.451 / 1.575。在缺口方向上，这一构造多数时候低于实测。所以它只是参照，不是判据，也不能拿来宣布预测与证据冲突。报告时并列“实测 / 参照”，偏差不归因给 q、KV、下游敏感度或任何部件。

### 4.4 措辞规则

- 可以说：“恢复（或原生）来源的实际增量在该接收背景中使 k 的条件效应变化 A（场景 x/6 同号，区间 …，约为 G 的 f）”。
- 禁止：“转移成功／失败”、“机制份额”、“必要”、“方向特异”、“自然中介”，以及把剩余差异归给某个未操作的部件。
- 阳性的上限：实际增量变化（未区分幅度与方向）在该接收背景中有可转移作用，仅限这些混合反事实、有限幅度、已见开发面板。
- 阴性或异号：只撤回“恢复来源增量普遍更有利”这一工作预测，不排除状态作用，也不指定原因。

## 5. 工程闸门（运行中断言，任一失败即停）

1. 来源：形成 hash 与 LVK 一致；NVB 正式记录与张量 sha 一致；旧格 t1 bf16 logits、t1 token、C t2 bf16 logits 和 M 与 NVB 逐位一致；NVB `NHook` 的 FP64 oracle 与状态差恒等误差 ≤1e−5。
2. 留存桥：固定 (c,b) 时，a 从 0 变 1 只改变 G 层 S；第 13 层状态在 c=0/1 之间逐位相同（所有 a、b）。
3. 同源对角：S(r,0,b)+ΔS(r,b) 经移植代码路径后与 S(r,1,b) 逐位相同，整份缓存与 B(r,1,b) 逐位相同。
4. 新格：与接收者 B(r,0,b) 相比只有 G 层 S 不同（其余缓存逐位相同）；第 13 层移植后等于 B(r,1,b)；FP64 求和后一次 cast，归一化误差 ≤1e−6；递推状态 dtype 为 float32。
5. 隔离：源状态、t1 缓存、t1 前背景、C/T 前后 hash 不变；C 与 N 各用独立深拷贝；t2 起无钩子；模块函数已复原，权重 sha 不变。
6. 计数不超 §6 上限；设备时间与存储不超上限。

**6.2 演示**（CPU，`test_sit.py`）：
- cast 闸门在 float32 上可满足、在 bfloat16 上不可满足；
- 读数在合成数据上能复现正、零、反号三种转移；
- 比例保护会触发；
- 分析入口用真实键结构端到端跑通；
- NVB 来源不符时会被拦下；
- 一阶参照从真实 JSON 重算，等于 §4.3 的登记值。

冻结前用真实模型跑一个预检输入，全部闸门须通过（`readiness/gpu_smoke.py`，只写闸门、计数与耗时，不写 M/Y）。

设备时间上限：正式 1.2 GPUh（按各 worker 墙钟求和），每次预检 0.15，合计 ≤1.5 GPUh；预检外推超过正式上限即停。参照 NVB 0.63、NBR 0.29 GPUh，本轮估计 0.3–0.6，未经实测。存储上限 12 GiB。只新存四个新格的 C t2 和 N t2 logits（bf16）以及逐层增量统计。

## 7. 停止与失败

- 任一闸门失败：该 worker 停止，launcher 停止其余 worker 并保留证据。归类为合同执行失败（信息量为零），不当作负面证据。
- 预检失败时，只允许一次有记录的工程修复：只修实现，不改定义、读数、输入或格子；新冻结 r02，记入 DEVIATIONS。正式开始后不改实现，不重试。
- 预检不按科学结果筛选；科学结果弱、异号或方向不一致都不加格、不换针、不调剂量。
- 完成四个新格与汇总即结束本轮。产物：原始记录与来源清单、verification、DEVIATIONS、DECISIONS、`analysis/sit-readouts-r01.json`、短报告。
