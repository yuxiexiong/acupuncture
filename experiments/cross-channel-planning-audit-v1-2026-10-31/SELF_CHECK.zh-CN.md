# 跨通道计划的旧数据核对：执行前自查

2026-10-31；仅 Python 标准库读取本地旧 JSON，不加载模型/张量，不联网执行服务器程序，不运行 GPU。用户授权核对已有多针多剂量数据并编写下一轮计划。

设计卡：主线是针如何改变写入/缓存/读取；本审计为跨通道选择提供真实覆盖，避免把十通道单剂量当十通道多剂量。对象为 4B、L0、旧十点调查和正负剂量调查正式记录、共享基线、采样/选择清单、协议与收据。核对文件哈希、唯一条件、剂量、题目覆盖、首 token EOS、空正文、128-token 截断、与基线 token 完全相同数。后四者是机械读数，不作能力或语义判断。输出 JSON 和原始回答摘录、来源 manifest。全部十通道保留，不依这些结果筛掉弱通道。只扫描既定来源，缺失/哈希失败停止汇总，不自动补跑。当前查看过少量记录结构，非盲分析；正式全表汇总尚未执行。

|检查|结论及理由|
|---|---|
|C01|通过：服务原主线代表性，非另设停止检测课题。|
|C02|通过：确定跨通道/跨剂量的真实覆盖，约束下一轮对比。|
|C03|通过：协议/正式收据/原始JSON优先于摘要和合同旧状态。|

|C08|通过：只报告覆盖/机械输出统计，不作因果归因。|

历史错误：E01保持主线；E02不把L0特殊性当事实；E03单位剂量为残差归一化并非激活加1；E04统计不是机制；E05/E06无变量拼换；E07不从旧阳性推自然路径；E08来源明确；E09不做状态因果交互；E10停止与交付分开；E11不推信息删除；E12无零分布主张；E13无恢复供体；E14覆盖/机制分开；E15旧时窗不能硬接新链；E16阴性保留；E17无撤销操作；E18余量不命名；E19哈希一致只为工程；E20行为类型不互斥；E21不主张方法新颖；E22按通道与题目配对报告；E23同助手自查、非独立复现；E24覆盖核对本身对设计有用；E25只审计L0与相关来源、不重扫模型；E26明确旧调查持续注入、新机制晚段窗口不同。

反方：首步EOS多不代表同机制；因此不按EOS强弱选机制成功者。正负小剂量只有一通道，无法校准其他通道等效行为强度；下一轮不以搜剂量制造相似。旧收据声称完成不等于当前文件完整；逐记录哈希核对。规则修正后仍有用：区分已测覆盖与待补对比。结论：离线审计设计通过，可在当前授权下执行；不授权任何模型运行。后续实验另写完整自查。
