## 估算依据与不确定性

现有 FA-01 吞吐测量为 256 样本、最多 4,096 tokens：0.8B 约 **14,045 token/s**，4B 约 **5,124 token/s**。它们不是 32k 长输出吞吐测量。

单次最大 512 条 ×32,768 token 共 16,777,216 生成 tokens。直接按上述速率外推，仅解码约 19.9 / 54.6 分钟，再加加载和激活读取；因此 4B 不能套用作者“约半小时”的 0.8B 预算。50 次全都达到最大生成规模，单计解码约 16.6 / 45.5 GPU 小时；激活重读与初始化可继续增加，建议硬上限仍可能提前触发。这是容量压力情景，不是预测编辑器会这样选。

作者公开 p50c 有 50 次成功调用（34 generate、16 teacher_forced），成功前向报告的时间合计约 9.10 小时；作者硬件和内部服务与我们不同，不能直接当作本机用时。其请求的生成 token 上限总和约 187.7M，按我们的短序列吞吐外推仅解码约 3.71 / 10.18 GPU 小时，尚不含重读和长上下文降速。两个情景共同说明：混合搜索常会低于建议硬上限，但现在给精确完成时刻不可靠。

Astra 集成的 4 个工程回合实际记录 input 63,918、cached input 39,936、output 2,214 tokens，约 65.1 秒编辑器调用时间；这只是小测试，不能外推科研长推理的配额。另两回合续接探针也已归档。当前用 ChatGPT 登录，剩余会话配额和可用金额没有可验证的数值；不虚构美元价格。正式启动前确认账号可以持续使用 Astra/max；遇到配额错误则暂停，不换模型续跑。CPU 300×900 秒的理论极端上限是每模型 75 小时，不是常规预期耗时。

## 磁盘缺口

交付前服务器 /workspace 可用空间约 210 GiB（约 226 GB）（以最后快照为准），足够当前工程验收，达不到正式配置的 400/600 GB 启动线。仅 TF 返回上限就是每模型 50×6 GB=300 GB；还要保存回答、候选及快照。当前新增的 checkpoint 私有缓存会在成功调用后清理：其源快照和哈希仍保留，已经验证 CPU 可重建相同 SHA256，不必保留每次 4B 完整副本。

建议给正式搜索准备 **约 1 TB 专用空间**，或经用户指定归档已有数据后确保至少 600 GB 空闲。400/600 GB 是实用启动门槛，不是所有合法编辑/工作文件的数学上界；若编辑器大量复制完整模型或持有大量中间文件，仍可能触发磁盘暂停。不会删除共享盘其他项目的文件。
