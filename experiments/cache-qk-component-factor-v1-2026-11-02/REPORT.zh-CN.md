# QKF-01（共同偏移的 q/k 分量与完整回答效应）结果报告

日期：2026-11-02。[合同 r01](CONTRACT.zh-CN.md)；[决策 D1–D4](DECISIONS.zh-CN.md)；计划 v1（7289925d，评审撰写）。代码 `1691c74`，freeze-r01 `8e07a0df…ddf6`。单半臂与 r_post 臂运行前无输出。同一助手实现、运行与撰写。

## 1. 结论（限制先说）

1. **加入侧的方向特异性弱。** 把与共同偏移 k 半“首读旧槽卷积贡献相同”的随机向量（r_post）加到干净 k 上，同样会逐 token 复现大量原错误：B = 0.74（N4146）、0.39（N1210）、0.45（R0）。共同偏移 k 半相对它的优势只有 0.26 / 0.55 / 0.09——N4146 刚过 0.25 门槛，R0 未过。所以“k 被扰动就会出首列错误”在相当程度上不依赖方向。
2. **去除侧的方向特异性强。** 从受针 k 减去共同偏移的 k 半就能修复（见第 3 条）；减去等强的随机向量不但不修复，还更差（P = −0.03 / −0.36 / −1.23）。
3. **预注册的“k 强于 q”在 N4146、N1210 成立，R0 未达到排序标准。**
   - 只去除 k 半：N4146 16 → 44/48（P = 0.87），N1210 28 → 48/48（1.00），R0 38 → 48/48（1.00）；只去除 q 半：16 → 16、28 → 28、38 → 40（P = 0 / 0 / 0.23）。
   - 只加入 k 半：在原错误上 B = 1.00 / 0.93 / 0.55；只加入 q 半：0.15 / 0 / 0。
   - R0 的 k 去除达标，但 k 加入的复现只出现在 2 个场景（需要 4 个），排序判据的场景条件也未满足，所以 R0 记“无排序”。
   - 对两档随机的优势：k 单半在 N4146、N1210 去除和加入两侧都过（加入侧相对 r_post 在 N4146 只有 0.26）；R0 只有去除侧过。
4. **q 半无作用要谨慎读。** 首读重建的几何显示：共同偏移的 q 半几乎不改变实际参与计算的归一化 q（每头中位余弦 0.98），k 半则把归一化 k 转开约 45°（余弦约 0.71，几乎就是受针 vs 干净的全部 k 差异 0.68–0.72）。所以“q 半没用”至少部分是因为它在归一化后的 q 上几乎没造成改变，不能推出读取路径与此无关。
5. **交互**：在完整交付上没有可见非加和（k 单半已近饱和）；在固定竞争者分差 M 上，共同偏移的 q、k 两半有正交互（I_M = 0.29–0.58，三方向都“可见”）——q 半只在 k 半也被处理时才推动分差。随机档没有这种交互。这是连续读数，不改变行为结论。
6. 不能说：读取/写入机制已分离；k 是唯一通路；共同偏移的方向本身是致错的充分特征（加入侧随机也能致错）。
7. 工程全部通过：C/T 哈希 = QCD G；8 类参照臂与 QCO 逐位重放（证明观察器只读）；预检零编辑逐位复现 V/F；r_pre、r_post 配平检查对全部输入通过（逐头最大相对差 5.03%，在 6% 容差内，与 CPU 预模拟一致）。

## 4. 对主线的含义

- 针在末端 q/k 上造成的共同偏移，其行为作用几乎全部经由 **k 半**：去掉它就修复，加上它就重现（两个方向强、R0 只有去除侧强）。
- 但 k 对扰动本身很敏感：等强随机扰动加到 k 上也常常导致同样的首列错误。所以目前更准确的图景是：**k 的方向被转开（约 45°）就会出首列错误，而针造成的转动恰好是一个可以被精确撤销的共同方向**。
- 下一个问题自然落在 k 进入门控 delta 更新的环节：k 被转开后，状态更新（S·k 的预测与修正）怎样把“首列”变成默认答案。这需要新的计划；本轮按合同结束，不拆层、不扫头。
